# 0126. Mobileメニューを開いたままスクロールすると本文が隠れる不具合を修正する

- 日付: 2026-09-11
- 状態: 採用

## Decision

プロジェクトオーナーから、本番(futoing.com)のMobile幅で「ヘッダーと
フッターがばらばら」に見える、との報告を受けた。スクリーンショットは、
ハンバーガーメニューを開いた状態でページ下部までスクロールしたもので、
メニュー直下からフッターの直前まで本文コンテンツが何も見えず、
大きな空白になっていた。

調査の結果、原因は以下の組み合わせと判明した。

1. Mobile幅の`.nav`(ドロップダウンメニュー)は`position: absolute`
   で`Header`(`position: fixed`)の直下に浮くオーバーレイであり、
   開いても本文を押し下げない(本文の上に重なるだけ)。
2. メニューはクリック外・Escapeキー・リンク遷移では閉じるが、
   **スクロールでは閉じない**実装になっていた。
3. そのため、メニューを開いたままスクロールすると、開いたメニューが
   画面上部に張り付いたまま本文だけがその下でスクロールする状態になる。

この状態自体は以前から存在していたが、Decision Log 0125でトップ
ページを4セクションに短縮した結果、Home全体の高さが縮み、上記の状態で
スクロールするとほとんどの本文セクションがメニューの下に隠れてしまい、
「メニューの下がほぼ空白、その先にいきなりフッター」という、実際より
大きく壊れて見える見た目になっていた。Desktop幅は影響を受けない
(Mobile専用のドロップダウンメニューの問題のため)。

## 対応

`src/components/Header.astro`のメニュー開閉スクリプトに、スクロール時
にメニューを閉じる処理を追加した。

```js
window.addEventListener(
  "scroll",
  () => {
    if (nav.getAttribute("data-open") === "true") closeMenu();
  },
  { passive: true },
);
```

既存の「クリック外で閉じる」「Escapeで閉じる」ロジックと同じ
`closeMenu()`を再利用しており、新しい依存やDOM構造の変更はない。

## 採用理由

根本原因は「メニューを開いたままスクロールできる」ことそのものに
あるため、表示が縮んだHomeだけを個別に手当てするのではなく、Mobile
メニュー自体の挙動を直した。スクロールで開いたドロップダウン/オフ
キャンバスメニューを閉じるのは一般的なUIパターンであり、ページの
総高さに関わらず今後も同じ問題が起きるのを防げる。

## 他の案

- Home側で本文の最小の高さを確保する(例: 各セクションのpadding
  拡大)案も検討したが、根本原因(メニューがスクロールで閉じない)を
  放置したままの対症療法であり、他ページや将来さらにHomeが短くなった
  場合に同じ問題が再発するため採用しなかった。
- メニューを`position: fixed`の全画面オーバーレイに作り替え、開いている
  間はスクロール自体を無効化する(`body`に`overflow: hidden`)案も
  検討したが、今回の不具合を直すには過剰な変更(デザイン・DOM構造の
  変更を伴う)であり、CLAUDE.mdの「今回の目的と関係ないリファクタリング
  はしない」方針にも反するため採用しなかった。

## 将来の変更可能性

Mobileメニューを将来オフキャンバス化・全画面化する場合は、この
スクロールで閉じる処理は不要になる可能性がある(スクロール自体を
無効化する設計に変わるため)。その際はこの実装ごと見直す。

## Research Context

直接的には研究内容に関わる決定ではないが、「β公開前に見つかった実装
上の不具合は、その場しのぎではなく根本原因まで遡って直す」という
