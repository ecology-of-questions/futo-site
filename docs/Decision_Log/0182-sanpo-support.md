# 0182 — 「音の道」を「散歩譜」に改称し、身体譜プレイヤーと試行錯誤への支援を追加

**2026-09-19追記(PR #109レビュー反映、まだmerge前のレイアウト調整):**
プロジェクトオーナーのPRレビューを受け、以下を修正した。
- 「← 実験室」直下の「実験」eyebrowラベルを散歩譜のみ削除し、見出し前後の余白を詰めた(`.backTight`/`.headingTight`、Fieldnote・研究断面をひらくは変更なし)。
- 身体譜のSVGに`preserveAspectRatio="none"`+明示的な高さ(chartHeight、インラインstyle)を指定し、横幅はコンテナに追従するが縦幅は画面幅に比例して拡大しないようにした。3レーン構成で高さ180pxに固定。
- レーン数を割るだけだったジオメトリ計算から上下パディング(chartTop等)を除去し、`.laneLabels`にも同じ高さを明示することで、「左・右・音」のラベル中心とSVG内のレーン中心が計算上・実測ともピクセル単位で一致するようにした。
- 再生を一度も開始していない間(`started`フラグがfalse)は進行演出(未到達ステップを薄くする処理)を適用せず、全ステップを不透明度1のまま保つように変更した。「最初に戻す」でもこの状態に戻す。再生を開始した後の未到達ステップの不透明度も0.3→0.55に上げ、読みやすさを優先した。
- `WalkingScorePlayer`の`.wrapper`に`max-width: var(--reading-width)`を追加し、支援欄が非表示(1カラムレイアウト)のときにプレイヤーが際限なく横に広がらないようにした。
- Googleスライドの常時表示・コメントリンクは変更していない。

Playwrightで、SVG内の罫線のy座標(px換算)とラベルのcenter位置(px)が完全一致すること、svgの実測高さが180pxで画面幅に応じて変化しないこと、`.wrapper`の実測幅が`--reading-width`(672px)で頭打ちになること、再生前後・最初に戻す操作後のopacityの遷移(すべて1→再生中は1/0.55混在→リセットで全て1に復帰)を確認した。

## Decision
2026-09-18、プロジェクトオーナーから「散歩譜＋支援」指示書v2(Astraで作成した`CLAUDE-CODE-INSTRUCTIONS.md`+参考UI`sanpo-ui.html`)を受け、以下を実装した。

1. 「音の道」を「散歩譜」に改称(表示名・description・OGP・Homeカード・実験室一覧のラベル)。route slug(`oto-no-michi`)・データID・Slides URL・コメントURLは変更していない。
2. 身体譜プレイヤーv0(`WalkingScorePlayer.astro`)を新設。横軸=経過秒、縦に左右ステップの2レーン+将来の公開音声用の1レーン。架空24秒デモデータ(`walkingScoreDemo.ts`)を表示し、「デモ・架空データ・音声なし」を常時表示。再生/一時停止/最初へは▶/Ⅱ/↶のアイコン、シークバー、48×48pxのタップ領域、prefers-reduced-motionでの離散更新、JSなしでの静的完全表示に対応。
3. ノート詳細ページのレイアウトを刷新。旧「スライドを1画面に収める」制約(Decision Log 0173)を撤去し、Googleスライドを常時表示の通常埋め込みに戻した。身体譜→「途中の記録」(スライド+コメント)→支援欄、という順で構成し、PCでは身体譜+スライドを主列、支援欄を副列とする2カラム(支援欄が無ければ1カラム)。
4. 「試行錯誤を支える」(`SupportSection.astro`)を新設。銀行振込のみ、fail-closed(`isSupportConfigured`、`src/config/support.ts`)。口座情報が1件でも欠けていれば支援ボタン自体を描画しない。今回は口座未登録のため`enabled: false`のまま実装し、本番には一切表示されない。
5. 「支援と使いみち」(`SupportLedger.astro`)を新設。月次収支(`src/data/supportLedger.ts`)を公開月のみ表示。`closingBalance = openingBalance + contributions - fees - Σexpenses`をモジュール読み込み時に検証し、不一致・繰越不整合はビルドを失敗させる(`assertLedgerIntegrity`)。今回は実データ未登録のため空配列で、セクション自体が描画されない。

## 採用理由 (Rationale)
- fail-closedの徹底: `supportConfig.enabled`を将来trueにしても、口座情報が不完全ならUIごと隠す設計にすることで、「空欄」「未設定」といった中途半端な表示を本番に出さないようにした。プレビュー用の口座・収支データはコンポーネント本体には持たせず、ローカル確認時のみ一時的に値を差し替えて目視確認し、確認後は元の空値に戻した(このコミットのdiffには含まれない)。
- 収支の整合性チェックをビルド時の例外としたのは、テストランナーが存在しないリポジトリで「小さな意味あるテスト」を実現する現実的な方法として選んだ。今後、月次データを追加する担当者が計算を間違えた場合、ビルドが失敗して気づける。
- 身体譜のレーン名・時刻目盛をSVGの外(HTML)に出したのは、320px幅でSVG内の文字が縮小され読めなくなることを避けるため。
- スライドの「1画面に収める」制約を撤去したのは、指示書が明示的に「入口の要件にしない」としたため。身体譜を主役にする構成に合わせた意図的な変更。

## 他の案 (Alternatives)
- 支援ボタンを「準備中」表示のまま常時出す案は、指示書が「未設定なら公開しない」と明記しているため見送った。
- 収支の検証をテストフレームワーク導入で行う案は、このリポジトリが依存を最小限に保つ方針(CLAUDE.md)のため見送り、ビルド時アサーションで代替した。

## 将来の変更可能性 (Future changes)
- 実口座が確定したら、`src/config/support.ts`の`supportConfig`を`enabled: true`+実際の口座情報に更新するだけで支援ボタンが公開される(コード変更は不要)。
- 実際の散歩記録・公開音声が用意できたら、`walkingScoreDemo`とは別に`kind: "recorded"`のWalkingScoreをノートのデータに追加し、`WalkingScorePlayer`にそのデータを渡す形に拡張する(コンポーネント自体は既にkindを区別できる設計)。
- 月次収支データは`src/data/supportLedger.ts`の配列に追記していく。`published: true`にした月から公開される。
