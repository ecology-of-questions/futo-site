# 0096. Aboutページの入口(ページヘッダー)を独立させ、見出し階層を明確化

- 日付: 2026-09-05
- 状態: 採用

## Decision

Decision Log 0094(2カラム化)・0095(循環図)を実施した後、ChatGPT
(Creative Director)のレビューとプロジェクトオーナーの確認を受け、
以下を追加で変更した。

1. **ページヘッダーの分離**: 従来、Eyebrow「ABOUT」(`<SectionTitle>`、
   h2)の直後にページのh1「公開研究室「ふ、と」について」が続き、
   そのh1が1つ目の2カラムブロックに含まれていた。これにより
   (a) h1が他のセクション見出し(h2)と同じfs-xlの見た目になり、
   (b) 見出し階層としてもh2の後にh1が来るという不自然な順序に
   なっていた。ページ冒頭を「Eyebrow(`<p>`)→ h1 → Lead」という
   独立したページヘッダーとして2カラムの外に切り出し、ページの
   最初の見出しがh1になるようにした。EyebrowはこのページのみSectionTitle
   コンポーネント(h2)を使わずプレーンな`<p>`にした(他ページの
   `<SectionTitle>`実装自体は変更していない)。
2. **Leadの新設**: 元々1つ目のセクションの本文だった最初の段落
   (「「ふ、と」は、日常のなかで生まれる小さな気づきや違和感を
   観察し…」)を、ページの要約としてページヘッダー側のLeadに移動
   した。文章そのものは変更していない。
3. **3セクション化**: ページヘッダーの下を「01 公開研究室として/
   02 研究と実践/03 運営者について」という番号つきの3セクションに
   再編した。01の本文はLeadに移した段落を除いた残りの段落
   (「大学や研究機関の内側だけではなく〜」)。02・03の本文・循環図は
   内容を変更していない。
4. **サイズ階層の明確化**: ページタイトル(h1、fs-xl・opacity:1)を
   ページ内で最も強い文字にし、セクション見出し(h2、fs-lg・
   opacity:0.75)を明確に一段小さくした。2カラム(左:番号+見出し、
   右:本文)は01〜03のセクションのみに適用し、ページヘッダーには
   使わない(タイトルが長く、12remの左カラムに収めると折り返しが
   増えるため)。
5. **セクション間の余白拡大**: 同じセクション内(見出しと本文)の
   間隔は変えず、セクション同士の間だけDesktop幅で`--space-5`
   (64px)、Mobile幅で`--space-4`(40px)に広げた。
6. **循環図の整理**(Decision Log 0095からの追加調整): 7項目
   (観察する/気づく/記録する/対話する/つくる/試す/また観察する)を
   5項目(観察する/気づく/記録する/対話する/つくる・試す)に整理し、
   最後の「つくる・試す」から最初の「観察する」に戻ることで循環を
   示す形にした。「また観察する」という独立ラベルは削除した(循環
   していること自体が「また観察する」を表すため)。円の中心に
   「問いの生態系」を追加し、単なる作業工程ではなく研究方法である
   ことを示した。この整理は円環図(装飾要素、aria-hidden)の
   ラベルのみに適用しており、本文の文章(「観察する、気づく、
   記録する、対話する、つくる、試す、そしてまた観察する。」)自体は
   変更していない。Playwrightで320px/375px/390px/1440px幅を計測し、
   5ラベルいずれも重なり・はみ出しがないことを確認した。

## 採用理由

- ChatGPT(Creative Director)から「ページタイトルと各セクション
  見出しが同じ見た目になっており、ページ全体の入口が弱くなって
  いる」という具体的な指摘があり、見出し階層(h2の後にh1)も実際に
  不自然だった。プロジェクト・オーナーが「本格的なほう」を選んで
  循環図を作った際の「全体的にわかりやすくしたい」という意図とも
  一致するため、ページの「入口」と「詳細」を明確に分ける今回の
  変更を採用した。
- 循環図のラベル統合(「つくる・試す」)は、Decision Log 0094では
  ChatGPT側の未確認の提案として見送っていたが、今回はプロジェクト
  オーナー自身が明示的にこの5項目案を指示しており、装飾要素
  (aria-hidden、本文とは別の視覚的な補足)のラベルにのみ適用される
  ため、実装した。本文の文章自体への影響はない。

## 他の案

- 特になし。プロジェクトオーナーからの指示がAstro側の実装方針
  (2カラムの範囲、余白の目安px、見出しサイズの相対関係)まで
  具体的だったため、指示通りに実装した。

## 将来の変更可能性

- 今回のAboutページの構成(Eyebrow/h1/Lead のページヘッダー + 番号
  つきセクション + 2カラム)は、プロジェクトオーナーの発言(「この
  Aboutページを先に「全ページ共通デザインの試作品」として完成させ
  るのがよい」)の通り、Home・Research・Contactへ展開する際の参照
  実装として扱う。展開時には、このページで使った`.pageHeader`・
  `.eyebrow`・`.pageTitle`・`.lead`・`.blockLabel`・`.number`という
  クラス名/構造をそのまま複製するのではなく、共通コンポーネント化
  するかどうかを含めて検討すること。
- Eyebrowをこのページだけ`<SectionTitle>`(h2)ではなく`<p>`にした
  ため、他ページ(Research・Contact)と実装が一時的に不揃いになって
  いる。他ページ展開時に、`<SectionTitle>`コンポーネント自体に
  `as="p"`を追加するか、共通の解決策を検討する。

## Research Context

「入口(ページヘッダー)」と「詳細(セクション)」を分けるという
判断は、読み手が最初に「このページが何のためのものか」を把握して
から、必要に応じて詳細を読み進められるようにするという、研究室の
「読みやすさ」に対する姿勢そのものである。Creative Directorの
指摘・プロジェクトオーナーの具体的な指示・実装者(Claude)による
検証(見出し階層・余白の実測、Playwrightでの重なり確認)という
3者の役割分担が機能した一例として記録する。
