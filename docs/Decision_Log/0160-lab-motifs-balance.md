# 0160. 実験室モチーフのバランス調整(文字を引き、モチーフを主役級に)

- 日付: 2026-09-17
- 状態: 採用
- 関連: Decision Log 0159(実験室モチーフ3種の決定案への統一)への
  追加調整。PR #88 merge後の新規PR。

## Decision

Decision Log 0159で実装したモチーフ3種について、プロジェクトオーナー
から「意味を持つビジュアルではなく、小さな装飾アイコンに見えやすい」
との指摘を受けた。とくに「研究断面をひらく」は重なりの面が小さいと
コンセプトが読めず、Fieldnoteも「点→線」の変化が見えにくいとの
判断だった。

指示は以下に限定されていた。

- ページの構造(タイトルと同じ行にモチーフを置く関係)は維持する。
- タイトルを約85〜90%に抑える。
- モチーフを約160%に拡大し、タイトル右側の空間をしっかり使う。
- category(「実験/アプリ/企画」)・説明文のサイズは維持する。
- モチーフを右端に小さく寄せるのではなく、タイトルと対になるくらいの
  幅を持たせる。

## 対応

`src/components/LabNotebookList.module.css`のみを、以下2箇所で調整
した。レイアウト構造(`titleRow`、flexboxによるタイトル/モチーフの
左右分割)自体は0159のまま変更していない。

1. `.title`の`font-size`を`var(--fs-xl)`から
   `calc(var(--fs-xl) * 0.88)`に変更(指示の85〜90%のレンジ内、88%)。
   トークン(`--fs-xl`)を基準にした相対値のため、`tokens.css`側の
   値が将来変わっても比率が維持される。
2. `.trace`の`width`を`clamp(3.25rem, 20vw, 5.5rem)`から
   `clamp(5.2rem, 32vw, 8.8rem)`に変更(0159比で各項を1.6倍)。
   モチーフのSVG自体(`viewBox`・path)は変更していないため、
   `width: 100%; height: auto`によりモチーフ全体(線・点・淡い面)が
   比例して拡大される。

`.label`(category)・`.description`(説明文)のfont-sizeは変更して
いない。

## 対応ファイル

- `src/components/LabNotebookList.module.css`: `.title`の
  font-size、`.trace`のwidthのみ変更。

`LabNotebookList.astro`(SVGのpathデータ自体)・
`src/pages/participate.astro`・`labNotebooks.ts`・
`/participate/[slug].astro`・Worker/D1/APIは今回も変更していない。

## 確認結果

- mobile(390px)/desktop(1440px)で`/participate`をPlaywright
  (`reducedMotion: 'reduce'`)で確認した。
  - モチーフが明確に大きくなり、タイトルは一段抑えられた見た目に
    なっている。
  - 「研究断面をひらく」: 拡大した高解像度スクリーンショット
    (390px幅・4倍スケール)で、3本の線が重なる部分の淡い面
    (`.overlap`)がはっきり見える大きさになったことを確認した。
  - Fieldnote: 同様の拡大スクリーンショットで、左側の散らばった点が
    右へ進むにつれ1本の線にまとまっていく「点→線」の変化が、以前
    より明確に読めることを確認した。
  - 最長タイトル「研究断面をひらく」でも、mobile(390px)でモチーフと
    重ならず、1行に収まっている(折り返しも発生していない)。
  - `document.documentElement.scrollWidth ===
    document.documentElement.clientWidth`をmobile・desktop双方で
    確認し、page-level horizontal overflowが無いことを確認した。
- `git diff --stat`で、変更が`LabNotebookList.module.css`1ファイルの
  みであることを確認した。
- `npx astro check`: 0 errors, 0 warnings, 1 hint(既存の無関係な
  hint)。
- `npm run build`: 15ページ生成、エラーなし。

## 採用理由

指示の数値(タイトル85〜90%・モチーフ160%)をそのまま採用し、
`calc()`によるトークン相対値と`clamp()`のスケールという既存の実装
パターンをそのまま流用した。新しいCSS変数や構造を増やさず、0159で
作った`titleRow`のflexbox構造(タイトル: `flex: 1 1 auto;
min-width: 0`、モチーフ: `flex: 0 0 auto`)がそのまま「タイトルと
モチーフが重ならない」という制約を満たし続けるため、サイズの数値
だけを変更する最小限の対応で済んだ。

## 他の案

モチーフのSVG自体(path)を描き直し、より複雑な意匠にする案も
検討し得たが、今回の指示は「サイズのバランス」に限定されており、
0159で採用した3つの意匠(立ち止まってまた歩き出す/点から線になる/
重なりから断面が生まれる)自体への不満ではなかったため、パスの再設計
は行わなかった。

## 将来の変更可能性

- 今回の`0.88`倍・`1.6`倍という係数は、プロジェクトオーナーが
  「くらいから試す」という表現で示した初期値であるため、実機確認の
  結果さらに調整する可能性がある。
- 「いま、ひらいている実験」セクション(Decision Log 0156の
  `liveExperimentSlugs`)が将来有効化された際も、同じ
  `LabNotebookList`を再利用するため、このバランスは自動的に
  引き継がれる。

## Research Context

「モチーフが小さな装飾アイコンに見える」という指摘は、単なる見た目の
好みではなく、モチーフが「かなり考えて作った」意味のある視覚言語で
あるにもかかわらず、そのサイズのせいで意味が伝わっていなかったという
指摘である。文字を一歩引かせてモチーフを主役級まで前に出す今回の調整
は、「装飾ではなく意味を運ぶ」という当初の意図(Decision Log 0155)を、
実際に機能する大きさで実現し直すものである。
