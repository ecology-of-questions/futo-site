# 0056. /research一覧の右側に説明文を2行までの要約として復活させる

- 日付: 2026-08-17
- 状態: 採用中(Decision Log 0054の続き)

## Decision

Decision Log 0054で一覧から削除した説明文(description)を、
プロジェクトオーナーの「右側に概要書けるんじゃない?」という
指摘を受けて復活させた。ただし単純に元へ戻すのではなく、
Desktop幅で行の右側に生まれていた余白を使う形にした。

`ResearchReviewList.astro`の各公開済みエントリを2カラムの
グリッドに変更した。
- 左カラム(`minmax(0, 22rem)`): 番号+タイトル、サブタイトル
- 右カラム(`minmax(0, 1fr)`): 説明文(最大2行、`-webkit-
  line-clamp: 2`で省略)、更新日+矢印

Mobile幅(899.98px以下)では1カラムに積み、右カラムは左寄せに
戻す。`PublishedReviewEntry`型にも`description`フィールドを
再度追加した。

## 採用理由

- Decision Log 0054でエントリを2行に圧縮した結果、Desktop幅では
  タイトル・サブタイトルの右側に余白が生まれていた。この余白を
  使って説明文を表示すれば、スクロール量を増やさずに「どんな
  内容か」という情報を一覧に戻せる。
- 説明文を2行に制限(line-clamp)することで、内容が長くても行の
  高さが揃い、一覧全体の縦方向のリズムが崩れない。

## 他の案

- 説明文を全文表示する案も検討したが、エントリごとに行の高さが
  バラバラになり、Decision Log 0054で目指した「スキャンしやすい
  一覧」という目的から外れるため、2行までの要約にとどめた。

## 将来の変更可能性

- 説明文の分量やタイトルの長さによっては、左右カラムの比率
  (`22rem` / `1fr`)を調整する必要が出てくる可能性がある。

## Research Context

「情報を削る」か「情報を活かす」かは、単純な二択ではなく、
使われていない余白を見つけて再配置する、という第三の道が
あることを示す一例。既存の要素(説明文)を捨てずに、レイアウトの
工夫で両立させた。
