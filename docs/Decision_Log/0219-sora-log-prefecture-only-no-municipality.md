# 0219. 市区町村の自由入力は追加せず、都道府県どまりとする

- 日付: 2026-11-13
- 状態: 採用

## Decision

Decision Log 0218で都道府県(任意)+簡易な位置図を実装した後、プロジェクトオーナーから「都道府県だけだとデータとして意味が薄いのでは」との指摘を受けた。これに対し、「都道府県を選ぶ→市区町村名を自由入力(末尾が市/区/町/村であることだけ検証)」という、プロジェクトオーナーが共有した試作と同じ方式を追加する案を提示したが、プロジェクトオーナーは「地図は都道府県単位のままでよいが、市区町村の自由入力は追加したくない」と回答した。

これを受け、記録項目は引き続き都道府県(任意)までとし、市区町村(自由入力・選択式いずれも)は追加しない。コード変更は無し(Decision Log 0218の実装のまま)。

## 採用理由

自由入力のテキストフィールドは、表記ゆれ(「藤沢市」「ふじさわ市」「藤沢」等)や誤入力によってデータの質が揺らぎやすく、「研究・報道・行政への要望・裁判など、目的を問わず使える公開の記録」という本アプリの目的(利用規約ドラフト参照)にとって、かえって扱いにくいデータになりうる。プロジェクトオーナーはこのトレードオフを踏まえ、精度より運用のシンプルさ・データの一貫性を優先する判断をした。

## 他の案

- 市区町村の自由入力(正規表現による末尾検証のみ)は提案したが、上記理由で不採用。
- 地域を絞った市区町村の選択式リスト(試作にあったShonan地域の市区町村一覧)も検討しうるが、全国展開を前提にした「都道府県」という粒度と矛盾する(特定地域だけ市区町村まで選べるのは一貫性がない)ため、今回は提案しなかった。

## 将来の変更可能性

将来、信頼できる市区町村データ(選択式での提供や、位置情報を伴う正式なデータセット)が用意できれば、改めて検討する。その際はDecision Log 0218の`prefecture`列と同様の形で、別途`municipality`列などを追加する形になる見込み。

## Research Context

正確さを求めて自由入力を増やすことが、かえってデータの一貫性を損ない「使える公開の記録」から遠ざかる、というのは重要な教訓である。シンプルな選択式のデータの方が、長期的には研究・報道などの用途に耐えるという判断は、このプロジェクトが重視する「育てていく記録」の考え方に合っている。
