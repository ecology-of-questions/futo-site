# 0087. Mobileメニューボタンを文字ラベルからハンバーガーアイコンに変更する

- 日付: 2026-09-04
- 状態: 採用中(Decision Log 0057を一部上書き)

## Decision

プロジェクトオーナーから、Mobile幅のHeaderにある「メニュー」という
文字ラベルのボタンについて「ダサいから3本線とかにして」との指示を
受けた。これを受け、`src/components/Header.astro` /
`Header.module.css`のMobile用開閉ボタン(Decision Log 0057で
実装済み)の見た目を、文字ラベルから3本線のハンバーガーアイコンに
変更した。

- ボタン内の「メニュー」というテキストノードを、`aria-hidden="true"`
  の`<span class={styles.menuIcon}>`に置き換えた。視覚的なラベルが
  なくなる分、ボタン自体に`aria-label="メニュー"`を追加し、
  スクリーンリーダー等でボタンの用途が引き続き分かるようにした。
- `.menuIcon`本体を中央の線とし、`::before`/`::after`疑似要素で
  上下2本の線を追加する形で3本線を表現した(`background-color:
  currentColor`により、ボタンの`color: var(--color-night)`をそのまま
  反映)。
- 開閉状態は、既存のJS実装(`aria-expanded`の切り替え、Decision Log
  0057)をそのまま流用し、CSS側で`.menuToggle[aria-expanded="true"]`
  セレクタを使ってアイコンを×形に変形させた(中央の線を透明にし、
  上下の線をそれぞれ45度/-45度回転)。JS側への変更は不要だった。

## 採用理由

- ハンバーガーアイコン(3本線)は、開閉式メニューの操作対象であることを
  一目で示す一般的な慣習的アイコンであり、「メニュー」という文字
  ラベルより視覚的に簡潔で、Headerの見た目もすっきりする。
- 開いた状態を×に変形させたのは、アイコンだけでは「今メニューが
  開いているか」が分かりにくいため。追加のJS実装なしに、既存の
  `aria-expanded`属性をCSSセレクタとして使うだけで実現できたため、
  「アニメーションライブラリを使わない」「フレームワークを使わない」
  という既存方針とも矛盾しない。
- `aria-label="メニュー"`を追加したのは、視覚的なテキストラベルを
  アイコンに置き換えたことで、スクリーンリーダー利用者にとって
  ボタンの用途が分からなくならないようにするため。既存の
  `aria-expanded`・`aria-controls`はそのまま維持した。

## 他の案

- SVGアイコンを別ファイルとして用意する案も考えられたが、3本線という
  単純な形状はCSSの疑似要素だけで表現でき、追加のアセットファイルを
  増やす必要がないため、CSSのみの実装を選んだ。
- 開いた状態のアイコン変形(×形)をJSで別クラスを付け替える実装も
  考えられたが、既存の`aria-expanded`属性がCSSセレクタとしてそのまま
  使えたため、JS側の変更を避け実装を最小限にとどめた。

## 将来の変更可能性

- アイコンのサイズ・線の太さは仮の値(`1.125rem`/`1.5px`)。実機で
  見づらい・小さすぎる等の指摘があれば調整する。

## Research Context

「メニュー」という文字ラベルを慣習的なハンバーガーアイコンに
置き換えたことで、Header全体の視覚的なノイズが減り、Decision Log
0085・0086で整えた「夜空」背景・Hero周りの静かなトーンとも調和する
見た目になった。
