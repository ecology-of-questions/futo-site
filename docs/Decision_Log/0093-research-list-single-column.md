# 0093. 研究断面一覧をデスクトップ・モバイル共通の縦1カラムに変更

- 日付: 2026-09-04
- 状態: 採用

## Decision

`/research`ページの研究断面一覧(`ResearchReviewList`)を、Desktop幅で
採用していた左右2カラム構成(左: 番号・タイトル・副題、右: 要約・
更新日)から、Desktop・Mobile共通の縦1カラム構成に作り直した。

- 各記事の情報を「番号・日付 → タイトル → 副題 → 要約 → 読む」の順に
  1本の縦の流れとして並べ、1つの記事内で視線が左右に分断されないよう
  にした。
- タイトルを最も強く(`--fs-xl`・weight 500)、番号・日付を最も小さく
  淡く(`--fs-sm`・opacity 0.6)、副題をタイトルより一段小さく
  (`--fs-lg`)、要約を本文サイズ(`--fs-base`・`--lh-body`)で表示する
  ようにサイズ関係を整理した。
- 要約の`-webkit-line-clamp: 2`による2行切り詰めを解除し、全文を
  表示するようにした。
- 公開済み記事(01・1.5)と構想中の記事(02・03)を分離し、構想中の
  記事は「次に考えていること」という見出しつきの別セクションに
  配置した。
- 見出し階層を、`SectionTitle`の「RESEARCH」(h2) → ページ固有の
  「研究断面」(`<p>`から`<h1>`に変更) → 各公開記事のタイトル(`<h2>`)
  → 「次に考えていること」(`<h2>`)という構成に整理した。
- 記事全体のリンク領域(`<a>`が記事ブロック全体を包む構造)は維持しつつ、
  末尾に「読む →」を追加し、hover・focus-visibleで矢印がスライドする
  (既存の`.arrow`パターンを踏襲)ことでリンクであることを示すように
  した。

配色・書体・背景・余白感(紺の夜空背景、`--space-*`トークンの使い方)
は変更していない。一般的なブログカードやサムネイル画像も追加していない。

## 採用理由

- 2カラム構成(Decision Log 0056)は、Desktop幅の右側の余白を埋める
  ために導入したものだったが、結果として1つの記事情報が左右に
  分断され、視線がジグザグに移動する構成になっていた。プロジェクト
  オーナーから「一つの記事内で視線が左右に分断される」という具体的な
  指摘を受け、情報の読む順序をそのまま画面上の並び順にする縦1カラムに
  戻すことにした。
- 要約の2行clampは、一覧を簡潔に見せるための制約だったが、「省略され
  た続きを読むには結局詳細ページに飛ぶ必要がある」という中途半端さが
  あった。指示に従い、一覧の時点で要約全文を読めるようにした。
- 構想中の記事(02・03)を公開済み記事と同じリスト内に混在させると、
  「読めるもの」と「まだ読めないもの」が同列に見えてしまう。別
  セクション名を与えることで、両者の違いを見出しレベルで明示した。

## 他の案

- 要約の全文表示は一覧を縦に伸ばすため、「続きを読む」のような
  展開UIも検討し得たが、Decision Log 0092(ページング機能見送り)と
  同じ理由(操作を挟むことによる離脱リスク)から、今回は素直に
  全文をそのまま表示する方針にした。

## 将来の変更可能性

- 研究断面の記事数が増えた場合(02・03が公開された場合など)、
  縦1カラムでは一覧が長くなる。その時点で、要約の見せ方や
  「次に考えていること」セクションの扱いを改めて検討する必要が
  あるかもしれない。
- ページ固有の`<h1>`(「研究断面」)は、`SectionTitle`の「RESEARCH」
  (h2)より後に登場する現行の見出し階層(About/Contactページと同じ
  パターン)を踏襲している。サイト全体でこのパターンを見直す場合は
  あわせて再検討する。

## Research Context

一覧という「入口」の情報設計は、研究そのものと同じく、完成した
静的な並びではなく、記事が増えるたびに見直されていく対象である。
今回の変更も、「読みやすさ」という具体的なフィードバックに応じて
並び順とサイズ関係を組み替えた一例であり、今後も記事数や内容の
変化に応じて作り直されることを前提にしている。
