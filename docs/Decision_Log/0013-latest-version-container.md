# 0013. ResearchStatement を「最新版を表示するための器」として位置づける

- 日付: 2026-08-04
- 状態: 採用中(コード変更なし、位置づけの明文化のみ)

## Decision

`ResearchStatement` を「完成版を表示するための器」ではなく、
「最新版を表示するための器」として位置づけ直す。Research Statementは
v0.1 → v0.2 → v1.0 と、Research Reviewや研究の進展とともに
変化し続けることを前提とする。

現在の `paragraphs` props は、この前提を追加実装なしで満たしている
(内容を丸ごと差し替えれば、それがそのまま最新版になる)。

一方で、以下はβ公開まで新機能を増やさない方針(2026-08-04合意)に
より、**実装せず Parking Lot に置く**。

- バージョン履歴の保持(過去のv0.1・v0.2をアーカイブとして残す)
- バージョン切り替えUI
- 変更履歴(差分)の表示

## 採用理由

- フィードバックにより、Research Statementが単発の差し替えではなく、
  今後継続的に版を重ねていくものだと明確になった。この認識を
  コンポーネントのコメントとして残しておかないと、次にこの
  コンポーネントを触る人(Claude自身を含む)が「完成版を待つ器」だと
  誤解する可能性がある。
- ただし、「今すぐ版管理機能を作る」ことと「将来版管理が来ることを
  意識して設計する」ことは別。現在の`paragraphs`という単純な構造は、
  既にどんな版が来ても差し替えられる形になっており、追加実装は
  不要だった。新機能凍結ルールに従い、コメントでの明文化に留めた。

## 他の案

- **version propを今のうちに追加しておく案(例: `version="0.1"`)**:
  表示に使わないメタデータを先回りして追加することは、「β公開まで
  新機能は増やさない」方針に反すると判断し見送った。実際に
  バージョン表示が必要になった時点で追加する。

## 将来の変更可能性

- β公開後、バージョン履歴・変更履歴の表示が必要になった時点で、
  `paragraphs` を単一の配列から `{ version: string; paragraphs:
  string[][] }[]` のような構造に拡張する可能性がある。その際も
  「器と中身を分ける」という設計方針(Decision Log 0003・0008)は
  変えない想定。

## Research Context

Research Statementが育つように、Research Reviewも、Conceptも、
Decision Logも育つ。器は変わらず、中身が育つ、という構造が
このプロジェクト全体を貫いている。ResearchStatus(Decision Log
0005・0006)を「出版状態ではなく研究状態」として設計したことも、
Research Statementを「完成版ではなく最新版の器」として位置づける
ことも、根は同じ一つの思想である。「公開研究室」というコンセプトが、
個々のコンポーネント設計を貫く一貫した原理として実装レベルに
降りてきている。
