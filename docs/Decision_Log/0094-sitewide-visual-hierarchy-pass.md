# 0094. サイト全体の視覚的階層の再設計(第一弾)

- 日付: 2026-09-04
- 状態: 採用(一部項目のみ。範囲はプロジェクトオーナー確認済み)

## Decision

「全体的に文字が多くて読む気をなくす」というプロジェクトオーナーの
フィードバックを受け、ChatGPT(Creative Director)からサイト全体の
視覚的階層(タイポグラフィの役割分け、余白・本文幅・罫線・背景の
使用ルール)を再設計する提案があった。提案全体をそのまま採用するのではなく、
実装担当(Claude/Tech Lead)として現状のコードと既往のDecision Logを
確認したうえで、(1)実装のみで完結する項目、(2)新しい文言や直近の
決定を覆す項目、に分けて報告し、(2)についてはプロジェクトオーナーに
個別に確認をとった。今回実装したのは以下。

1. **Heroの本文短縮**(index.astro): 4行の本文を、ChatGPT提案の2行
   「日常に生まれる小さな気づきを観察し、問いが育つ過程をひらく
   研究室です。」に差し替えた(プロジェクトオーナー確認済み)。
2. **Research Statement全文ページの章構成**(research-statement.astro、
   ResearchStatement.astro): 既存14段落を、文章・語順を一切変えずに
   意味のまとまりごとに5章(ふと、という瞬間/問いが生まれる手前/
   問いの生態系/誰にひらくのか/この研究がすること)に分けた
   (プロジェクトオーナー確認済み)。あわせて、冒頭2段落のみを
   Leadサイズ(fs-lg)で表示し(全文ページのみ。Homeの抜粋表示は
   Decision Log 0090の統一サイズのまま変更していない)、「問いの
   生態系」章では元の段落の一文をそのまま引用として抜き出して
   視覚的な目印にした(段落本文もそのまま残している)。
3. **Aboutページの2カラム化・プロセス表示**(about.astro/.module.css):
   Desktop幅で「公開研究室について/研究と実践/運営者について」の
   3区画を「左: 見出し(控えめなラベル) / 右: 本文」の2カラムに分け、
   区画間に細い罫線を追加した。Mobile幅では従来通り縦積みに戻す。
   あわせて、「研究と実践」本文中の「観察する、気づく、記録する、
   対話する、つくる、試す、そしてまた観察する」という一文と同じ語を
   使い、縦のプロセス表示(観察する→気づく→記録する→対話する→
   つくる→試す→また観察する)を本文の補足として追加した(文章自体
   は削除・変更していない)。
4. **Contactページの2カラム化**(contact.astro/.module.css): Desktop
   幅で「左: 導入文 / 右: フォーム」の2カラムに分けた。Mobile幅では
   従来通り縦積み。フォームの送信処理(Formspree、honeypot、送信
   状態表示)は変更していない。
5. **OPEN PRACTICEセクションの背景差別化**(index.astro/.module.css):
   「一緒に試す」セクションのみ、紺の背景(--color-night)を
   `color-mix()`でごく淡く明るくした面を敷き、他セクションと区別
   できる「独立した区画」として見せた。新しいHEX値を決め打ちせず、
   既存トークンから算出している。プロジェクトオーナーの指示により、
   他セクションへの背景差別化は今回は対象外。

## 採用理由

- 各項目とも、文章そのものを変えずにレイアウト・余白・罫線・背景の
  「見せ方」だけを変える範囲であれば、Tech Lead(Claude)の実装判断
  として進めてよい(CLAUDE.md「実装、アーキテクチャ、保守性、技術的
  提案」の担当範囲)。
- 一方、Heroの新しい文言・章見出しの追加・Lead/Bodyのサイズ差の
  再導入(Decision Log 0090で「本文サイズに統一する」と決めたばかり)
  は、内容・情報設計に関わる決定であり、プロジェクトオーナーの確認を
  個別に取ってから実装した(CLAUDE.md「コンテンツ、コピー、情報
  アーキテクチャに関する意思決定は事前に確認する」)。

## 他の案(ChatGPT提案のうち、今回見送った項目)

- **研究一覧のタイトル/副題/要約の一文統合**: 直近(同日)の
  プロジェクトオーナーからの、より具体的な指示(副題と要約を分けて
  全文表示する。Decision Log 0093、PR #51)と矛盾するため、今回は
  ChatGPT側の一般的な提案より、より新しく具体的なプロジェクトオーナー
  の指示を優先し、変更しなかった。
- **Lead/Bodyのサイズ差の全面的な再導入**: 適用範囲をResearch
  Statement全文ページの冒頭のみに限定し、Home抜粋を含む他ページには
  適用しなかった(プロジェクトオーナーの回答による)。
- **背景の明度差の全面適用**: OPEN PRACTICEセクションのみに限定し、
  About・Contact・Research Statementの引用等への適用は見送った
  (プロジェクトオーナーの回答による)。
- **プロセス表示の語の圧縮**(ChatGPTは「観察する→気づく→記録する→
  対話する→つくる・試す→また観察する」の6語圧縮版を提案していたが、
  「気づく」を省き「つくる/試す」を1語に統合するのは文章の内容を
  変える行為にあたるため採用せず、既存の本文にある7語をそのまま
  使った)。

## 将来の変更可能性

- 今回はChatGPT提案のうち「レイアウトのみで完結する範囲」を実装した
  第一弾。文言・情報設計に関わる残りの項目(タイポグラフィ役割の
  ドキュメント化、他セクションへの背景差別化、研究一覧の一文統合案
  など)は、プロジェクトオーナーの意向次第で改めて検討する。
- Aboutの2カラムレイアウトは`minmax(0, 12rem)`、Contactは
  `minmax(0, 18rem)`の左カラム幅を仮の値として実装した。実際の見え方
  を見て、必要であれば調整する。
- OPEN PRACTICEの背景差別化(`color-mix()`によるcolor-night+white 6%)
  は、視覚的な効果を見ながら明度を調整する余地がある。

## Research Context

ChatGPTの提案をそのまま実装するのではなく、実装担当としての技術的
判断(何が実装のみで完結し、何が内容・情報設計の意思決定にあたるか)
を挟んでから進めたことは、「研究室」としての役割分担(Creative
Directorが方向性を出し、Tech Leadが実装可否とリスクを判断し、
Project Ownerが最終決定する)を実践する一例である。ChatGPT提案の
一部を明示的に見送った判断も含め、記録として残す。
