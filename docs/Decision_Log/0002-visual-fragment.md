# 0002. VisualFragment を独立コンポーネントとして分離する

- 日付: 2026-08-04
- 状態: 採用中

## Decision

Hero等に配置する画像を `<img>` 直書きにせず、`VisualFragment.astro`
という独立コンポーネントとして切り出す。画像ソースは `src` / `alt`
の props で外部から渡し、コンポーネント内部には
「AIイラストか手描きスケッチか」の分岐ロジックを一切持たせない。
画像形式(PNG / SVG / WebP)も固定しない。

## 採用理由

- 現在Heroに配置しているAIイラストは仮素材であり、
  制作者本人の手描きスケッチへ順次置き換わっていく前提
  (キックオフ文書「将来の前提」/ Design Spec 9・13)。
- 差し替えは Hero だけでなく、各セクションの小さな図や線画にも
  今後起こりうるため、「差し替え可能な画像スロット」という概念を
  Hero専用ではなく汎用コンポーネントとして独立させておく方が
  将来の再利用性が高いと判断した。
- 画像形式を限定すると、SVGの線画に切り替えたいときに
  コンポーネントの改修が必要になる。`<img src>` ベースの
  シンプルな構造であれば形式を問わず差し替えられる。

## 他の案

- **Hero.astro に `<img>` を直接書く案**: 実装は最速だが、
  差し替えのたびにHero本体を触ることになり、
  「修正しやすいコードを書いてください」という要望に反すると判断し見送った。
- **画像形式ごとに分岐処理を持つ案(例: SVGならインライン描画、
  PNGなら`<img>`)**: 現時点でその複雑さが必要な理由がなく、
  「不要なライブラリ・複雑さを導入しない」方針に反するため見送った。
  必要になった時点で再検討する。

## 将来の変更可能性

- 画像に加えてキャプションや出典(観察日、場所など)を
  添えたくなった場合、`VisualFragment` に slot を追加する可能性がある。
- 手描きスケッチがSVGの線画になった場合、`<img>` ではなく
  インラインSVGでの描画に切り替える可能性がある。その際も
  呼び出し側のprops構造(`src`/`alt`)はできる限り変えない方針。
- 現在 `src` 未指定時にプレースホルダー枠を表示しているが、
  全セクション実装が進みアセットが揃った段階でこの分岐は
  不要になる可能性がある。

## Research Context

このホームページは完成品ではなく、研究とともに育つことを前提としている。
現在使用しているAIイラストは完成形ではなく、将来そこへ観察スケッチや図が
置かれるための余白である。VisualFragmentはその思想を実装へ翻訳するための
コンポーネントである。
