# 0023. Mobile幅のHeroビジュアルを、縦積みから背景の「透かし」表現に変更する

- 日付: 2026-08-15
- 状態: 採用中(Decision Log 0020における「Mobile: コピー→ビジュアル
  縦積み」という設計方針を一部上書き)。Desktopに関する記述は
  Decision Log 0024で上書き済み。

## Decision

Hero(`src/components/Hero.astro` / `Hero.module.css`)のMobile幅
(900px未満)での表示を変更した。

修正前は、Decision Log 0020で確定した通り「コピー(見出し・本文・
CTA)→ビジュアル(渦のアートワーク)」の縦積みで、ビジュアルはコピー
ブロックの下に独立したブロックとして表示されていた。

修正後は、ビジュアルをコピーの背景側に大きく重ね、`opacity: 0.4`の
「透かし」として配置する形に変更した。実装は次の4点:

- `.hero`に`position: relative`を追加し、`.visual`のabsolute配置の
  基準にした。
- `.copy`に`position: relative; z-index: 1;`を追加し、常にビジュアル
  より前面に来るようにした。
- `.visual`は`@media (max-width: 899.98px)`で
  `position: absolute; inset: 0; z-index: 0; opacity: 0.4;
  pointer-events: none;`を指定し、`.hero`いっぱいに広げた背景として
  配置した。`pointer-events: none`により、下に重なったコピー側の
  リンク(CTA・Scroll)のタップ操作を一切妨げない。
- `.visual :global(img)`(Mobile限定)で`object-fit: cover;`を指定した。
  VisualFragment側の既定は`object-fit: contain`だが、これはDesktopの
  3:2の箱を前提にした値。Mobileでは`.visual`がコピーの縦に長い背面
  全体(`inset: 0`)まで広がるため、`contain`のままだと画像が横幅基準の
  細い帯にレターボックスされ、絵柄のごく一部(キャンバス中央〜右寄り
  に集中している範囲。Decision Log 0018参照)しか透けて見えない
  問題があった。`cover`に切り替え、絵柄が背面エリア全体に大きく
  行き渡るようにした。

この時点ではDesktop幅(900px以上)の左右分割レイアウトは変更して
いなかった。`.visual`のDesktop向けの基本スタイル(`width: 100%;
aspect-ratio: 3 / 2;`)はそのまま残し、`@media (max-width: 899.98px)`
側だけがそれを上書きする形にした(Desktopのレイアウト自体は、
その後Decision Log 0024で「Hero内の右カラム」から「Home全体の
固定背景」へと変更されている)。

## 採用理由

- 依頼(「文章の下に別ブロックとして表示されているものを、文章に
  重ねる形にしたい」)に対して、`position: absolute` + 低opacityの
  透かし表現は、追加のライブラリなしにCSSのみで実現でき、
  「アニメーションライブラリ不使用」「ライブラリを持ち込まない」
  という方針とも矛盾しない。
- 初回実装では依頼で示された0.15〜0.3の範囲から`opacity: 0.2`を
  採用したが、スクリーンショットで確認したところ、画像自体が
  `object-fit: contain`によりMobileの縦長の背面で細い帯状に
  レターボックスされていたため、絵柄がほとんど見えなかった
  (右側にわずかに透ける程度)。`object-fit: cover`へ変更して絵柄が
  背面全体に行き渡るようにした上で、`opacity`も0.4へ上げ、
  375px/320px幅のスクリーンショットで絵柄がはっきり視認でき、
  かつ見出し・本文の可読性も損なわれていないことを確認した。
- `pointer-events: none`を明示したのは、`.visual`が`.copy`と重なる
  領域を持つため、指定しない場合ビジュアル側がCTAやScrollリンクの
  タップ判定を奪う可能性があったため。Playwrightでの実クリック確認
  でも、CTAリンク(`#research-statement`へのページ内遷移)が問題なく
  機能することを確認済み。
- `.visual`の基本スタイル(Desktop向け)をそのまま残し、Mobile側だけ
  `max-width`メディアクエリで上書きする構成にしたのは、CSSの
  カスケード順序(同じ詳細度のルールは後に書かれた方が勝つ)を踏まえ、
  「Desktop用の基本値を先に書き、Mobile限定の上書きをその後に置く」
  という順序を守ることで、意図しない上書き衝突を避けるため。

## 他の案

- **`.hero`側の`@media (min-width: 900px)`ブロック内に`.visual`の
  リセット(`position: static`等)を追加する案**: 実装時に一度この形で
  試したが、`.visual`の基本ルール(Desktop向け`aspect-ratio: 3/2`等)が
  CSSファイル内でその後(下)に書かれているため、CSSのソース順に
  よって基本ルールがリセットを上書きしてしまい、Desktopでも
  Mobile用のabsolute配置が残ってしまう不具合になった。ルールの
  書く順序に依存する脆い実装だったため、「Desktop向け基本値 →
  Mobile限定の上書き(`max-width`メディアクエリ)」という順序が
  自己完結する構成に変更した。
- **画像自体にCSSの`filter: blur()`をかけて馴染ませる案**: 依頼の
  範囲(opacityによる透かし)を超える提案だったため見送った。
  将来「もっと馴染ませたい」という声が出た場合の選択肢として残す。

## 将来の変更可能性

- ビジュアル画像(`03_top_page_artwork.png`)自体が差し替わり、
  画像内のコンテンツ配置(現在は中央〜右寄り)が変わる場合、透かし
  として見える位置も変わるため、Mobileでの見え方を再確認すること。
- opacityの値(0.4)は「絵柄が視認でき、かつ可読性を損なわない範囲」
  という基準で選んだ仮値。Design Spec側で正式なトーン・透過率の
  指定が来た場合は、そちらを優先して更新する。
- `object-fit: cover`は箱の縦横比によっては絵柄の周辺部分が
  トリミングされる。将来Heroのコピー量が増減して`.hero`の縦横比が
  大きく変わる場合、透かしとして見える範囲も変わるため、その都度
  Mobileでの見え方を確認すること。

## Research Context

Hero Spec(Design Spec 5)が定める「ビジュアルの役割は"研究内容"
ではなく"空気"を伝えること」という位置づけは、この変更でむしろ
強化されたと考えている。ビジュアルを独立したブロックとして
「見せる」のではなく、コピーの背景に溶け込ませる透かし表現に
することで、ビジュアルは主張せず、あくまでコピーが伝える「気づき」
の空気を下支えする存在になった。これは「余白を思考時間として扱う」
という研究室の思想を、Mobileという限られた縦スペースの中でも
維持しようとする試みでもある。
