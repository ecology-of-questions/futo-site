# 0205 — 「この場所について」を「試す」のすぐ右横に、モバイルもflex-wrapで対応

## Decision
Decision Log 0204(「この場所について」を人物イラストの行の右に配置)に対し、プロジェクトオーナーから「もっと『試す』の右横にできる? モバイルも、モーションの右横配置可能?」という追加の指摘を受けた。0204ではPC幅(761px以上)だけ`.heroSceneWithAside`を`justify-content: space-between`のflexにしており、リンクは人物イラストの行から離れた右端に配置されていた。モバイル幅(760px以下)は`.heroSceneWithAside`をflex化しておらず、常に人物イラストの行の下に積んでいた。

`src/pages/index.module.css`の`.heroSceneWithAside`を、幅を問わず(メディアクエリを撤廃して)常に`display: flex; flex-wrap: wrap;`にし、`justify-content: space-between`をやめて`column-gap: var(--space-4); row-gap: var(--space-3);`によるgapベースの隣接配置に変更した。これにより:

- PC幅では、リンクは人物イラストの行の右端(コンテナの右端)ではなく、「試す」のすぐ右に隣接するようになった。
- 画面幅が十分にある場合(実測で430px以上)は、モバイルでも人物イラストの行とリンクが横並びになる。
- 画面幅が足りない場合(実測で412px以下)は、`flex-wrap`により自動的にリンクが人物イラストの行の下に折り返す。これは以前の「760px以下は常に縦積み」という固定的なブレークポイントの代わりに、実際に並べる余地があるかどうかで自動的に決まる。

`.introAside`のmargin-top(以前は複数の`@media (max-width: 760px)`ブロックに分散し、最終的に`var(--space-3)`が有効になっていた、Decision Log 0199参照)は、折り返したときの余白を`.heroSceneWithAside`の`row-gap`が担うようになったため、最後に有効だった宣言(`@media (max-width: 760px) { .introAside { margin-top: ... } }`)を`0`に変更した。

また、`.heroScene`クラス自体はDecision Log 0204で`margin-top`を`.heroSceneWithAside`に移して以降、CSSプロパティを一つも持たないクラスになっており、ビルド後のHTMLにも出力されていなかった(未使用として扱われていた)。`src/pages/index.astro`から`class={styles.heroScene}`という参照を削除した(`aria-hidden="true"`は保持)。

## 採用理由 (Rationale)
- 「試す」のすぐ右横に、という指摘に対しては、`justify-content: space-between`(コンテナの両端に離す)をやめ、`gap`だけで隣接させる方式に変えるのが最も直接的な対応。
- モバイルも「横並びにできるか」という問いに対しては、幅で分岐する固定ルールではなく、`flex-wrap`によって「入る幅があれば横に並び、無ければ自動的に下に折り返す」という、コンテンツ量ベースの自然な挙動にした。これにより、今後人物イラストのサイズやリンクの文言が変わっても、都度ブレークポイントを再計算する必要がない。
- 実測(Playwrightで320〜1440pxを確認)の結果、430px以上の画面では横並びに収まり、412px以下では折り返す。この境界を明示的な数値でハードコードするのではなく、実際のコンテンツ幅(人物イラストの行の幅+gap+リンクの幅)がコンテナ幅に収まるかどうかで自然に決まるようにした。人物イラストのサイズを画面幅に応じて縮小しすぎない(Decision Log 0199の方針)という制約と両立させるには、無理に全幅で横並びを強制するよりも、この自動折り返しの方が安全である。

## 他の案 (Alternatives)
- モバイルでも常に横並びを強制する案(人物イラストをさらに縮小する、またはリンクの文言を短くする)も検討したが、Decision Log 0199で「人物が記号的に小さくなりすぎないように」という制約を確認済みであり、狭い画面でさらに縮小する余地は乏しいため見送った。
- 特定のピクセル幅(例: 430px)を新しいブレークポイントとして明示的にハードコードする案も検討したが、`flex-wrap`によるコンテンツベースの自動折り返しの方が、将来人物イラストやリンクのサイズが変わっても追従できるため、こちらを採用した。

## 将来の変更可能性 (Future changes)
- リンクと人物イラストの行の間隔は`.heroSceneWithAside`の`column-gap`(横並び時)・`row-gap`(折り返し時)でそれぞれ調整できる。
- 横並びになる境界の画面幅を変えたい場合は、人物イラストのサイズ(`--hero-walker-w`等)かリンクの文言・余白を調整することで、間接的に変わる。

## Research Context
「この場所について」への入り口を、実際に探究を営む人物イラストのすぐそばに置くという方針(Decision Log 0204)を、画面幅に関わらず徹底した変更である。ハードコードされたブレークポイントではなく、「入る余地があれば並び、無ければ自然に折り返す」という柔軟な挙動にしたことは、コンテナやコンテンツが変化しても壊れにくい実装を志向するという、このプロジェクトの実装方針(CLAUDE.md「単純な実装を優先する」)にも沿っている。
