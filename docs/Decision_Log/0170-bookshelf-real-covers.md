## Decision

プロジェクトオーナーから、指示書(`claude_code_bookshelf_v0.2.md`)を
受け取った。要旨は以下の4点。

1. 疑似背表紙(tone色面)を実際の書影に置き換える。
2. 表紙下のタイトル・著者名の重複表示を削除する(→ Decision Log 0168で
   既に対応済みのため、今回は確認のみ)。
3. 「一緒に読みたい」UIを本棚一覧から削除する(→ Decision Log 0167で
   既に対応済みのため、今回は確認のみ)。
4. レイアウトをシンプルに保ち、レスポンシブで見やすくする。

書影の取得方法について、事前のやり取りでプロジェクトオーナーから
「Amazonリンクから引用」という案が出たが、Amazon商品ページの直接
スクレイピングによる画像hotlinkは、Amazon Product Advertising API
(PA-API)のような正規の取得方法ではなく規約上グレーであること、
PA-APIの利用には継続的な適格販売実績(直近30日間で一定数、初回は
180日以内に3件)が必要で、本棚の現状(全冊`purchaseUrl`未設定)では
現実的でないことを説明した。指示書v0.2では、この問題を回避する形で
「ISBN経由でOpen Library Covers API等から取得する」という、Amazonに
依存しない方針が示されたため、これに沿って実装した。

## 対応

### 書影取得の優先順位に「ISBN経由」を追加

`src/types/bookshelf.ts`のコメント、`src/components/BookshelfShelf.astro`
の実装を、以下の優先順位に変更した。

1. `book.image`(自前で用意した画像)
2. `book.externalCoverUrl`(正規に取得済みの外部URL)
3. `book.isbn13`から組み立てたOpen Library Covers API URL
   (`https://covers.openlibrary.org/b/isbn/{isbn13}-L.jpg?default=false`)
4. 仮カバー(tone、color-mixの色面)+タイトルの可視テキスト

Open Library Covers APIを選んだ理由は、ISBN(本の書誌情報として実在する
公開された識別子)から書影を引ける無料の公開APIで、認証・契約・
Amazonのような適格販売要件が不要なため。指示書v0.2で例示されていた
方法でもある。

`coverImage`/`isbn`という指示書上の新フィールド名は使わず、既存の
`image`/`isbn13`をそのまま流用した。意味・役割が完全に一致しており、
並行する2種類のフィールドを持つ必要が無いため。

### 書影が見つからない場合のフォールバック

Open Library Covers APIは、該当する書影が無いISBNに対して`default=false`
指定時は404を返す。ISBN指定のimg要素に`data-cover-fallback`を付け、
ページ末尾の`<script>`で`error`イベントを監視し、失敗時はその`img`を
削除し、隣接する非表示のプレースホルダー(`data-cover-placeholder`、
`hidden`属性)を表示する形にフォールバックする。「本棚に本を持ち寄る」
トグル等、既存のhidden属性+JSというvanilla JSパターンを踏襲している。

実装中、プレースホルダーに使う`.coverTitle`が常時`display: -webkit-box`
を持つため、UAスタイルシートの`[hidden] { display: none }`がカスケードで
負けてしまう問題を発見した(Decision Log 0161で発見した`.heroItem`と
同種の問題)。`.coverTitle[hidden] { display: none; }`を明示的に追加して
対処した。

### `object-fit`を`cover`から`contain`に変更

`.coverImage`は、仮カバー(tone色面)を前提に`object-fit: cover`だったが、
実際の書影(縦横比が3:4の枠と必ずしも一致しない)を切り取らず全体が
見えるよう`object-fit: contain`に変更した。余白が生じる場合は`.cover`の
toneグラデーション背景がそのまま透けて見える(指示書の「画像の縦横比を
崩さない」「書影全体が見えるようにする」に対応)。

### 6冊のISBN-13・著者情報の調査

6冊すべてについて、国立国会図書館サーチ・版元ドットコム・出版書誌
データベース(books.or.jp)・出版社公式サイト等、複数の公開書誌情報源で
相互に確認できたISBN-13を追加した。あわせて、これまで著者未確認だった
「調査的感性術」の著者(マシュー・フラー、エヤル・ヴァイツマン。訳者は
中井悠)も同じ調査で判明したため追加した(いずれも推測ではなく、複数の
情報源で確認済み)。

| 本 | 版元・訳者等 | ISBN-13 |
|---|---|---|
| 経験と教育 | 講談社学術文庫(市村尚久訳、2004) | 9784061596801 |
| 調査的感性術 | 水声社(中井悠訳、2024) | 9784801007659 |
| 想像の共同体 | 「定本」書籍工房早山版(白石さや・白石隆訳、2007) | 9784904701089 |
| マツタケ――不確定な時代を生きる術 | みすず書房(赤嶺淳訳、2019) | 9784622088318 |
| 生きていること――動く、知る、記述する | 左右社(柴田崇ほか訳、2021) | 9784865280371 |
| 現代日本語における意図性副詞の意味研究 | ひつじ書房(2023) | 9784823411717 |

「想像の共同体」は、初版(NTT出版・1997年、ISBN-13制度導入以前の
書籍でISBN-10のみ)と「定本 想像の共同体」(書籍工房早山・2007年)の
2つの版が流通している。データ上の`title`は版を区別していないため、
現在も入手しやすい「定本」版のISBNを採用した(版の選択自体は本の
内容を変えるものではないと判断)。

## 確認結果(および確認できなかったこと)

- `npx astro check`: 0 errors, 0 warnings, 1 hint(既存の無関係な
  hint)。
- `npm run build`: 15ページ生成、エラーなし。
- Playwrightでmobile(390px)/desktop(1440px)を確認し、横方向overflowが
  無いこと、`alt`にタイトル(+持ち寄られた本の場合はその旨)が入って
  いること、「一緒に読みたい」文字列が存在しないこと、「本棚に本を
  持ち寄る」トグルが引き続き動作することを確認した。
- **フォールバック機構自体の動作は確認できた**: この開発環境の
  ネットワークegressポリシーが`covers.openlibrary.org`への接続を
  ブロックしているため(組織ポリシーによるもので、開発者側で解除
  できない)、6冊とも意図的に「画像取得失敗」の状態が発生し、
  `error`イベント→画像削除→プレースホルダー表示という一連の
  フォールバックが正しく動作することを確認できた。
- **一方、実際にOpen Library側に該当する書影が存在するかどうかは、
  この環境からは確認できていない。** 本番環境の実際の訪問者の
  ブラウザは、この開発環境のネットワーク制限を受けずに
  `covers.openlibrary.org`へ直接アクセスするため、そちらでは正しく
  取得できる可能性があるが、それを実際に確認する手段が今回無かった。
  デプロイ後、実際に書影が表示されるか、プロジェクトオーナー側での
  確認をお願いしたい。書影が見つからなかった本は、上記フォールバック
  により自動的に仮カバー表示になるため、最悪の場合でも壊れた画像
  アイコン等が表示されることは無い。

## 採用理由

指示書v0.2の方針(Open Library Covers API等、Amazon依存でない取得
方法)に沿って実装した。Amazon PA-APIは適格販売要件のハードルが
高く、現状の本棚の規模・目的(物販ではなく研究記録)に合わない一方、
Open Library Covers APIはISBNさえ分かれば認証・契約不要で使える。
書影が見つからない場合も、フォールバックにより「実在しない書影を
それらしく見せる」ことなく、既存の仮カバー表示に自然に戻る設計に
した。

## 他の案

指示書が提案していた新規フィールド`coverImage`/`isbn`を追加する案も
検討したが、既存の`image`/`isbn13`がすでに同じ役割を持っており、
並行する2つのフィールド体系を持つと混乱するため見送った。

## 将来の変更可能性

- 実際にデプロイ後、書影が正しく表示されない本があった場合は、正しい
  ISBN-13への修正、または`externalCoverUrl`への切り替え(正規に取得
  した別の書影URLがあれば)を検討する。
- 将来Amazon PA-API等、より高品質な書影ソースが利用可能になった場合、
  `externalCoverUrl`の優先順位がisbn13より高いため、データ追加だけで
  切り替えられる。

## Research Context

書影という「実在するが自分では作っていないもの」をどう扱うかという
問題は、CLAUDE.mdの「実在するものだけを見せる」という原則と、
Amazonの利用規約・書影自体の著作権という外部の制約の、両方を同時に
満たす必要がある実践的な課題だった。ISBNという公開された書誌情報を
手がかりに、認証不要の公開APIを使うという選択は、「できる範囲で
正直に実装し、できないことは仮カバーという既存の誠実な表現に戻す」
という、このプロジェクトがこれまで繰り返してきた判断の延長線上に
ある。
