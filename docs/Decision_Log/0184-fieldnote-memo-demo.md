# 0184 — 「Fieldnote」ノートに読書メモアプリの体験デモを追加

**一部superseded → 0190(2026-09-20)。** 記録詳細画面の「AIが読んだこと」+「私のメモ」は、実際に出荷した本体アプリ(`/fieldnote/`、Decision Log 0187)の語彙「抜粋・コメント・つながり」に合わせて刷新した。このエントリの他の決定(iframe不採用、6セッションの非対称データ、配色統一、progressive enhancement方式、セッションレベルのタブ構成)はそのまま有効。

## Decision
2026-09-19、プロジェクトオーナーから、Claudeの「Design」キャンバス機能で作った「Fieldnote デューイ読書」というアプリ構想のモックアップ(claude.ai/artifact/QSx1PF2fTRXEEpqAzqAXwL)を共有され、「読書メモ体験デモ」としてHP内に埋め込みたいという相談を受けた。検討の結果、以下の方針で実装した。

1. モックアップのURLをそのままiframeで埋め込むことはしなかった。理由は「他の対応」節を参照。
2. モックアップの見た目・状態遷移(セッション表示 → 「概要/たどる/自分のまとめ/育つ」の4タブ → 追記(写真・手書き)を開いて詳細を見る画面)を、サイト共通のtokens.cssの配色・書体を使った素のAstroコンポーネント(`FieldnoteMemoDemo.astro`)として再実装した。
3. 埋め込み先は、プロジェクトオーナーの選択により「Fieldnote」ノート詳細ページ(`/participate/fieldnote`)。既存の`WalkingScorePlayer`(散歩譜ノート)と同じ「1ノートに1つの体験デモを埋め込む」パターンを踏襲した。モックアップのデフォルトセッションが「デューイ読書」で、本棚の「経験と教育」(ジョン・デューイ)と自然につながる点もこの選択の後押しになった。
4. データ(6セッション分の記録内容)は、モックアップの`DATA`配列の内容をそのまま`src/data/fieldnoteMemoDemo.ts`に引き継いだ(架空の内容を新しく足していない)。

## モックアップから変更した点
- **「Watchの録音の追記先」ボトムシート → 「他の記録を見る」セッション切り替えに変更**: 元のUIは、Apple Watchの録音がどのセッションに追記されるかを選ぶだけで、表示中のセッションの記録自体は切り替わらない設計だった。まだ存在しない実機連携(Apple Watch)を前提にした文言をデモにそのまま出すのは実態と異なるため、「表示するセッションを切り替える」という、実際に機能する形の操作に置き換えた。
- **「写真を追加」「読み取り直す」「この追記を削除」ボタンを削除**: 静的なデモにはこれらを支えるバックエンドが無く、押しても何も起きないボタンになってしまう。「未完成な動作をそれらしく見せない」という、このリポジトリの既存コンポーネント(`WalkingScorePlayer`等)と同じ方針に合わせて、機能しない操作は表示しないことにした。
- **「私のメモ」欄を実際に入力できるtextareaにした**: 訪問者が実際に触って体感できる要素として、この欄だけは本物の入力欄にした(このデモでは保存されない。ページを離れると消える旨を明記している)。
- **配色・書体をtokens.cssの既存値に統一**: モックアップは独自の配色(緑・赤のアクセント、Google FontsのShippori Mincho B1・Zen Kaku Gothic New)を使っていたが、CLAUDE.mdの「色・書体を独自にハードコードしない」方針に従い、`--color-accent-blue`ひとつをアクセントとして使う配色に描き直し、書体もサイト共通の`--font-body`/`--font-sans`を使うようにした。緑=肯定/赤=削除という色分けは、削除機能自体を無くしたため引き継いでいない。

## 他の対応 (Alternatives)
- **URLをそのままiframe埋め込みする案**: 見送った。このモックアップはClaudeの「Design」キャンバスという編集ツールの1バージョンであり、外部からiframeで開いた場合にキャンバスの編集画面(ズーム・パン等の操作UI)ごと表示される可能性が高く、単体の画面だけを綺麗に見せる保証がない。また表示・動作がAnthropicの独自ランタイム(`support.js`等)に依存し続けることになり、CLAUDE.mdの「ポータブルな静的サイトを保つ」方針にも合わない。
- **6セッション全ての詳細な内容を新しく書き足す案**: 見送った。モックアップは「デューイ読書」以外の5セッションは記録のみで概要・まとめが空、という非対称な状態を意図的に見せていた(「まだ書いていません」「まだ見つかっていません」の状態を含めて構想の一部)。架空の内容を追加で埋めると、この非対称さ=「育つまでには時間がかかる」というツールの本質的な部分が失われるため、そのまま引き継いだ。

## 実装方式
CLAUDE.mdの「フレームワーク不使用」方針に沿い、6セッション分のヘッダー・タブ・パネルを全てビルド時に静的HTMLとして描画し、クライアントサイドJSは表示/非表示の切り替えのみを行う(`WalkingScorePlayer`と同じ「全部描画してJSで出し分ける」progressive enhancement)。JSが無い場合でも初期状態(デューイ読書・たどるタブ)がそのまま読める。タブの選択状態は`aria-selected`属性のみで管理し、CSS Modulesのハッシュ化されたクラス名をJS側から付け外ししない(既存コンポーネントの検証で得た教訓を踏襲)。

## 将来の変更可能性 (Future changes)
- 実際にこのツールを開発する場合、`src/data/fieldnoteMemoDemo.ts`のデータ構造(`FieldnoteSession`/`FieldnoteEntry`)は、実データに置き換える出発点として使える設計にしている。
- 「他の記録を見る」の実装は、複数ノート(散歩譜・Fieldnote等)を横断する形に将来発展する可能性があるが、今回はFieldnote内の6セッションの切り替えのみを対象にした。

## Research Context
「ふ、と」は公開研究室として、完成していないもの・構想段階のものもそのまま見せる方針(CLAUDE.md「未完成を隠さない」)。この体験デモも、実際に動くアプリではなく構想の手触りを体感してもらうためのものであることを冒頭のラベル(「Fieldnoteの体験デモ」「デモ・架空の記録です」)と末尾のキャプションで明示し、実在するかのように見せていない。
