# 0198 — モバイルHeroのモーションに、デスクトップと同じ「揃って待つ→間を置いて再開」の時間の流れを適用

## Decision
Decision Log 0197でデスクトップHeroに追加した「観察する→学ぶ→試すの順にフェードイン→3人が揃った状態を保持→同時にフェードアウト→短い間を置いて再開」というモーションについて、プロジェクトオーナーから「モバイルにも同じ時間の流れを適用してほしい」という指示を受けた。0197はデスクトップのみを変更しており、モバイル(人物ひとりが中央でその場のまま観察する/学ぶ/試すをクロスフェードし続ける、Decision Log 0195)は、ループの継ぎ目に間が無いまま延々と循環する構成のままだった。

`src/pages/index.module.css`のモバイル専用アニメーション(`heroPoseObserveMobile`/`heroPoseLearnMobile`(新設)/`heroPoseTryMobile`、および対応する`heroCaptionMobile*`)を以下のとおり変更した。横並びの3人・人物イラスト・サイズ・見出し・余白は変更していない。

1. 観察するの姿勢とラベルが現れ(フェードイン)、しばらく留まる。
2. 観察するが消えるのと入れ替わりに学ぶが現れ(クロスフェード)、しばらく留まる。
3. 学ぶが消えるのと入れ替わりに試すが現れ(クロスフェード)、しばらく留まる。
4. 試すが消えたあと、他の2つと違い、すぐには次(観察する)を出さず、約1秒の空白(人物・ラベルとも非表示)を置く。
5. 空白のあと観察するに戻り、周期(11秒)を繰り返す。

デスクトップとモバイルで「間(空白)を置くのは1周期につき1回だけ、かつ最後の姿勢が消えたあとにまとめて置く」という構成を揃えている。観察する↔学ぶ、学ぶ↔試すの間はデスクトップと同様にクロスフェードで滑らかに繋いでおり、そこには空白を挟んでいない(指示文でも試す→観察するの区間だけに「短い空白の後に」という言い回しが使われているため)。周期はデスクトップと同じ11秒にした。

`prefers-reduced-motion: reduce`・`scripting: none`(JavaScript無効相当)のフォールバック(人物を「学ぶ」で静止、注釈は「観察する　学ぶ　試す」を静かな1行で表示)は変更していない。通常時に注釈を1語だけ表示する仕組み(`.heroCaptionGroup`/`.heroCaptionMobile`)も変更していない。

## 採用理由 (Rationale)
- モバイルは物理的に1体しか置けないため、デスクトップの「3人が同時に画面に揃う」状態をそのまま再現することはできない。指示も「横並びにはしない」と明記しているため、その代わりに「1周期の終わりに一度だけ間を置いて再開する」という時間配分の構造だけを揃えることで、「同じ時間の流れ」という要求に応えた。
- 観察する↔学ぶ、学ぶ↔試すの間は空白を挟まずクロスフェードにしたのは、指示文が「短い空白」と明示しているのは試す→観察するの1箇所だけであり、姿勢の切り替えのたびに毎回一瞬何も無くなる作りにすると、かえって不安定で落ち着かない見え方になるため。
- 周期をデスクトップと同じ11秒にしたのは、単純に他の値を選ぶ理由が無く、指示の「約10〜12秒」の範囲内でデスクトップと数値を揃えておいた方が、将来どちらかの周期を調整する際に混乱が少ないため。

## 他の案 (Alternatives)
- 観察する→学ぶ→試すの間にも短い空白を挟む案(3箇所すべてに間を置く)も検討したが、指示文の書き方(試すの後だけ「空白」という言葉を使っている)と食い違うため見送った。
- モバイルの周期をデスクトップと別の値(例えば独自に9秒など)にする案も検討したが、指示にモバイル独自の秒数指定は無く、デスクトップと合わせておく方が「同じ時間の流れ」の趣旨に近いと判断した。

## 将来の変更可能性 (Future changes)
- 空白の長さ(現在は11秒中の90.9%〜100%、約1秒)や各姿勢の保持時間は、`heroPoseObserveMobile`/`heroPoseLearnMobile`/`heroPoseTryMobile`と対応する`heroCaptionMobile*`の%値を(3種類とも同じ値で)調整すればよい。
- デスクトップの周期(`heroFigureCellObserve`等)を変える場合は、モバイル側もこのentryの対応関係を保ったまま同じ秒数に合わせることが望ましい。

## Research Context
「ふ、と」の探究は工程ではなく、現れては留まり、また現れるという呼吸のようなリズムで進む。デスクトップとモバイルで見せ方(3人同時か、1人が入れ替わるか)は異なっても、「しばらく留まってから、一度だけ間を置いて最初に戻る」という時間の流れそのものを両方の画面幅で揃えたことは、どちらの画面で見てもHeroが同じ呼吸をしているという一貫性を保つための変更である。

## 検証・未検証事項
- `npx astro check` / `npm run build`: エラーなし。
- Playwright(Chromium、390px幅)でWeb Animations APIのcurrentTimeを操作し、0〜11秒を0.5秒刻みでサンプリング: 観察する(0.5〜3.5秒)→クロスフェード→学ぶ(4〜6.5秒)→クロスフェード→試す(7.5〜9.5秒)→10〜11秒は人物・ラベルとも不透明度0(空白)、という設計どおりの推移を確認。通常時は常にラベルが1語以下(遷移中の一瞬だけ2語)であることを確認。
- デスクトップ(1440px幅)で0/1/2.5/4/6/8.7/9.5/11秒の不透明度をサンプリングし、Decision Log 0197時点と同じ推移(観察する→学ぶ→試すの順にフェードイン→3人保持→同時フェードアウト→空白)のままであることを確認(今回デスクトップ側のCSSは変更していない)。
- `prefers-reduced-motion: reduce`で人物が「学ぶ」の姿勢に静止し、「観察する　学ぶ　試す」が静かな1行で表示されることをスクリーンショットで確認。
- JavaScript無効(`scripting: none`)でも同様の静止表示になることをスクリーンショットで確認。
