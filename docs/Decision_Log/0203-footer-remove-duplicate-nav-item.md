# 0203 — Footerから「実験室」を削除し、お問い合わせ/個人情報の取り扱いの2項目に

## Decision
プロジェクトオーナーから「ヘッダーとフッターのナビゲーションはなぜ違うのか」という質問を受けた。HeaderとFooterで項目が異なるのは意図的な役割分担(Decision Log 0111: Headerは「サイト内を移動するナビゲーション」、Footerは「支援する/問い合わせるというクロージングのCTA」)だったが、実際に見比べると分かりにくいという判断になり、Footerの構成を見直す指示を受けた。

`src/components/Footer.astro`のFooterナビゲーションから「実験室」(Headerのサイト内ナビゲーションと重複する項目)を削除し、「お問い合わせ」「個人情報の取り扱い」の2項目にした。サイト名(公開研究室ふ、と)・コピーライト表示は変更していない。

## 採用理由 (Rationale)
- Footerに残す2項目(お問い合わせ・個人情報の取り扱い)は、いずれもHeaderのサイト内ナビゲーション(研究断面/実験室/本棚/この場所について)には含まれておらず、重複がない。「実験室」だけがHeaderと重複していたため、これを削除すれば「Footerはページ内を移動するための項目ではなく、問い合わせ・法的情報のためのクロージング領域」という役割がより明確になる。
- Header/Footerの役割分担という設計方針自体(Decision Log 0111)は維持しつつ、実際に見て紛らわしい重複だけを取り除く、最小限の修正にした。

## 他の案 (Alternatives)
- FooterをHeaderと完全に同じ4項目に揃え直す案(Decision Log 0067の方針に戻す)も考えられたが、プロジェクトオーナーの直近の指示は「実験室を削除して問い合わせと個人情報の取り扱いのみに」という具体的な内容だったため、それに従った。
- Footer自体を廃止する案は、コピーライト表示や個人情報の取り扱いへの導線が失われるため採らなかった。

## 将来の変更可能性 (Future changes)
- Footerに項目を追加・削除する場合は`Footer.astro`内の`<nav>`を編集するだけでよい。Headerとの重複が生じないよう、追加時はHeaderのナビゲーション項目(研究断面/実験室/本棚/この場所について)と見比べる。

## Research Context
ヘッダーとフッターという2つのナビゲーション領域が異なる理由が読者に伝わらなければ、「役割分担」という設計意図はただの不整合に見えてしまう。重複していた「実験室」を取り除いたことで、Footerは「サイトを読み終えた後に取れる行動(問い合わせる/個人情報の取り扱いを確認する)」という一貫した役割だけを持つ領域になった。
