# 0081. メルマガは、β公開後に着手する

- 日付: 2026-09-04
- 状態: 採用中

## Decision

プロジェクトオーナーから「メルマガはベータ版ではやらないことになって
いたけど開発コスト高いの?」という質問を受けた。実装コスト自体は
高くない(購読フォーム+外部配信サービスへの連携で、Contactフォーム
[Decision Log 0076]と同程度)ことを説明したうえで、それでも
「新機能追加」にあたる以上はCLAUDE.mdの「ベータ公開前は新機能を
追加しない」ルールの対象であること、また実装よりも「配信を継続する」
という運用コストの方が本質的に重いことを共有した。プロジェクト
オーナーはこれに同意し、β公開後に着手する方針を確認した。実装は
行っていない。CLAUDE.md・PROJECT.mdのParking Lotリストに項目を
追加した。

## 採用理由

- メルマガのようなご支援（寄付）ページ(Decision Log 0075)と同様、
  「実装コストの低さ」だけでParking Lotルールの例外にしてしまうと、
  「軽ければ例外」という前例ができ、ルールが形骸化する。実装コストの
  多寡にかかわらず、新機能はβ公開後にまとめて着手する方が一貫性が
  保てる。
- メルマガは購読フォームの実装で完結せず、「配信を始めたら止めにくい」
  という継続的な運用コミットメントを伴う。β公開前の慌ただしい時期に
  始めるより、公開後に配信頻度・使用サービスをじっくり検討してから
  始める方が、無理なく続けられる。

## 他の案

- 購読フォームだけ先に実装し、配信自体はβ公開後に始める案も考えられた
  が、「フォームだけあって配信がない」状態は訪問者に対して中途半端な
  印象を与えるため、フォームと配信開始をセットでβ公開後に着手する
  方針にした。

## 将来の変更可能性

- β公開後、他のParking Lot項目と合わせて優先順位をつけて着手する際に、
  配信サービス(Buttondown・Substack・Resend Audiences等)と配信頻度を
  プロジェクトオーナーと改めて決める。

## Research Context

「開発コストは高いのか」という問いへの答えが「低い」であっても、
着手しない判断ができるのは、この研究室が技術的な実現性だけでなく
「始めた後どう続けていくか」まで含めて機能追加を検討しているから
である。実装のしやすさに引きずられて機能を増やさない、という姿勢は、
「完成度よりも育てられることを優先する」という方針を、機能を足す
場面だけでなく足さない場面でも一貫させている例と言える。
