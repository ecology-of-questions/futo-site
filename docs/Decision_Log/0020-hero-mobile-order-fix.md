# 0020. Heroのモバイル表示順バグを修正する(ビジュアルがコピーより先に出ていた)

- 日付: 2026-08-10
- 状態: 一部上書き済み(→ 0023)。`order`を使わずDOM順(コピー→
  ビジュアル)に依存する、という本Decisionの結論自体は現在も有効。
  ただし前提としていた「Mobileでは縦積み」というレイアウトは
  0023でビジュアルを背景の透かしとして重ねる形に変更されたため、
  その部分は0023を参照。

## Decision

`Hero.module.css` の `.copy`/`.visual` に設定されていた `order`
プロパティの値が、モバイル幅(縦積みレイアウト)で意図と逆になって
いたバグを修正した。

修正前は `.copy { order: 1 }` / `.visual { order: 0 }`(モバイル既定)
となっており、`.hero` のコメント・`Hero.astro` のコメントがどちらも
「Mobileでは コピー → ビジュアル の順」と明記しているにもかかわらず、
実際にはビジュアル(画像)がコピー(見出し・本文・CTA)より先に表示
されていた。`order` の値を削除し、DOM順(`.copy` → `.visual`)を
そのまま使う形にした。DOM順は元々コピーが先・ビジュアルが後なので、
`order` を指定しなければモバイル(1カラム)・デスクトップ(2カラム)
双方で狙った並びになる。

あわせて、`.visual` の `aspect-ratio: 3 / 2` (Decision Log 0018で
デスクトップ幅にのみ設定されていた)をモバイル幅にも適用した。

## 採用理由

- `order` の値がコメントの意図と逆転していたのは、デスクトップ用に
  カラムを入れ替える実装(Decision Log 0018)を追加した際に、モバイル側
  の値を混同して書いてしまったための実装ミスだと判断した。DOM順が
  元々「コピー→ビジュアル」であるにもかかわらず、モバイル側で
  `order` を明示的に指定していたこと自体が不要な複雑さであり、
  `order` を完全に削除する方が「バグを直す」と「実装をシンプルにする」
  を同時に満たせると判断した。
- `aspect-ratio: 3/2` をモバイルにも広げたのは、今回の依頼「画像が
  極端に縦長・横長にならないか確認する」に対する具体的な担保のため。
  修正前もモバイルでは(パーセンテージ指定の高さが不定な場合に
  `<img>` の実高さが自動的にintrinsicな比率にフォールバックする、
  という挙動により)結果的に大きく崩れてはいなかったが、それは
  ブラウザの暗黙的なフォールバック挙動に依存した状態だった。
  Decision Log 0018で明示的に定めた3:2という比率を、モバイル幅でも
  CSSとして明示することで、挙動をブラウザ実装に委ねず確実にした。

## 他の案

- **`.copy`/`.visual`の`order`をモバイル側だけ入れ替えて維持する案**:
  値を`0`/`1`から`1`/`0`に単純に反転させれば直せるが、DOM順と
  一致させるだけなら`order`自体が不要になるため、削除してシンプルに
  する方を採用した。

## 将来の変更可能性

- 将来Hero内のDOM順(コピーとビジュアルの記述順)を変更する場合は、
  `order`に頼らず表示順が決まる前提が崩れるため、その際は改めて
  `order`の指定が必要になる。

## Research Context

「Mobile確認」という今回の依頼そのものが、実機(相当のヘッドレス
ブラウザ)で確認しない限り見つからない類のずれだった。コメントに
書かれた設計意図とCSSの実装が一致しているかどうかは、コードを
読むだけでは気づきにくく、実際に動かして確認する過程で初めて見える。
「観察から始める」(Design Spec 8)というこの研究室の姿勢は、コピーや
リサーチの姿勢だけでなく、実装そのものの検証プロセスにも同じように
当てはまる。
