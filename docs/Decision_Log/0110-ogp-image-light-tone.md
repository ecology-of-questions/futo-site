# 0110. OGP画像をライトトーンの配色に作り直す

- 日付: 2026-09-10
- 状態: 採用

## Decision

プロジェクトオーナーから、「urlシェアした時の画像背景が青のままになって
しまってる」との報告を受けた。

### 原因

`public/images/ogp/default.png`(OGP・Twitter Card用の共有プレビュー
画像、1200×630)は、2026-09-04にHero見出しフォント導入と同時に作成
された静的なPNGファイル(Decision Log 0082)で、当時のサイト配色
(濃紺の「夜空」背景+白文字+光の粒)をそのまま画像として焼き込んで
いた。2026-09-10のサイト全体配色変更(Decision Log 0104、背景を
`--color-paper`の白に近いトーンへ)はCSS側のみの変更であり、この
静的画像を自動的に更新する仕組みはなかったため、ライブサイトの配色を
変更した後もURLシェア時のプレビュー画像だけ旧配色(濃紺)のまま
残っていた。ロゴ・見出し・タグラインの内容自体は変更していない。

### 対応

- 新しい`default.png`を作成し直した。背景を`--color-paper`
  (`#fafaf7`)、見出し・ロゴを`--color-ink`(`#303432`)、タグラインを
  `--color-ink-muted`(`#606663`)にし、現在のサイト本体と同じ配色
  トークンの値を使用した。
- 光の粒(旧デザインの「夜空」演出)は、ライブサイト側でも撤去済み
  (Decision Log 0106)のため、画像側にも含めていない。
- ロゴは`public/images/logo/logo.svg`(標準のダークカラー版)を
  そのまま使用した。旧画像は濃紺背景用に白反転させたロゴを使って
  いたが、白背景では反転の必要がない。
- 見出しフォント(Klee One、Decision Log 0082)・レイアウト構成
  (ロゴ左上・見出し・タグラインの縦並び)は変更していない。見出し
  文言も、Research Statementの見出し句点削除(Decision Log 0108)に
  合わせて「気づいたら、そこに問いがある」(句点なし)にした。
- 画像はPlaywrightで1200×630の2倍解像度(2400×1260)でHTML/CSSを
  レンダリングし、Lanczosで1200×630にダウンサンプルして書き出した
  (テキストのアンチエイリアシング品質を確保するため)。
- `DefaultLayout.astro`の`og:image`参照に`?v=2`を追加した。
  X(Twitter)・Facebook・LINE・Slack等はOGP画像をURL単位で
  キャッシュするため、ファイル名(URL)を変えずに中身だけ差し替えても
  プラットフォーム側のキャッシュには古い画像が残り続ける
  (favicon修正時と同じ問題、Decision Log 0107)。

## 採用理由

- 静的画像が配色変更に追従していなかったことが直接の原因であり、
  画像をサイト本体の現在のトークン値で作り直すことで解決した。新しい
  HEX値を決め打ちせず、`tokens.css`に既にある値をそのまま使っている。
- 光の粒を含めなかったのは、その演出自体がライブサイトから撤去済み
  (Decision Log 0106)であり、OGP画像だけに残すと「今のサイトの
  雰囲気」と「共有時のプレビュー」がずれてしまうため。

## 他の案

- 画像生成を毎回手動で行うのではなく、ビルド時に自動生成する仕組み
  (例: Satori等でCSSトークンから直接OGP画像を生成)も考えられるが、
  現状1枚の共通画像を手動更新する運用で十分頻度が低く、今回はその
  ための新しい依存関係を追加しない方針とした。将来ページごとに専用
  画像を用意する話(Decision Log 0082の将来課題)が具体化した際に
  改めて検討する。

## 将来の変更可能性

- サイトの配色トークンが再度変わった場合は、この画像も合わせて
  作り直す必要がある(自動追従しない静的アセットである点は今回も
  変わっていない)。
- ページごとに専用OGP画像を用意したくなった場合は、`DefaultLayout`
  に`ogImage` propを追加すれば個別ページで上書きできる(Decision Log
  0082時点で構造だけ用意されている、未実装)。

## Research Context

URLシェア時のプレビューは、多くの訪問者が実際のページを開く前に
最初に目にする「顔」である。ライブサイトの配色を変えても、この
「顔」だけ古いままでは、公開研究室の現在の姿勢(静かな白いトーン)が
正しく伝わらない。コンテナ(配色)の変更をコンテンツ(共有プレビュー
画像)にも一貫して反映したという点で、Decision Log 0104〜0106の
一連の配色変更の仕上げにあたる。
