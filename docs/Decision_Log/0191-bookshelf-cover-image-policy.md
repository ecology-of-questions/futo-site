# 0191 — 書影(表紙画像)の利用ルールを明文化(コード変更なし)

## Decision
指示書「Fieldnote読書記録と公開本棚の統合 v3」7節(書影・著作権)を踏まえ、プロジェクトオーナーから「書影は無理に復活させなくてよい。現状が文字表示なら維持してください。実表紙を追加する場合にだけ、利用根拠を確認し、不明なら独自の文字装丁にするルールを適用してください。大きな『著作権ポリシーエンジン』は不要です」という指示を受けた。

現状(`/bookshelf`はタイトル・著者のみのテキスト行リスト、Decision Log 0179)を変更する理由は無いため、**コードの変更は行わない**。今後、実際に書影(表紙画像)を表示に使う判断をする場合に備えて、以下の簡潔なルールをここに記録するのみとする。

## ルール(将来、書影を追加する場合に適用する)

1. **実際の表紙画像を使う場合は、必ず先に利用根拠を確認する。** 出版社の公式素材提供・許諾、あるいは書影APIの利用規約(例: Open Library Covers API等)を確認し、根拠を本コミット(または該当Decision Log)に明記してから使う。「たぶん大丈夫だろう」で使わない。
2. **利用根拠が確認できない・不明な場合は、実物の表紙を模した見た目(色面・縦書きタイトル等、実際の装丁を連想させる表現)を作らない。** 代わりに、タイトル・著者のみのテキスト表示(現状)か、実装するとしても「独自の文字装丁」(例: サイト共通のtokens.cssの配色・書体だけを使い、本のタイトル文字をそのまま主役にする、実在の表紙デザインを模倣しない抽象的なカード)に留める。
3. **本棚以外(Home・体験デモ・OGP画像等)でも同じルールを適用する。** 書影・書影に類する表現をどこか一箇所にだけ厳しく、他は緩く、ということはしない。
4. **大掛かりな「著作権ポリシーエンジン」(自動判定・自動フォールバック機構等)は作らない。** 判断は都度人が行い、根拠をコミット・Decision Logに残す、という今までどおりの手動運用で十分と判断した。

## 採用理由 (Rationale)
- 現状のテキストのみの表示(Decision Log 0179)は、プロジェクトオーナー自身の「表紙は見にくいかもしれない」という懸念から生まれた判断であり、覆す理由が無い。
- 過去の経緯(Decision Log 0167〜0170で書影グリッドを試し、0179で差し戻した)を踏まえると、「書影を使うかどうか」自体がこのスタジオにとって繰り返し検討されてきた論点であり、次に書影を検討する際に同じ検討(利用根拠の確認)を都度やり直さずに済むよう、判断基準だけを先に記録しておく方が合理的。
- 自動化されたポリシー判定の仕組み(画像のライセンス自動検出等)は技術的に過剰で、実際には人が出版社のサイト・利用規約を読んで判断するしかない性質の問題のため、仕組み化しない。

## 他の案 (Alternatives)
- 今回、独自の文字装丁パターンを実際にコンポーネントとして先に作っておく案も検討したが、「使う予定が無いものを先に作らない」というCLAUDE.mdの基本方針に反するため、ルールの記録に留めた。

## 将来の変更可能性 (Future changes)
- 実際に書影を追加する具体的な提案が出た場合、このルールに従って利用根拠を確認したうえで、新しいDecision Logエントリを起票すること(この0191をsupersededにするか、実装の詳細を追記するかは、その時の状況に応じて判断する)。

## Research Context
このルールは、実装コードではなく「今後の判断のための最小限の指針」だけを記録するものである。研究の道具は完成させないが、判断の一貫性は保つ——という、公開研究室としてのこのスタジオの姿勢に沿っている。
