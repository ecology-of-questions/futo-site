# 0076. Contactページをnote経由からフォーム(Formspree経由でメール転送)に変更する

- 日付: 2026-09-03
- 状態: 採用中

## Decision

プロジェクトオーナーから「Contactページをnoteへの問い合わせから、
裏側で個人のGmailに送られる問い合わせフォームにできないか」という
相談を受け、以下の構成で実装した。

- Contactページに入力フォーム(お名前・ご返信先メールアドレス・
  お問い合わせ内容)を新設し、note経由の導線を置き換えた。
- フォームの送信先は外部フォームバックエンドサービス
  **Formspree**(`https://formspree.io/f/{Form ID}`)への直接POST。
  サーバーサイドのコードは書いていない。
- 送信先メールアドレスは、プロジェクトオーナーの希望により
  **サイト専用に新規作成するGmailアドレス**(個人のGmailとは別)。
  Formspree側でそのGmailアドレスを使ってアカウントを作成し、
  フォームを紐づける。
- `src/config/site.ts`の`formspreeFormId`は現時点でプレースホルダー
  (`"YOUR_FORM_ID"`)。プロジェクトオーナーがFormspreeでアカウント・
  フォームを作成した後、実際のForm IDに差し替える必要がある。
- スパム対策として、Formspreeの規約に沿ったハニーポット欄
  (`name="_gotcha"`、視覚的にのみ非表示)を追加した。
- JS未対応環境でも動作する通常の`<form method="POST" action="...">`
  を土台にし、JSが動く環境では`fetch`でAjax送信してページ遷移せずに
  結果を表示する(進行拡張)。

## 採用理由

- CLAUDE.mdの「デプロイ先はCloudflare Pagesだが、ビルドはポータブルな
  静的サイトを保つ(Cloudflare固有のアダプタ・機能を使わない)」という
  制約があるため、Cloudflare Pages Functionsのようなデプロイ先固有の
  サーバーサイド機能は選ばなかった。Formspreeのような外部フォーム
  バックエンドサービスへ`<form>`を直接POSTする方式であれば、サイト
  自体は静的なままで(`npm run build`の出力はHTML/CSS/JSのみ)、
  裏側のメール転送だけを外部サービスに委ねられる。
- Formspreeは無料枠があり(月50件まで)、ダッシュボードで送信履歴の
  確認・スパムフィルタリングができるため、プロジェクトオーナーが
  希望した「管理しやすく、無料」という条件に合う。
- サイト専用のGmailアドレスを新規作成する方針は、個人のプライベートな
  メールと、公開研究室宛ての問い合わせ(取材依頼・寄稿相談等、今後
  増えうる)を分離できる。プロジェクトオーナー自身の希望でもある。

## 他の案

- Web3Forms: アカウント登録なしでアクセスキーのみで使える点は
  手軽だが、Formspreeよりダッシュボード機能(送信履歴の確認等)が
  簡素なため、「管理しやすさ」を優先してFormspreeを選んだ。
- Cloudflare Pages Functions: デプロイ先がCloudflareであることを
  生かせば実装は可能だが、CLAUDE.mdの「ポータブルな静的サイトを保つ」
  という明示的な方針に反するため見送った。
- noteの問い合わせ機能を維持する案: 既存の仕組みをそのまま使えるが、
  プロジェクトオーナーの要望(「裏側で個人のGmailに送られる仕組み」)
  に応えられないため、今回は置き換えた。

## 将来の変更可能性

- `formspreeFormId`がプレースホルダーのままだと、実際の送信は
  失敗する(フォーム自体は表示され、バリデーションも機能するが、
  送信ボタンを押すとエラーメッセージが出る)。プロジェクトオーナーが
  Formspreeでアカウント・フォームを作成し、実際のForm IDを
  `src/config/site.ts`に反映してから本番公開する必要がある。
  → 2026-09-04、プロジェクトオーナーがサイト専用Gmail
  (`futoing@gmail.com`)でFormspreeアカウントを作成し、実際の
  Form ID(`mvkoqzov`)を発行。`src/config/site.ts`の
  `formspreeFormId`をプレースホルダーから実値に差し替えた。この
  作業を行ったサンドボックス環境からはネットワークポリシーにより
  `formspree.io`への疎通確認ができなかったため、実際の送信動作は
  プロジェクトオーナー側での実機確認を依頼した。
  → 同日、プロジェクトオーナーが実際にContactフォームから送信し、
  HTTPステータス200での成功と、`futoing@gmail.com`への着信を確認。
  Contactフォームは本番で問題なく機能している。
- Formspreeの無料枠(月50件)を超える、あるいはFormspree自体を
  変更したくなった場合は、`src/config/site.ts`の`contactFormEndpoint`
  を差し替えるだけで他サービスに移行できる(フォーム自体のマークアップ
  は変更不要)。

## Research Context

「公開研究室」が外部との接点を持つ窓口のひとつであるContactページを、
プラットフォーム(note)依存から、サイト自身が持つ入力フォームに
変更したことは、研究室としての独立性を少しずつ高めていく過程の一部
でもある。裏側の送信先を個人のメールから研究室専用のメールへ分離した
ことも、「暮らしと研究の一体性」を保ちながら、研究室という人格を
少しずつ輪郭づけていく判断のひとつと言える。
