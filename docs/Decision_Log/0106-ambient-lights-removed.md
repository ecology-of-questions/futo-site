# 0106. カーソル追従の光・ふと現れる光の演出を撤去する

- 日付: 2026-09-10
- 状態: 採用

## Decision

Decision Log 0105で、ライトトーン化(Decision Log 0104)により見えなく
なった2つの光の演出(`NightBackground`の光の粒、`CursorGlow`の
カーソル追従の光)を、色相の差で見せる方式(`--color-accent-blue`を
`color-mix()`で薄く溶かした色、配合30%/25%)に作り直した。

その後、プロジェクトオーナーから「白背景に白の光だと点滅してるように
感じる」との指摘を受けた。原因は配合が薄くコントラストが低すぎたこと
(`--color-paper`との比較で約1.6:1)で、opacityが低い間はほぼ知覚
できず、ピーク付近で急に見える強さになるため、「じわじわ」ではなく
点滅のように見えていた。配合を50%/40%(コントラスト比 約2.2:1)に
引き上げて確認したところ、低いopacityの段階から滑らかに見えるよう
になることをPlaywrightで複数のopacity値を固定して確認した(この
配合調整はブランチ上で検証・実装したのみで、コミット・マージ済みの
Decision Logとしては残していない)。

その調整後の見た目を見たプロジェクトオーナーから「これだったら光
なくていいや」との指示を受け、光の演出自体を撤去することにした。
背景色(温かみのある白、`--color-paper`)と、Research Statementエリア
の背景グラデーション(`--color-night-gradient-*`)はそのまま残す。

### 対応

- `NightBackground.astro` / `NightBackground.module.css`: `.lights`・
  `.light`要素、`lightPulse`アニメーションを削除。`.background`
  (単色背景)・`.gradient`(Research Statement用グラデーション)は
  変更していない。DOM構造がシンプルになった以外、他の呼び出し元
  (Home・/research・/about・/contact・研究断面詳細ページ)の見た目・
  構造への影響はない。
- `CursorGlow.astro` / `CursorGlow.module.css`: ファイルごと削除した。
  カーソル追従の光を描画する以外に役割を持たないコンポーネントであり、
  削除後は完全に不要になるため(CLAUDE.md「確実に未使用と分かる
  ものは完全に削除してよい」という方針に従った)。
- 上記削除に伴い、`<CursorGlow />`を配置していた7ページ
  (404・about・contact・index・research・research/reviews/01・
  research/reviews/1-5)から、importと呼び出しを削除した。

## 採用理由

- Decision Log 0105以降、配合比率を2度(30%/25%→50%/40%)調整しても、
  プロジェクトオーナーの実際の見た目の評価では「光がない方がよい」
  という結論に至った。これ以上の微調整を重ねるより、演出自体をやめる
  方がシンプルで、CLAUDE.mdの「静かなトーンを保つ」という一貫した
  方針にも合う。
- `CursorGlow`は元々「カーソル追従の光を描画する」という単一目的の
  コンポーネントであり、その効果自体をやめる以上、コンポーネントを
  空のまま残す理由がない。呼び出し元を残したまま中身だけ空にする
  (何もレンダリングしない)という対応は、未使用のimportやコンポーネ
  ント呼び出しが7ページに残り続けることになり、後から読むときに
  「なぜ呼んでいるのに何も起きないのか」という混乱を招くため避けた。
- `NightBackground`は光の粒を除いても「ページ全体の背景色を描画する」
  という役割が残っているため、コンポーネント自体は削除せず、内部の
  光の粒に関する実装だけを取り除いた。

## 他の案

- `CursorGlow`のように、`NightBackground`の光の粒部分だけを別
  コンポーネントに切り出した上でファイルごと削除する案も考えられたが、
  `.background`/`.gradient`と同じファイル内で密結合していた実装を
  今回のためだけに再分割するのは過剰な変更だと判断し、同じファイル内
  で該当部分を削除するに留めた。
- `CursorGlow.astro`を削除せず、中身を空にして残す案も検討したが、
  上記の「呼び出し元の混乱」を避けるため、ファイルごと削除し呼び出し元
  も整理する方を選んだ。

## 将来の変更可能性

- 将来的に光の演出を別の形(色・強度・トリガーが異なるもの)で
  再検討したくなった場合は、Decision Log 0059・0078・0105の実装内容
  (color-mix()による色相ベースの光表現、コントラスト確保の考え方)が
  参考になる。`CursorGlow`はgit履歴から復元可能。

## Research Context

「静かなトーンを保つ」という方針は、装飾を足すことよりも、実際に
確かめた上で「これは要らない」と判断できることの方が、この研究室の
姿勢(観察し、試し、必要であれば手放す)に近い。今回の一連の
やり取り(光を戻す→点滅を直す→やっぱり要らない)自体も、Decision
Logとして積み重なることで、「なぜ今この形なのか」を後から追える
記録になっている。
