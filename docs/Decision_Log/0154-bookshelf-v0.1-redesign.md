## Decision

プロジェクトオーナーから、v0.1公開仕様書(`claude_code_bookshelf_v0.1.md`)
に基づき、`/bookshelf`を「本のカード一覧」から「いまの探究のそばに
実際に置かれている本が見える場所」へ再設計する指示を受けた。PR #84
(研究断面)は既にmerge済みだったため、最新mainから新しいブランチ
(`claude/bookshelf-v0.1`)を作り、新規PRとして進めた。本棚以外の
ページは変更していない。

### 実装前の調査結果

- **`/bookshelf`のcomponent構成**: `bookshelf.astro`(ページ) +
  `BookshelfFullList.astro`(全冊リスト、フィルター5ボタン+status混在の
  1列リスト) + `BookshelfFullList.module.css`。データは
  `src/data/bookshelf.ts`の`books`配列(`src/types/bookshelf.ts`の
  `BookEntry`)。
- **実データ**: 6冊。`reading`(いま読んでいる)3冊(経験と教育/
  調査的感性術/想像の共同体、全冊`owned: true`)、`wishlist`
  (読みたい)3冊(マツタケ/生きていること/現代日本語における意図性
  副詞の意味研究、全冊`owned: false`・`giftEnabled: true`・`reason`
  あり)。`queued`(これから読む)・`finished`(読了)・`gifted`
  (贈っていただいた)は0冊。`contributed: true`(持ち寄られた本)の
  本も現時点で0冊。
- **画像/表紙asset**: `public/images/`配下に本の表紙・背表紙画像は
  一切存在しない(`logo`/`research`/`hero`/`ogp`のみ)。6冊すべて
  `image`/`externalCoverUrl`フィールドも未設定で、既存実装は全冊
  「仮カバー」(`tone`によるcolor-mixの色面、旧`BookshelfFullList.
  module.css`)で表示していた。
- **「本を持ち寄る」導線**: `bookshelf.astro`内に既存のFormspree
  フォーム(タイトル/著者/きっかけ/お名前/メールアドレス、
  `contactFormEndpoint`、honeypot)。加えて、本ごとに「一緒に読みたい」
  という展開式フォーム(同じくFormspree、`book_id`/`book_title`を
  hidden fieldで送信)が全冊に常設されていた。

### 実装した変更

- **「いま読んでいる」をHero区画に**: `status: "reading"`の本を、
  ページ上部に最も大きく見せる区画にした。仮カバー(tone)を横に並べ、
  その下に各本のタイトル・著者・「一緒に読みたい」を添える。
  カードグリッドにはしていない(枠線・影・背景色ボックスは使わず、
  色面の書影のみ)。
- **status別セクション**: `queued`/`wishlist`/`finished`/`gifted`の
  うち、実データが1冊以上あるものだけをセクションとして表示する
  (`bookStatusLabels`をそのまま見出しに使う)。今回のデータでは
  `wishlist`(読みたい)のみが該当し、他の3つは自動的に非表示になる
  ことを確認した。新しいカテゴリ(おすすめ・人気等)は追加していない。
- **フィルターボタンの削除**: 旧「すべて/読書中/これから読む/読みたい/
  読了」の5ボタン(vanilla JSでの表示切替)を削除した。本が6冊のみで、
  既にstatus別セクションに分かれているため、フィルターが無くても
  一覧性を損なわないと判断した。
- **本ごとのアクションの分離**: 「購入リンク・この本から生まれた記録・
  一緒に読みたい」を`BookActions.astro`に切り出し、Hero・
  セクション行の両方から同じロジックで呼び出せるようにした
  (ロジック自体は旧実装から変更していない)。
- **「本を持ち寄る」を静かな導線に**: 見出し+説明文+常時展開のフォーム
  だった構成を、指示された文言候補(「この本も、と思い出したものが
  ありますか。」+「本を持ち寄る →」)による1行の呼びかけ+トグル
  ボタンに変更した。クリックで展開するフォーム自体(フィールド構成・
  Formspreeエンドポイント・honeypot・`_subject`)は一切変更していない。
- **導入文(BOOKSHELF/研究の本棚/冒頭2文)**: 既存のコピーをそのまま
  維持した。新しい長いコンセプト文は追加していない。

### コンポーネントの再編成

旧`BookshelfFullList.astro`/`.module.css`は削除し、以下に置き換えた。

- `BookshelfShelf.astro`/`.module.css`(新規): ページ本体のHero+
  status別セクションの描画。
- `BookActions.astro`/`.module.css`(新規): 本1冊ぶんのアクション
  (購入リンク・関連記録・一緒に読みたいの展開フォーム)。Hero・
  セクション行の両方から呼び出す。

ファイル名を変更したのは、「フィルター付きの1列全リスト」という旧
実装の役割(`FullList`)と、新しい「Hero+status別セクションの棚」と
いう役割が実質的に別物になったため、今後の読み手が名前から役割を
誤解しないようにする判断による。

## 採用理由

指示を字面通りに実装した。特に「実際の背表紙写真がrepositoryに
存在しない場合は、勝手に生成画像や架空の背表紙を作らない」という
制約に対し、既存の仮カバー(tone、color-mix)をそのまま使い、
新しい画像アセットは一切追加していない。「持ち寄る」フォームを
静かな導線にする際も、新しいフォーム基盤は作らず、既存のFormspree
エンドポイント・フィールド構成をそのまま再利用した(指示の「既存設定を
ハードコードで複製しない」に対応)。

`BookActions`への切り出しは、「本棚だけ他ページより少し物質感が
あってよいが、装飾的にしすぎない」という指示を、Hero区画(大きな
書影)とセクション行(小さな書影)という2つの見た目で表現しつつ、
本ごとのアクション(挙動)を1箇所のロジックに保つための構造判断。
将来実写の背表紙画像に差し替える際も、`BookshelfShelf.astro`側の
`book.image`優先順位はそのままに、`bookshelf.ts`にURLを追加するだけで
反映される。

## 他の案

- **「本からひらく問い」セクションを実装する**: `wishlist`の3冊には
  `reason`(なぜこの本が気になっているか)フィールドが実際に存在する
  ため、これを「本からひらく問い」として転用する案も検討した。しかし
  `reason`は「まだ読んでいない本を、なぜ読みたいと思ったか」という
  動機であり、v0.1仕様が例示する「本からひらく問い」(本と探究の
  実際の関係・本から生まれた問い、`『経験と教育』/経験は、いつ探究へ
  変わるのだろう。`)とは性質が異なる(後者は本を読んだ・関わった
  ことから生まれた問いを想定していると解釈した)。指示にある「該当
  データがなければ実装しなくてよい」「UIのためだけに架空コピーを
  作らない」に従い、今回はこのセクション自体を実装しなかった。かわりに
  `reason`は、`wishlist`セクションの各行に(既存の見た目のまま)引き続き
  表示している。
- **「持ち寄られた本」を独立セクションにする**: `book.contributed`は
  status非依存のフラグのため、専用セクションを新設する案も検討したが、
  現時点で`contributed: true`の本が0冊であり、実装しても常に非表示に
  なる。「空のカテゴリは表示しない」「架空データのためだけに複雑さを
  増やさない」という判断から、今回は専用セクションを作らず、各行の
  タイトル脇に「・持ち寄られた本」と添えるラベル(旧実装から踏襲)の
  みとした。実際に持ち寄られた本が掲載された時点で、必要なら独立
  セクション化を再検討する。
- **Heroの書影を横スクロールではなく縦積みにする**: 3冊のみのため
  縦積みでも成立するが、v0.1仕様のASCIIモックアップが「実際の本の
  背表紙が横に並ぶ」という横方向の配置を明示しており、「棚」という
  比喩にも横並びの方が近いと判断し、横スクロール(`overflow-x: auto`、
  carousel UIやpagination dotは使わない素のネイティブスクロール)を
  採用した。本数が少ない現状では実際にはスクロールせずに収まる
  (Desktop)か、3冊目が少しだけ画面端にはみ出す(Mobile 390px)ことで、
  却って「スワイプできる」ことが自然に伝わる見た目になっている
  (Playwrightで`document.body.scrollWidth`を確認し、ページ全体が
  横方向にはみ出していないことを確認済み。はみ出しているのは
  `.heroShelf`要素の内部のみ)。

## 確認結果

- mobile(390px)/desktop(1440px)を実装後にスクリーンショットで確認した。
  - 本がカード一覧ではなく「いま読んでいる」Hero+status別セクションの
    「棚」として感じられる。
  - 「いま読んでいる」がページ最上部・最大サイズの区画として主役に
    なっている。
  - 研究断面ページ(文字中心)とは異なり、色面の書影が並ぶことで
    物質感がある。
  - 架空の本・架空の背表紙画像・架空の「問い」は混ざっていない。
  - `queued`/`finished`/`gifted`/`contributed`の空カテゴリは表示されて
    いない。
  - 「本を持ち寄る」は1行の呼びかけ+トグルボタンのみで、大きなCTAに
    なっていない。
  - Header/Footer/配色/タイポグラフィがTop・About・研究断面と共通で、
    同じサイトに見える。
  - `document.body.scrollWidth`をPlaywrightで検証し、mobile(390px)で
    ページ全体が横方向にはみ出していないことを確認した(`.heroShelf`
    要素自身の内部スクロールのみ)。
  - 「一緒に読みたい」(Hero・セクション行それぞれ)・「本を持ち寄る」の
    両トグルを実際にクリックし、フォームが正しく展開することを確認
    した(`BookActions`への切り出し後も機能が壊れていないことの確認)。
- `npx astro check`: 0 errors, 0 warnings, 1 hint(既存の無関係なhint)
- `npm run build`: 15ページ生成、エラーなし

## 将来の変更可能性

- 実際の背表紙・表紙写真を用意できた際は、`bookshelf.ts`の該当する本に
  `image`(自前で撮影・用意した画像パス)または`externalCoverUrl`
  (正規に取得した外部URL)を追加するだけで、Hero・セクション行の
  両方に自動的に反映される(`BookshelfShelf.astro`の表示優先順位
  `image → externalCoverUrl → 仮カバー`は変更していない)。
- 「本からひらく問い」は、実際に読んだ本についての具体的な問いが
  記録された時点(例えば新しいフィールドを`BookEntry`に追加する等)で、
  改めて実装を検討する。
- `queued`/`finished`/`gifted`/`contributed`の本が実際に追加された
  際は、対応するセクションが`BookshelfShelf.astro`の既存ロジックに
  よって自動的に表示される(コンポーネント側の追加実装は不要)。

## Research Context

「本のカード一覧ではなく、いまの探究のそばに実際に置かれている本が
見える場所」という位置づけは、研究断面=紙面・実験室=線と痕跡・
本棚=本そのものという、v0.1仕様が明確化した3領域の「物質」の違いを
体現している。特に、実データに無い関連付け・問い・カテゴリを一切
作らなかったことは、Decision Log 0152・0153で確立した「架空の関連付け
を作らない」「現在実際に存在するものだけを見せる」という原則を、
本棚という領域にも一貫して適用したものであり、CLAUDE.mdの「公開研究
室」という位置づけ(演出ではなく実在する研究・実践の断面をひらく場)を
支えている。
