# 0218. タブ切り替え式に戻し、都道府県+簡易な位置図を追加する

- 日付: 2026-11-13
- 状態: 採用(Decision Log 0217の構成を部分的に変更)

## Decision

Decision Log 0217で「記録する」「記録したものをみる」をアンカーリンク+常時表示の1ページ構成にしたが、プロジェクトオーナーから次のフィードバックを受けた。

1. タブに分けているのに結局1ページになっているのは分かりにくい。
2. ラベルは「記録したものをみる」ではなく「記録を見る」にしたい。
3. 「記録を見る」は日本地図が見られる形にしたい。

確認の上、以下の方針で実装した。

- 構成: 切り替え式のタブ(一方しか表示しない、同じページ内)に戻す。
- 地図: 今回のスコープに含める。都道府県データの収集も合わせて実装する。

### 実装内容

- `src/components/SkyLog.astro`: 「記録する」「記録を見る」の2つを`role="tablist"`のタブに戻した(Decision Log 0216以前と同じ`aria-selected`+`hidden`方式)。「記録する」タブは空の帯+記録フォームのみ、「記録を見る」タブに地図・一覧・ふりかえりをまとめた。
- `src/data/skyLog.ts`: `SkyLogPrefecture`型(47都道府県)・`prefectures`配列・`prefectureCoords`(都道府県庁所在地のおおよその緯度経度)を追加。
- `migrations/0003_sora_log_prefecture.sql`: `sora_log_entries`に`prefecture`列を追加(任意、47都道府県のいずれかであることをCHECK制約で保証)。
- `worker/index.ts`: `prefecture`パラメータの検証・保存・公開レスポンスへの追加。
- `src/components/SkyLog.astro`の記録フォームに都道府県の`<select>`(任意、47都道府県+「選ばない」)を追加。
- 「記録を見る」タブに、都道府県ごとの記録件数を示す簡易な位置図(SVG)を追加。都道府県庁所在地のおおよその緯度経度を単純な等間隔図法(緯度経度を直線的にx/y座標へ変換)でプロットしただけの図で、海岸線・行政境界などの実際の地理的形状は描いていない。件数がある都道府県は丸(大きさ=件数)とラベル、無い都道府県は小さい点のみ表示する。「丸の大きさは件数です。(中略)海岸線や行政境界の実際の形は描いていません」とキャプションで明示した。

## 採用理由

- タブ切り替え式に戻したのは、「記録する」「記録を見る」という明確に異なる2つの操作(入力/閲覧)を、見た目(ボタンの選択状態)と実際の表示が一致する形にするため。Decision Log 0217のアンカーリンク方式は、ボタンの見た目がタブっぽいのに実際はジャンプでしかないという不一致があった。
- 地図を正確な地理データ(海岸線・県境のGeoJSON等)から描画するのではなく、都道府県庁所在地の緯度経度を単純に投影した点だけの図にしたのは、外部の地図データを取得する手段がこのセッションに無く、かつ手描きで正確な日本地図の輪郭を作ると不正確になるリスクが高いため。「位置はおおよそです」という同種の注記は、プロジェクトオーナーが共有した試作(Decision Log 0215で参照したプロトタイプの地図機能)でも使われており、同じ考え方を踏襲した。
- 都道府県を記録項目に追加したことで、Decision Log 0216で「位置情報は取得しません」としていた`/privacy`の記述と齟齬が生じるため、別途`/privacy`の10番ブロックを更新する必要がある(本Decision Logのコミットと合わせて対応)。

## 他の案

- 市区町村単位(プロジェクトオーナーが共有した試作で使われていたShonan地域の市区町村リスト)での収集も検討したが、「日本地図」という指示の範囲(全国)には細かすぎ、特定地域に閉じた選択肢になってしまうため、都道府県単位を採用した。
- 正確な日本地図の輪郭(SVGパス)を用意する案は、信頼できる地理データソースをこのセッションから取得する手段が無く、手描きでは不正確になるため見送った。将来、信頼できる地理データ(例: プロジェクトオーナーが提供するSVG、または許可されたソースからの取得)が得られれば、県境入りの地図に置き換えられる。

## 将来の変更可能性

- 正確な地図データが手に入れば、現在の点だけの位置図を、実際の都道府県境界を描いた地図に置き換えられる(`renderMap()`関数を差し替えるだけで済む構成にしてある)。
- ラベルの重なり(東京都・神奈川県のように近接する都道府県)は、件数が増えて実用上問題になった段階で、ラベルの間引きや吹き出し表示に改善する。
- 都道府県より細かい市区町村単位の収集は、プロジェクトオーナーのプライバシーポリシーの方針が固まった段階で検討する。

## Research Context

地図は、この道具が「個々の記録」から「地域ごとの傾向」を読み取れるようにする、重要な一歩である。同時に、正確でない地図をあたかも正確であるかのように見せないこと(キャプションでの明示)は、このプロジェクトが一貫して重視してきた「実態より完成度を高く見せない」という姿勢の延長である。
