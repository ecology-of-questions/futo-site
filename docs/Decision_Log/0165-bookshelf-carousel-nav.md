- 関連: Decision Log 0161・0163(/participateの1画面圧縮・Hero行

## Decision

Decision Log 0164で、`/bookshelf`の「いま読んでいる」「読みたい」を
mobile・desktopともスクロールなしで見せる工夫として、既存トークン
基準の`calc()`による余白圧縮・著者名のinline統合・font-size調整を
行ったが、mobile(390×844)では「読みたい」3冊目の下端が約201px
画面外にはみ出したままだった(reason文を隠さない範囲での圧縮の限界)。

この報告を受け、プロジェクトオーナーから「それぞれ1冊だけ表示して、
残りは前へ/次へで見る形にしてはどうか」という提案があり、確認の上で
採用が決まった。具体的には以下の2案を提示し、「両方に適用する」
(案1)が選ばれた。

1. Hero・「読みたい」の両方を1冊ずつ+前へ/次へボタンにする。
2. 「読みたい」だけ1冊ずつ+前へ/次へボタンにし、Heroは既存の横
   スクロールのまま維持する。

## 対応

### 表示方式の変更

`src/components/BookshelfShelf.astro`: Hero・status別セクション
(現状「読みたい」のみ実データあり)の両方で、複数冊ある場合は
1冊目だけを表示し(`hidden={i !== 0}`)、`.carouselNav`(前へ/次へ
ボタン+「n / 件数」の状態表示)で切り替える構成にした。1冊しか
無いグループでは、ナビゲーション自体を描画しない
(`{group.rows.length > 1 && (...)}`)。

### 汎用的なカルーセルJS

ページ末尾に`<script>`を追加し、`[data-carousel]`要素を持つブロック
(Hero・各status別セクション)ごとに、独立したindexを持つ最小限の
表示切替ロジックを実装した。

```js
document.querySelectorAll<HTMLElement>("[data-carousel]").forEach((carousel) => {
  const items = Array.from(carousel.querySelectorAll<HTMLElement>("[data-carousel-item]"));
  // ...前へ/次へボタンのクリックでindexを更新し、items[i].hiddenを
  // 付け替える。件数が1件以下のカルーセルは何もしない。
});
```

フレームワーク・アニメーションライブラリは使わず、既存の
「本棚に本を持ち寄る」パネルの開閉(`hidden`属性+vanilla JS)と
同じ実装パターンを踏襲した。カルーセルごとに状態が独立しているため、
Hero側の操作が「読みたい」側に影響しない。

### `[hidden]`が実際に効かない問題への対応

`.heroItem`は`display: flex`を自身のCSSで宣言しているため、
`[hidden]`のUser-Agentスタイル(`display: none`)は、同じ詳細度の
author側宣言に負けて効かないことが分かった(originの優先順位により、
author стиль > UAスタイルとなるため)。`[data-carousel-item][hidden]
{ display: none; }`という、詳細度の高いauthorルールを追加し、確実に
非表示になるようにした。`.row`は元々`display`を宣言していないため
この問題は起きないが、同じセレクタで両方を安全にカバーしている。

### 「読みたい」の行スタイルの単純化

1冊ずつしか表示されなくなったため、`.row`にあった`:first-child`の
padding-top調整・`:last-child`のborder-bottom調整(縦積みリストの
境界線を揃えるための調整)を削除し、`padding: 0`のみにした。また、
`.heroShelf`の`overflow-x: auto`(横スクロール)も、常に1つの
flex子要素しか可視でないため不要になり、コメントで明記のうえ実質的に
無効化した(プロパティ自体は将来の切り戻しを考慮し、コメントのみ
残して削除はしていない)。

### ナビゲーションUIのスタイル

新しい装飾要素(ボタン枠・矢印アイコン画像等)は作らず、既存の
`.contributeToggle`/`.actionLink`と同じ、下線付きプレーンテキストの
ボタンにした。件数表示(「1 / 3」)は、Decision Log 0154が明示的に
不採用としていた「pagination dot」(視覚的などット)ではなく、
プレーンテキストのstatus要素(`aria-live="polite"`)にした。

## 確認結果

- Playwrightで、Hero棚の前へ/次へボタンの動作を確認した。初期状態は
  1冊目のみ可視・状態表示「1 / 3」。次へを1回押すと2冊目が可視に
  なり「2 / 3」。そこからさらに2回(計3回)押すと1冊目に戻り
  「1 / 3」(正しく循環)。1冊目から前へを押すと3冊目に戻り
  「3 / 3」(逆方向の循環も正しく動作)。
- カルーセルを2冊目に切り替えた状態で、その本の「一緒に読みたい」
  トグルが正しく開閉することを確認した(book.id単位で独立した
  `aria-controls`のため、カルーセルの表示切替と競合しない)。
- 「本棚に本を持ち寄る」トグルが引き続き正しく動作することを確認
  した。
- Playwrightで「読みたい」ブロック全体(カルーセルコンテナ)の下端を
  実測し、**mobile(390×844)で下端y=813px、desktop(1440×900)で
  下端y=702px、両方ともスクロールなしで収まることを確認した**
  (Decision Log 0164ではmobileが約201px超過していたが、今回の変更で
  解消した)。
- mobile/desktopとも`document.documentElement.scrollWidth ===
  clientWidth`を確認し、横方向のoverflowが無いことを確認した。
- `npx astro check`: 0 errors, 0 warnings, 1 hint(既存の無関係な
  hint)。
- `npm run build`: 15ページ生成、エラーなし。ビルド後のHTMLに
  `class="undefined"`等の異常な出力が無いことも確認した。

## 採用理由

Hero棚(横に並んだ複数冊)は、height的にはもともと「1行ぶん」しか
消費していなかった(flexで横並びのため)。一方「読みたい」の縦積み
リストは、冊数ぶんの高さがそのまま積み上がっていたため、圧縮の効果が
薄かった(Decision Log 0164)。1冊ずつの表示に変えることで、
「読みたい」も常に「1冊ぶん」の高さしか消費しなくなり、reason文を
一切隠すことなく、mobileでも完全なスクロールなしを達成できた。

Hero・「読みたい」の両方に同じ方式を適用したのは、プロジェクト
オーナーの選択(案1)による。両方が同じ「1冊ずつ+前へ/次へ」という
一貫したインタラクションになるため、ユーザーが本棚のどの区画でも
同じ操作方法を学習すればよいという利点もある。

## 他の案

「読みたい」だけをこの方式にし、Heroは既存の横スクロールのまま
残す案(提案の案2)も検討されたが、プロジェクトオーナーが「両方に
適用」を選んだため、Heroも同じ方式に変更した。

## 将来の変更可能性

- 本棚に登録する本の冊数が今後大きく増えた場合、「1 / 20」のような
  大きな件数でも同じUIで対応できるが、その規模になった場合は
  改めてUIの見直しを検討する。
- 「これから読む」「読了」「贈っていただきました」等、現時点で
  データが無いstatusに本が追加された場合も、同じ`data-carousel`の
  仕組みがそのまま適用される(コンポーネント自体の追加実装は不要)。

## Research Context

「1冊ずつ見せる」という変更は、情報を隠す・省略するという意味では
なく、むしろ「一度に1冊とじっくり向き合う」という体験に近い。
reason文(「なぜこの本を読みたいか」)を一切削らずに済んだことは、
CLAUDE.mdの「実在する内容をそのまま見せる」という方針との一貫性を
保ちながら、1画面に収める密度という制約を両立させた結果である。
