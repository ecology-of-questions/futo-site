# 0190 — HP体験デモを「抜粋・コメント・つながり・公開プレビュー」に刷新(0184を一部supersede)

## Decision
Decision Log 0187で、`FieldnoteMemoDemo.astro`(`/participate/fieldnote`の体験デモ)のタブ構成(概要/たどる/自分のまとめ/育つ、Decision Log 0184)を全面刷新することは「情報設計の決定であり先に確認すべき」と判断し見送っていた。今回、プロジェクトオーナーから「HPデモを添付画像と指示書に合わせる。注意書きの追加だけでなく、抜粋にコメントを重ね、他の記録につなげ、公開プレビューを見る体験まで作ってください。過去のDecision Logは、今回承認した変更を後継ログに記録して更新してください」という明確な承認・再指示を受けたため、実装した。

## 実装したこと

指示書が要求した対象は「記録の詳細を見る画面」であり、セッション一覧の4タブ(概要/たどる/自分のまとめ/育つ)自体の再設計ではなかった。そのため、変更範囲を**記録詳細(旧「追記を見る」画面)に限定**した。

### 記録詳細画面の刷新
- 旧: 「AIが読んだこと」(架空のAI自動読み取り結果)+「私のメモ」(自由記述1つ)。
- 新: 「抜粋」「コメント」「つながり」の3タブ(`role="tablist"`、既存のセッションタブと同じ`.tabbar`/`.tabButton`の見た目を再利用)。
  - **抜粋**: 手入力された抜粋テキスト(実アプリの`excerptText`に相当)。空なら「まだ書いていません。」
  - **コメント**: 複数のコメント(実アプリの`FieldnoteComment`に相当)を時刻付きで一覧表示。追加用のtextareaも設置(このデモでは保存されない旨は明記していないが、他の入力欄と同じくページを離れると消える。既存の「私のメモ」欄と同じ扱い)。
  - **つながり**: 他の記録・サイト内の記録へのリンク一覧(実アプリの`relatedLinks`に相当)。デモ内の別の記録へのリンクは、クリックするとその記録が実際に開く(`data-open-entry`を再利用、フェイクのリンクにしない)。
- 「AIによる自動読み取り」を扱う機能は、デモから完全に削除した。実際に出荷したアプリ(`/fieldnote/`)にはこの機能が存在せず、デモにだけ残すと実態と乖離するため。

### 公開プレビューを見る体験を追加
- 抜粋がある記録には「公開プレビューを見る →」ボタンを追加。押すと、実アプリの公開プレビュー(Decision Log 0187・0189)と同じ形——「自分の考え」「引用+出典」「関連記録」——を模した画面を表示する。
- 「デューイ読書」セッションは、実在する本棚データ(`src/data/bookshelf.ts`の「経験と教育」、ジョン・デューイ)と紐づけ、出典表示に実在の書誌情報を使った(架空の書誌を作らない)。
- 「デモです。実際には公開されません。」という注記を明示し、実際に公開される・サーバーに送信されるかのような誤解を避けた。

### データ内容の作り直し
- `src/data/fieldnoteMemoDemo.ts`の6記録(d1・d2・x1・k1・p1・l2)のうち、抜粋・コメント・つながりを持つ4件(d1・d2・x1・k1)は元のモックアップと同じ文脈(同じ日・同じ話題)を保ったまま内容を作り直した。空の状態を見せていた2件(p1・l2、元は「テキストは見つかりませんでした」というAI読み取り失敗の演出)は、実アプリに合わせて「まだ書いていません」の空状態(抜粋なし)に変更した——AIが「読み取れなかった」のではなく、単に「まだ手入力していない」という、実アプリと同じ意味に揃えた。

## 確認したが変更しなかった点
- セッションレベルの4タブ(概要/たどる/自分のまとめ/育つ)自体の構成は変更していない。指示書が具体的に求めたのは記録詳細の刷新(「抜粋にコメントを重ね、他の記録につなげ、公開プレビューを見る体験」)であり、セッション全体のタブ構成の再設計は対象に含まれていなかったため、変更範囲をスコープした。
- 「育つ」タブ(AIが検出した「育っている問い」等)は、プロジェクトオーナー自身の将来構想であり、今回変更しないことをDecision Log 0187で確認済み。今回も踏襲した。

## 採用理由 (Rationale)
- 実際に出荷したアプリの語彙(抜粋・コメント・つながり、Decision Log 0187)にデモを揃えることで、デモと実物の乖離を小さくした。これまでの「架空のAI自動読み取り」という演出は、指示書が明示的に除外している「AI自動要約・自動リンクは実装しない」という方針と実質的に矛盾していた(実装ではなく構想の演出だったとはいえ)。今回の刷新で、この矛盾も解消された。
- 公開プレビュー画面を、実アプリのデータ形(`authorReflection`/`quote`/`quoteLocation`/`relatedRecords`)そのままの見た目にしたのは、デモと実物の一貫性をさらに強めるため。

## 他の案 (Alternatives)
- セッションレベルのタブ構成(概要/たどる/自分のまとめ/育つ)も同時に刷新する案も検討したが、指示書の要求範囲を超え、かつDecision Log 0184の「育つ」タブはプロジェクトオーナー自身の構想であるため、今回は対象外とした。

## 将来の変更可能性 (Future changes)
- 「育つ」タブを含むセッションレベルの構成を見直す場合は、新しいモックアップ・情報設計の相談を経ること。
- 「コメントを追加」欄も含め、デモの入力欄はすべて非永続(ページを離れると消える)。実際に保存されるかのような誤解が生まれていないか、将来のUI変更時に改めて確認すること。

## Research Context
今回の刷新は、「構想の演出」から「実物の反映」へという性質の変化を伴う。Decision Log 0184時点では、デモは「まだ存在しないアプリの体験」を先取りして見せるものだったが、Stage 1〜3(Decision Log 0187〜0189)の実装が進んだことで、デモが指し示す先に実物が存在するようになった。デモを実物の語彙に合わせ続けることは、公開研究室が「今、実際にできること」を誠実に示し続けるための、継続的なメンテナンス作業として今後も必要になる。
