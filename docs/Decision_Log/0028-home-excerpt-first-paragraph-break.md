# 0028. Home抜粋1段落目に、指定位置の改行を1箇所追加する

- 日付: 2026-08-15
- 状態: 採用中

## Decision

`src/pages/index.astro`のResearch Statement抜粋、1段落目
(「いつもの道を歩いていたら〜」)の`paragraphs`配列を、
「いつもの道を歩いていたら、何度も通っていたはずの家が、」の
直後で2要素に分割し、その位置に改行(`<br>`)を1箇所入れた
(プロジェクトオーナーの指示)。

```
[
  "いつもの道を歩いていたら、何度も通っていたはずの家が、",
  "その日だけ急に気になった。本を読んでいて、一つの言葉が、まったく別の出来事を思い出させた。料理をしているときに、「あれを足したらおいしくなるかもしれない」と、ふと思いついた。そんな経験はないでしょうか。",
]
```

文の途中(句点「。」の位置ではなく読点「、」の位置)での改行だが、
指示された通りの位置であり、文章そのもの(語順・言葉遣い)は変更
していない。対象はこの1段落・この1箇所のみで、他の段落・全文ページ
(`src/pages/research-statement.astro`)は変更していない。

## 採用理由

- 改行位置の指定は、Decision Log 0026・0027までの「段落単位の
  改行方針」の議論とは異なり、1段落内の特定の一箇所を指す具体的な
  指示であり、コピーの表現そのものに関わる判断(CLAUDE.md Workflow:
  研究方向・コンテンツ・最終決定はProject Owner)としてそのまま
  反映した。
- Decision Log 0026・0027で「段落間の余白だけでリズムを作る」
  「強制改行は自然な折返しに任せる」という方針にしたが、これは
  「原則すべて自然な折返しにする」という一般則であり、特定の1箇所
  だけ意図的に改行を入れたいという個別の指示を妨げるものではない。
  `paragraphs: string[][]`という構造(Decision Log 0012)自体が
  「必要なら任意の位置で改行できる」余地を持っているため、この
  指示を実現するのに新たな仕組みは不要だった。

(検討の余地が小さい単純な変更のため、特になし)

## 将来の変更可能性

- 他の段落にも同様の個別の改行指定が入る場合は、同じ形
  (`paragraphs`配列の該当箇所を複数要素に分割する)で対応できる。

## Research Context

Decision Log 0026・0027が「段落単位の一般則」を定めたのに対し、
この変更は「特定の1文の中の、特定の読点の位置」という、より
細かい粒度の指示だった。一般則と個別の例外が両立できるのは、
`paragraphs: string[][]`という構造(Decision Log 0012)が
そもそも「段落ごとに何行にするかを自由に選べる」設計だからであり、
過去のDecision Logが積み重ねてきた設計判断が、こうした細かな
調整にもそのまま応えられる形になっている。
