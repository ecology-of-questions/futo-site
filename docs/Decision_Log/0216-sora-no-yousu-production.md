# 0216. 「きょうの空」を「そらのようす」に改称し、体験デモを本番の記録ツールに切り替える

- 日付: 2026-11-13
- 状態: 採用

## Decision

Decision Log 0213/0214で実装した「きょうの空」(実験室のノート、体験デモ付き)について、プロジェクトオーナーから「体験デモという形で載せているが、これをデモではなく本番として反映させたい」との指示を受けた。これを受けて実装前に2つの確認を行った。

1. プロジェクトオーナーが別途アップロードしたzip(`futo-claude.zip`、このリポジトリには取り込んでいない別プロジェクトの文書)の`reference/terms.md`・`reference/privacy.md`(利用規約・プライバシーポリシーの下書き)を読んだところ、アプリ名が「**そらのようす**」になっており、futo-site側の「きょうの空」と食い違っていた。また、これらの下書きは市区町村選択・端末の匿名IDによる自分の記録の削除・集計データのCCライセンス公開ページなど、今回実装する範囲を超える機能を前提にしていた。
2. この食い違いをプロジェクトオーナーに確認し、(a)アプリ名は「そらのようす」に統一する、(b)市区町村選択・匿名ID・集計公開ページは次回以降とし、今回は種類/うるささ/天気/場所/機数/メモを公開記録として保存する最小構成を即日実装する、(c)利用規約・プライバシーの`[CHECK: …]`未記入箇所は、技術的に分かるもの(ホスティング=Cloudflare Workers、DB=Cloudflare D1、不正対策=自作のレート制限)は埋め、残りは「調整中」と明記する、という3つの回答を得た。

これに基づき、以下を実装した。

### 改称(「きょうの空」→「そらのようす」)

- `src/data/labNotebooks.ts`: `slug`を`kyou-no-sora`→`sora-no-yousu`、`title`を「きょうの空」→「そらのようす」、`detailHref`を`/kyou-no-sora/`→`/sora-no-yousu/`に変更。descriptionも「〜道具をつくっています」(制作中)から「〜道具です」(実際に使える)に変更。
- `src/components/LabNotebookList.astro` / `src/pages/participate.astro` / `src/pages/index.astro`: キー・slug参照をすべて`sora-no-yousu`に更新。`participate.astro`のランディング説明文も「〜記録する方法を考えています」(検討中)から「〜記録できる道具です」(本番)に更新。
- `src/pages/kyou-no-sora/` → `src/pages/sora-no-yousu/`(`git mv`)。
- `src/data/productionNotes.ts` / `src/types/productionNote.ts` / `src/components/ProductionNoteList.astro`: コメント中の名称・パス表記を更新(データ・実装自体は変更なし)。
- `CLAUDE.md` / `PROJECT.md`: Parking Lot解禁済みリストと該当節を更新。

このノートはまだ未公開(本PRでの新規追加)のため、散歩譜の改称時(Decision Log 0182、slugは据え置き)とは異なり、今回もslug・URLを変更した。過去のDecision Log(0213・0214)の本文は旧名表記のまま残している(履歴改変はしない)。

### 体験デモから本番へ

- `src/data/skyLogDemo.ts` → `src/data/skyLog.ts`(`git mv`、Decision Log 0215で拡張した型・ラベルは維持。架空の`demoEntries`は削除)。
- `src/components/SkyLogDemo.astro`/`.module.css` → `src/components/SkyLog.astro`/`.module.css`(`git mv`、全面書き換え)。ビルド時にpropsとして記録を渡す体験デモの構成をやめ、マウント時に`GET /api/sora-log/entries`で実際の公開記録を取得して描画する構成にした。記録は`POST /api/sora-log/entries`でサーバーに送信される。「種類」「うるささ」は必須(未選択の間は送信ボタンをdisabled)、「天気」「場所」「機数」「メモ」は任意。JavaScriptが無効な場合は`<noscript>`で利用にJSが必要な旨を明示する(実データに依存するため、ビルド時描画でごまかさない)。
- `migrations/0002_sora_log_entries.sql`: 新規テーブル`sora_log_entries`(id/kind/loudness/weather/place/count/note/created_at/status/ip_hash)。`entries`テーブル(交換ノート)とは別テーブルにした(記録の性質が異なるため)。
- `worker/index.ts`: `/api/sora-log/entries`(GET/POST)を追加。既存の交換ノートAPIと同じWorker・同じD1インスタンスに相乗りさせた(CLAUDE.mdの「Cloudflare依存をこの機能に限定する」方針のもとでの2件目の利用、本Decision Logで明記)。honeypot・IPハッシュ・レート制限(15秒間隔・1日100件、交換ノートより緩め)は既存実装を踏襲した。
- `package.json`: `d1:migrate:{local,preview,production}:0002`を追加。
- `src/pages/sora-no-yousu/index.astro`: 「体験デモ」の見出しを削除し、「記録する」の下に実ツールを埋め込んだ。「ご利用にあたって」節(利用規約ドラフトの安全な部分=実際に自分で聞いた音だけを記録する・同じ音を何度も記録しない、を転載)と、`/privacy`・`/contact`へのリンクを追加した。
- `src/pages/privacy.astro`: 10番のブロックを新設し、「そらのようす」が実際に取得する情報(種類・うるささ・天気・場所・機数・メモ・受信時刻・IPハッシュのみ、個人情報は取得しない)を、09番(交換ノート投稿)と同じ「実装した範囲だけを事実として書く」方針で記載した。市区町村選択・匿名ID・削除機能・ライセンス表記は、実装でき次第更新する旨を明記した。

## 採用理由

- アプリ名を「そらのようす」に統一したのは、プロジェクトオーナーが別途進めている利用規約・プライバシーポリシーの下書きが先に存在し、そちらの名前を変えるより、futo-site側(まだ未公開のPR内のみ)を合わせる方が影響範囲が小さいため。
- 利用規約・プライバシーポリシーの下書きをそのまま転載しなかったのは、`/privacy.astro`の既存の方針(Decision Log 0135のコメントにある「勝手に長い法務文章へ書き換えない」という明示の指示)と、下書きが約束する機能(市区町村・匿名ID削除・CCライセンス公開)がまだ実装されていないため、そのまま載せると実態より完成して見せることになり、このプロジェクトが繰り返し避けてきた問題(Decision Log 0188・0207等)と同じ構造になるからである。実装済みの範囲だけを事実として書く、という09番ブロックの前例を踏襲した。
- 記録時刻をサーバー受信時刻のみにし、クライアントからの時刻送信・修正を一切受け付けない設計にしたのは、プロジェクトオーナーが別途検討している「裁判などで証拠として使える記録」という要件(受け取った時刻を残す、という項目)を、最も単純な形で満たすため。時刻をクライアントが指定・修正できる余地を残すと、「本当にその時刻に記録したか」を担保できなくなる。
- 「そらのようす」の記録APIを、交換ノートと同じWorker・D1に追加したのは、CLAUDE.mdが既に認めている「Cloudflare依存をこの1機能に限定する」という前提を、新しいWorker/D1インスタンスを増やすのではなく、既存の1つのインスタンス内で機能を追加する形で維持するため(別のCloudflareプロジェクトを増やさない)。
- 市区町村選択・匿名IDでの自分の記録削除・集計データの公開ライセンス表示は、今回実装しなかった。理由は、(1)プロジェクトオーナーの回答が「最小構成を即日中に」だったこと、(2)これらは一覧性のあるUI(都道府県選択、端末記憶、集計ページ)を要し、「とりあえず見れるように」という今回の要求の範囲を超えること、(3)`/privacy`に実装範囲外であることを明記しておけば、後から機能を追加した際にポリシーを更新するだけで整合性を保てるため。

## 他の案

- 利用規約ドラフトをまるごと転載し、`[CHECK: …]`を全て「調整中」に置き換えて公開する案も検討したが、プロジェクトオーナーの回答(「技術的に分かるものは埋め、残りは調整中と明記」)は、ドラフト全体の転載ではなく、実装に即した記述を求めるものと解釈し、09番ブロックの前例に合わせて新規に書く方式を採った。
- 記録の時刻をクライアントの端末時刻で送り、「3分前にする」等の修正機能を実装する案(試作アーティファクトにある構成)も検討したが、記録の確からしさ(あとから時刻を書き換えられない)を優先し、サーバー受信時刻のみを採用した。

## 将来の変更可能性

- 市区町村選択・匿名IDでの記録管理・自分の記録の削除・集計データの公開ページ(ライセンス表示付き)は、プロジェクトオーナーの利用規約・プライバシーポリシーが確定し、実装の合意が取れた段階で追加する。追加時は`migrations/`に新しいマイグレーション、`worker/index.ts`にエンドポイント追加、`/privacy`の10番ブロック更新、という同じパターンで進められる。
- 不正投稿を集計から除外する仕組み(`sora_log_entries.status = 'excluded'`)は、スキーマ上は用意したが、実際に除外を判断・実行する運用や、除外件数・理由を公開する仕組みはまだ実装していない。
- `d1:migrate:*:0002`は、このセッションにはCloudflareの認証情報が無く実行できなかった。Preview/Production環境のD1に対しては、`wrangler`にログイン済みの環境(プロジェクトオーナー側)で`npm run d1:migrate:preview:0002`・`npm run d1:migrate:production:0002`を実行する必要がある(本番適用前の既存手順と同じ)。

## Research Context

「そらのようす」が体験デモから本番に切り替わったことは、この研究室が「作っている過程を見せる」段階から「実際に使われ、記録が蓄積されていく」段階に進んだことを示す。利用規約・プライバシーポリシーをそのまま転載せず、実装済みの範囲だけを正直に書いたのは、「公開研究室」が一貫して大事にしてきた、完成度を実態より高く見せない、という姿勢の延長である。記録時刻をサーバー側だけに限定したのも、「記録の確からしさ」という、この道具が将来何かの根拠として使われうることを見据えた、最初から誠実さを設計に組み込む判断である。

- `/privacy`・`/participate`・Home(1000px/1200px)をPlaywrightで静的ビルド経由で確認し、「そらのようす」表記への統一とコンソールエラーが無いことを確認した。
- Preview/Production環境のD1への実際のマイグレーション適用は未実施(上記「将来の変更可能性」参照、プロジェクトオーナー側での実行が必要)。
