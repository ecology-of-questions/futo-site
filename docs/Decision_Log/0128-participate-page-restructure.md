# 0128. /participateページを「持ち寄る」の循環が見える構成に再編する

- 日付: 2026-09-11
- 状態: 採用

## Decision

プロジェクトオーナーから、`/participate`ページの再構成指示を受けた。
目的は「参加方法をたくさん並べるページ」ではなく、「さまざまな人が
持っているものを『ふ、と』に持ち寄り、公開できるものは他の人とも
共有されていく場所」にすることだった。

### 主な決定事項

- PARTICIPATEの日本語名称は引き続き「持ち寄る」とする(URL・英語
  ラベルは変更なし)
- 「気になるものを寄せる」「一緒に試す」「話す」「場所を貸す」
  「情報を教える」「知識・技術を貸す」という、参加メニューを多数
  横並びにする構造をやめる
- 「何かを持ち寄る」と「本をプレゼントする」の2つを主要な入口にする
- 本・記事・人・場所・知識・経験などを、「紹介」と「提供」に分けず、
  同じ「何かを持ち寄る」の1つの入口(1つのフォーム)で扱う
- 持ち寄られたものは、投稿者が公開可否をチェックボックスで選択できる
  (初期値OFF)
- 公開可であっても自動掲載はせず、運営側が内容を確認してから手動で
  `src/data/contributions.ts`に追加する
- 公開されたものは「持ち寄られたもの」セクションで他の訪問者も見られ
  るようにし、新しい出会いのきっかけにする
- 「話す」「一緒に試す」は独立した参加メニューとしては扱わず、
  「持ち寄られたものから生まれる行為」として、ページ下部に短い1文で
  表現するにとどめる
- ユーザーアカウント・ログイン・データベース・Formspree投稿の自動
  公開・投稿者プロフィール・コメント・フォロー・いいね・人気順・
  通知・自動マッチング等、SNS的な機能は一切追加しない

## 対応

### ページ構成の変更(`src/pages/participate.astro`)

旧構成: Hero → 気になるものを寄せる(フォーム) → 本から参加する →
一緒に試す → 話す → 場所・知識・技術を貸す → まとめ

新構成:
1. Hero: スタンス表明(「異なる他者や、知らなかった世界との出会いを
   大切にしたい」)+「持ち寄る」の考え方を伝える短い説明(2段落)
2. 何かを持ち寄る: 旧「気になるものを寄せる」フォームを拡張。旧
   「場所・知識・技術を貸す」3カードの内容も、別カテゴリに分けず
   この1つの入口の説明文に統合した(3カード自体は削除)
3. 持ち寄られたもの(新設): `src/data/contributions.ts`の公開承認済み
   (`visible: true`)エントリのみを、種類・タイトル・短い説明・
   任意の外部リンクという静かな一覧で表示する。0件時は不自然な空
   カードを出さず、「まだ紹介できるものがありません。届いたものから、
   少しずつここに加えていきます。」という文章のempty stateにした
   (セクション自体を非表示にする案も検討したが、「研究は常に成長する
   もの」というCLAUDE.mdの方針に合わせ、今後ここが育っていくことが
   伝わる文言を残す方を選んだ)
4. 本をプレゼントする(旧「本から参加する」を改称): featured本の表示
   (`BookshelfList.astro`)・`/bookshelf`への導線は変更なし
5. まとめ(旧「ともに、続けていくために」): 旧「一緒に試す」「話す」
   独立セクションを廃止し、「持ち寄られたものから、誰かと話したり、
   一緒に何かを試したりすることがあります。」という1文に圧縮して
   このセクションの冒頭に統合した

### 「何かを持ち寄る」フォームの変更

既存のFormspreeエンドポイント(`contactFormEndpoint`)・honeypot
(`_gotcha`)をそのまま再利用した。

- 必須: 持ち寄りたいものの名前 / URL(1項目、旧フォームと同じ構造)
- 任意: どんなものか・なぜ届けたいと思ったか(1つのtextareaに統合)、
  お名前、メールアドレス
- `_subject`を「ふ、と｜何かを持ち寄る」に変更
- 新設: 「この内容を、サイト上でみんなにも共有してよい」チェック
  ボックス(初期値OFF)。チェックボックス自体には`name`を付けず、
  別途用意した`<input type="hidden" name="public_ok" value="no">`の
  値を、送信直前にJSでチェック状態に応じて`"yes"`/`"no"`に書き換える
  実装にした。これにより、チェックの有無にかかわらずFormspreeの
  送信内容に必ず`public_ok`の値が1つだけ含まれる(チェック時のみ
  同名フィールドが送信され複数値になる、というありがちな実装ミスを
  避けている)。Playwrightでネットワークリクエストを捕捉し、未チェック
  時`public_ok=no`・チェック時`public_ok=yes`が単一の値として送信
  されることを確認済み。
- チェックボックスの下に「チェックの有無にかかわらず、お名前や
  メールアドレスをサイト上で公開することはありません。内容を確認の
  うえ、運営がサイトに掲載します。」という注記を追加した
  (`BookshelfFullList.astro`の既存の「話してみたい」フォームにある
  プライバシー注記と同じ考え方)。

### 個人情報を公開しない構造(コード上の保証)

`src/types/contributions.ts`の`Contribution`型には、投稿者名・
メールアドレス等の連絡先フィールドを一切持たせていない。「誰が
持ち寄ったか」ではなく「何が持ち寄られたか」だけを表現する構造に
することで、実装上も個人情報が公開データ(`contributions.ts`)に
混ざりようがないようにした。公開は既存のFormspree送信内容を運営が
目視確認したうえで、この型に沿って手動でデータを追記する形になる
(チェックボックスがONでも、フォーム送信内容がそのまま自動的に
掲載されることはない)。

### 新設データ構造

- `src/types/contributions.ts`: `ContributionType`(book/article/
  person/place/project/event/other)、`contributionTypeLabels`
  (表示用日本語ラベル)、`Contribution`インターフェース(id/title/
  type/url?/note?/publishedAt/visible)
- `src/data/contributions.ts`: 上記型を使う`contributions`配列。
  現時点では空配列(`[]`)。運用方法(公開確認の手順)をファイル冒頭の
  コメントに明記した

### 削除したもの

- `src/types/participate.ts`(`LendCategory`型。「場所・知識・技術を
  貸す」3カードの廃止に伴い完全に未使用になったため削除)
- `participate.module.css`の`.lendGrid`/`.lendCard`/`.lendIcon`/
  `.lendTitle`/`.lendDescription`(同上の理由)

### 既存機能への影響

`/bookshelf`・canonical bookshelf data(`src/data/bookshelf.ts`)・
本について話したいフォーム・本を贈るMVP・Formspree・`/support`→
`/participate`のリダイレクト・研究断面/研究断面一覧は、いずれも
変更していない。「本をプレゼントする」も新しい本一覧を作らず、
既存の`featured: true`フィルタ・`BookshelfList.astro`をそのまま
再利用した。`src/data/bookshelf.ts`・`src/types/bookshelf.ts`・
`src/components/BookshelfList.astro`・`src/pages/bookshelf.astro`の
コメントに残っていた「本から関わる」という旧セクション名への言及は、
現状(「本をプレゼントする」)に合わせて更新した(機能・データ構造
自体は変更していない)。

## 採用理由

指示を字面通りに実装した。「紹介」と「提供」を分けない、という
指示に従い、旧来の「場所・知識・技術を貸す」3カードを独立UIとして
残さず、1つのフォームの説明文に統合した。公開可否の値を確実に
`yes`/`no`のどちらかとして送信する実装(hidden fieldの値を送信直前に
書き換える方式)は、チェックボックスの有無だけに頼る実装より、
Formspreeで受け取るメールを読む運営側にとって曖昧さがなく確実である
ため採用した。

## 他の案

- 「持ち寄られたもの」0件時にセクション自体を非表示にする案も、
  指示の選択肢として提示されていたが、今後投稿が増えていくことを
  訪問者に予感させる方を選んだ(採用理由参照)。
- 「持ち寄られたもの」の表示に既存の`CurrentWorkList`コンポーネント
  (index.astro「研究断面」で使用)を再利用する案も検討したが、
  同コンポーネントのCSSはDesktop幅で「常に2カラム」という固定2件
  前提のレイアウトになっており、可変長の一覧には適さないため、
  シンプルな縦積みリストを`participate.astro`内に直接実装する形に
  した(コンポーネントの流用よりも、責務の異なるコンポーネントを
  無理に共用しないことを優先した)。

## 将来の変更可能性

- 投稿数が増えた場合、`type`によるフィルターや並び替えの追加を
  検討する余地がある(現時点では複雑な分類UIを避け、単純な一覧に
  とどめている)。
- 将来的に投稿者名を表示する可能性はあるが、今回は実装していない
  (`Contribution`型に投稿者関連フィールドが増えた場合、個人情報を
  公開しない方針との整合を都度確認する必要がある)。
- Formspreeからの自動取得・自動公開の仕組みは、投稿数が増え運営の
  手動確認が負荷になった段階で改めて検討する。

## Research Context

この再編は、CLAUDE.mdの「継続的に研究を育てる」という考え方を、
サイトの参加導線そのものに反映させたものと言える。「支援する側/
支援される側」を固定しない、という指示は、「ふ、と」が特定の誰かの
ためのプロジェクトではなく、持ち寄られたものが別の誰かにとっての
新しい出会いになり、そこからまた別の問いが生まれる、という循環的な
構造を持つ公開研究室であることと一致する。UIをシンプルに保ち
(SNS的な機能を追加しない)、この循環をUIと構造から自然に伝える
という方針も、「余白を思考時間として扱う」「静かな編集的レイアウト」
というDesign Spec/CLAUDE.mdの美意識と整合している。
