# 0114. 「関わる」ページの本文コピー・データ構造を確定版に差し替える

- 日付: 2026-09-11
- 状態: 採用(Decision Log 0113の一部を上書き)

## Decision

Decision Log 0113で実装した「関わる」ページについて、プロジェクト
オーナーから次の指摘・指示を受けた。

1. 本文コピーは、セッションのコンテキスト要約により原文が失われた
   状態で「推測・再創作」されたものだった。プロジェクトオーナーは
   全文言を確定させており、推測せずその確定版にそのまま合わせること。
2. 添付イメージに表示されていた本のタイトル・著者等はデザイン確認用の
   仮データであり、実在情報として確定してはならない。後から実際の
   「読みたい本」に差し替えやすいデータ構造にすること。

この指摘を受け、Decision Log 0113で実装した本文コピー・
「本を贈る」データ構造を全面的に差し替えた。まだmainへのマージは
行わず、`claude/top-page-redesign`ブランチ上での調整として実施した。

## 対応

### 1. 本文コピーの全面差し替え

Hero・気になるものを寄せる・本を贈る・この本を贈る・一緒に試す・話す・
場所知識技術を貸す・まとめの全セクションで、プロジェクトオーナーが
提示した確定文言にそのまま差し替えた。改行位置は意図されたリズムの
ため、ResearchStatement.astroの既存方針(「改行位置はコピーの意図
そのものなので変更しない」)にならい、`<br />`でそのまま保持している。

「一緒に試す」「話す」は、Decision Log 0113では1つの見出し
(「一緒に試す、話す」)にまとめていたが、確定文言では独立した2つの
セクション(見出し・本文・ボタンをそれぞれ持つ)だったため、
`<ResearchSection>`を分割し、他のセクションと同じ「1見出し1
ResearchSection」の構成に揃えた。

「場所・知識・技術を貸す」の3カードも、確定文言に合わせて内容を
差し替えた: 「知識を貸す」→「情報を教える」(内容も知識ではなく
情報提供に変更)、「技術を貸す」→「知識・技術を貸す」(1カードに
統合)。`LendCategory`の`icon`列挙型も`"place" | "info" | "skill"`に
更新し、対応するインラインSVGアイコンを差し替えた。

まとめセクション末尾に、確定文言にあった小さな結びの一文
(「それぞれのふとが、研究をひらいていく。」)を`.closingTagline`
として追加した。

Hero右側に置いていた縦書きの装飾コピー(「問いは、ひとりでは
育たない」、Decision Log 0113で追加)は削除した。これは実在の写真が
用意されるまでの仮の飾りとして実装側が追加した文言であり、確定
コピーの一覧には含まれていなかったため、確定していない文言を
残さない方針で撤去し、色面のみのプレースホルダーにした。

### 2. GiftBookEntryのデータ構造変更

`src/types/participate.ts`の`GiftBookEntry`を、プロジェクトオーナー
指定の7項目(`title` / `author` / `status` / `reason` / `image` /
`newBookUrl` / `usedBookUrl`)を持つ形に変更した。`image`が未設定の
本は、`GiftBookList.astro`が並び順(index)からトーン(warm/moss/sky)を
機械的に割り当てて仮カバーを表示する(データ自体に色の情報を
持たせない)。

現時点の3件のデータ(`participate.astro`)は、タイトル・著者・
status・reasonのすべての値に「(仮データ)」を明記した。実在の書籍
情報として確定しないためで、実際に読みたい本が決まり次第、配列の
要素を1件ずつ丸ごと差し替えるだけで更新できる。

### 3. 「この本を贈る」の贈り方をper-book化

Decision Log 0113では、贈り方3択(`GiftMethod[]`)を全冊共通の
静的リストとして実装していたが、確定文言では「新品で贈る」
「古本で贈る」は選択中の本ごとに遷移先が変わる想定(`newBookUrl`/
`usedBookUrl`)だったため、`GiftMethod`型を廃止し、`GiftBookList.astro`
内のvanilla JSで、カード選択時に該当する2つのリンクの`href`を
書き換える方式に変更した。「手元にある本を贈る」は本に依存しない
固定の導線とし、送付先住所をサイト上に公開せず、`/contact`
(既定値、`contactHref` propで変更可能)につなげている。

### 4. 気になるものを寄せるフォームの項目変更

フィールドを「URL / 名前(必須、`name="target"`)」
「なぜ気になったか(任意、`name="reason"`)」「お名前(任意、
`name="name"`)」「メールアドレス(任意、`name="email"`)」の4項目に
変更した。必須はtarget(URL / 名前)のみで、他はすべて任意。
`_subject`隠しフィールドの値を「ふ、と 関わるページ 気になるものを
寄せる」に変更し、Formspree受信箱で「関わるページ経由」であることが
件名から分かるようにした。honeypot(`_gotcha`)は変更なし。送信ボタン
文言を「これ、気になるかも →」に差し替えた。

## 採用理由

- 「文章はこちらで確定している」という明確な指摘のもと、推測に
  基づく再創作を続けることは、CLAUDE.mdの「Design Specの世界観・
  コピー・情報設計を実装都合で変えない」方針に反する。確定文言への
  一字一句の合わせ込みを優先した。
- 実在しない書籍の著者名等を、確定情報であるかのように掲載すると、
  誤情報が公開される可能性があった。値そのものに「(仮データ)」と
  明記することで、コードを見た人にも、(まだmainにマージしていない
  現時点で)ページを見た人にも、仮データであることが伝わる形にした。
- 贈り方のper-book化・「手元にある本を贈る」の住所非公開は、
  プロジェクトオーナーの明示的な設計指示であり、そのまま実装した。

## 他の案

- 仮データの本のタイトルを、Decision Log 0113のように「それらしい」
  架空のタイトル(例:「偶然と観察」)にする案もあったが、プロジェクト
  オーナーから「デザイン確認用の仮データを実在情報として確定
  しないでください」との指摘を受けたため、あえて「書籍タイトル1
  (仮データ)」のような、実在の書籍と誤認されようがない表記に変更した。

## 将来の変更可能性

- `giftBooks`配列の3要素を、実際に読みたい本が決まり次第、
  title/author/status/reason/image/newBookUrl/usedBookUrlを
  差し替える形で更新する。
- Hero右側の色面は、実際の写真素材が用意され次第、画像に差し替える
  想定(Decision Log 0113から変更なし)。

## Research Context

このDecision Logは、AIが実装した内容とプロジェクトオーナーが意図した
内容がずれた場合に、どちらを正とし、どう修正したかを記録するもので
ある。特に「コンテキストの制約により実装側が推測で補った部分」を
確定情報として扱わず、確定した時点で速やかに正しい内容に置き換える、
という運用そのものを記録している。あわせて、仮データを仮データと
分かる形で残すことは、「完成度よりも育てられることを優先する」という
CLAUDE.mdの姿勢と、「未確定の情報を確定情報として公開しない」という
誠実さの両方を両立させる実務的な工夫である。
