# 0014. CLAUDE.md を「開発ルール集」から「プロジェクト憲章」へ再構成する

- 日付: 2026-08-04
- 状態: 採用中(初版のCLAUDE.mdを全面的に書き直し)

## Decision

CLAUDE.mdを、Philosophy(思想)を最上位に置いた構成に全面的に
書き直した。

```
The Project
↓ Philosophy
↓ Product Identity
↓ Current Phase
↓ Architecture
↓ Workflow
↓ Coding Rules
↓ Documentation
↓ Commit Rules
↓ Default Behavior
↓ (締めの一文: Does this help the Public Research Studio grow?)
```

初版(直前のコミット)は、技術スタック・体制・ルールを並列に
並べた「開発ルール集」だった。これを、思想(Philosophy)が
コーディングルールより上位にある構成へ組み替えた。

## 採用理由

- 「Claude Codeは最初を一番読む」という指摘の通り、ファイルの
  冒頭に何を置くかが、実質的な優先順位の表明になる。技術スタックを
  先頭に置いていた初版は、「これは技術プロジェクトである」という
  誤ったメッセージを最初に発してしまっていた。
- Design Specが「プロダクト」を定義し、CLAUDE.mdが「チーム(の
  振る舞い)」を定義する、という役割の違いが明確になった。
  CLAUDE.mdは説明書ではなく、プロジェクト憲章として書くべき
  だという指摘を採用した。
- Current Phase(今何を作っているか)を独立したセクションとして
  持つことで、β公開という現在のマイルストーンとParking Lotが
  常に最新の状態に更新される前提を作った。
- Default Behavior(実装が完了していなくても止まらない、
  後から直せるものは実装してから記録する)を明文化することで、
  「モックアップ待ちにならない」という運用ルールを、判断基準として
  一段落とし込んだ。

## 他の案

- 初版のまま、セクションの並び順だけ変える案も検討したが、
  「開発ルール集」という性質そのものを変える必要があると判断し、
  Philosophy・Product Identityという新しいセクションを追加した
  上で全面的に書き直した。

## 将来の変更可能性

- Current Phaseは、β公開後は内容が大きく変わる(新しい
  マイルストーン・優先順位・Parking Lotの解除)。このセクションは
  他のセクションより高い頻度で更新される想定。
- Philosophy・Product Identityは、キックオフ文書やDesign Spec全体を
  貫く原則であり、頻繁には変えない想定。

## Research Context

Design Specが「プロダクト」を定義し、CLAUDE.mdが「チーム」を
定義する、という切り分けは、このプロジェクトの「器と中身を
分ける」という一貫した思想の、もう一段上のレベルでの適用である。
コンポーネントが文章を受け取る器であるように、CLAUDE.mdは
実装判断を受け取る器であり、その器の一番上に「これは公開研究室
である」という一文を置くことで、以降のすべての技術的判断が
その前提の上で行われるようにした。
