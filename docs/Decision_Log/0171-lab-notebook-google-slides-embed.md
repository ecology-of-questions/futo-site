# 0171. 実験室ノート: Miro埋め込み構想をGoogleスライド埋め込み+コメント用リンクに置き換え

- 日付: 2026-09-17
- 状態: 採用(URL未設定のため、実際の書影確認は未完了。下記「確認結果」
  参照)
- 関連: Decision Log 0140(3冊のノート構造・共通テンプレート`[slug].astro`
  の新設)。Decision Log 0155(「音の道βのMiro公開ができた際は」という
  将来構想メモの初出、当時Miro自体の実装は無かった)。

## Decision

プロジェクトオーナーから、「futoing.com「公開研究室ふ、と」のMiro埋め込み
部分を、Googleスライドの埋め込み+コメント用リンクに変更してください」
という指示を受けた。

### 事前調査で判明したこと

着手前にリポジトリ全体を調査したところ、**実際に動いているMiro埋め込み
(`<iframe>`等)はどこにも存在しなかった**。「Miro」という語が出てくるのは
`participate.astro`・`LabNotebookList.astro`のコメント内のみで、いずれも
「将来、音の道βのMiro公開ができた際は」という将来構想のメモ
(Decision Log 0155)であり、実装そのものは一度も行われていなかった。

また、指示文にある「この断面にコメントを置く →」の「断面」という言葉が、
このサイトでは「研究断面」(`/research/reviews/01`等)の命名規則と重なる
一方、「実験室」側は「ノート」と呼んでおり「断面」という言葉は使って
いなかったため、対象ページが実験室(3冊のノート)なのか、Research
Reviewページなのか、この場では判断できなかった。この状態のまま実装を
進めると誤った対象を変更するおそれがあるため、着手前にプロジェクト
オーナーに確認した。確認の結果、**対象は実験室の3冊のノート(音の道・
Fieldnote・研究断面をひらく)すべて**であることが分かった。

## 対応

### データ構造: ノートごとに2つの任意URLを追加

`src/types/labNotebook.ts`の`LabNotebook`型に、以下の2フィールドを
追加した。

- `slidesEmbedUrl?: string` — Googleスライドの「ファイル→共有→ウェブに
  公開」で取得する埋め込み用URL。
- `slidesCommentUrl?: string` — Googleスライド本体の共有URL(コメント
  可能な権限にしたもの)。「この断面にコメントを置く →」の遷移先。

指示の「埋め込み用URLとコメント用共有URLは別々に設定できる構成にする」
に対応するため、意図的に別フィールドにした(Google側でも「ウェブに
公開」の埋め込みURLと、コメント可能な共有URLは別の設定・別のURLに
なるため)。

`src/data/labNotebooks.ts`の3冊とも、**この2フィールドは追加していない
(未設定のまま)**。実際のURLが無い状態で架空の値を入れない、という
指示への対応。

### 表示: 埋め込み用URLが無い場合、区画自体を表示しない

`src/pages/participate/[slug].astro`に「スライド」区画を追加した
(Hero直後、「書かれたこと」の前)。`notebook.slidesEmbedUrl`が無い
場合(現状の3冊すべて)、この区画自体を描画しない。壊れたiframeや
無効なリンクを表示しないための、既存パターン(Decision Log 0161の
「liveExperiments.length > 0 &&」等)を踏襲した条件描画。

`slidesCommentUrl`も同様に、値がある場合のみコメントリンク+補足文を
表示する(埋め込みはあるがコメントリンクは無い、という状態も許容する
構成)。

### 自動再生・ループの無効化

`buildSlidesEmbedSrc()`関数で、渡された埋め込みURLに`start=false`・
`loop=false`を強制的に付加してからiframeの`src`に使う。Google側の
「ウェブに公開」ダイアログでどのオプションを選んでコピーしても
(自動再生・ループのクエリが含まれていても)、常に無効化される
(訪問者が自分のペースでページを送れるようにする、という指示への
対応)。

### 縦横比・レスポンシブ

`.slidesEmbed`に`aspect-ratio: 16 / 9`(現行のGoogleスライドの既定の
横縦比)を指定し、`max-width: 48rem`で広い画面での伸びすぎを防いだ。
iframe自体は`width: 100%; height: 100%;`でラッパーに追従するため、
PC・スマホとも横にはみ出さず、縦横比も崩れない。

### コメント用リンク

既存の`ArrowLink.astro`(「◯◯について知る →」矢印付きテキストリンク、
Contactページの外部リンクでも使用中)をそのまま再利用した。
`external`propにより`target="_blank"`・`rel="noopener noreferrer"`・
スクリーンリーダー向けの「(外部サイトが新しいタブで開きます)」を
自動的に付加する。新規CSSを追加せず、大きなCTAではない「静かな
テキストリンク」という指示に自然に合致する。補足文
「Googleスライドを開いてコメントできます。」は、既存の`.privacyNote`
等と同じ`fs-sm`・`color-ink-muted`の控えめな注記スタイルを踏襲した。

コメント欄の自作・Googleログイン機能の実装は行っていない(指示通り、
リンク先のGoogleスライド上でのコメント機能をそのまま使う)。表示中の
スライドとリンク先の同期機能も実装していない。

## 対応ファイル

- `src/types/labNotebook.ts`(`slidesEmbedUrl`・`slidesCommentUrl`の
  型追加)
- `src/data/labNotebooks.ts`(コメントのみ。実データの追加は無し)
- `src/pages/participate/[slug].astro`(スライド区画の追加、
  `buildSlidesEmbedSrc()`関数、`ArrowLink`のimport)
- `src/pages/participate/[slug].module.css`(`.slidesEmbed`・
  `.slidesComment`・`.slidesCommentNote`の追加)

Miro関連の記述があった`participate.astro`・`LabNotebookList.astro`の
コメントは、実装が無かったため変更不要と判断し、今回は変更していない
(将来構想メモとしての実害は無いが、必要であれば別途整理を検討する)。
`/research/reviews/*`・Worker/D1/API・他ページは変更していない。

## 確認結果

- `npx astro check`: 0 errors, 0 warnings, 1 hint(既存の無関係な
  hint)。
- `npm run build`: 15ページ生成、エラーなし。
- 3ノートとも、ビルド後のHTMLに`<iframe>`・「この断面にコメントを
  置く」の文字列が1件も含まれないことを確認した(URL未設定時に区画
  自体が描画されないことの確認)。
- **一時的なテスト**として、`data:`URI(ネットワークアクセスを伴わない
  安全な値)と`https://example.com/...`のダミーURLを`labNotebooks.ts`に
  ローカルで一時的に設定し、mobile(390px)/desktop(1440px)で表示・
  レイアウトを確認したうえで、**コミット前に完全に元に戻した**
  (`git diff`でテスト用の値が残っていないことを確認済み)。この
  一時テストで、以下を確認した。
  - iframeの実際の描画サイズが、mobile(342×192px)・desktop
    (768×432px)とも正確に16:9になっていること。
  - `src`に`?start=false&loop=false`が正しく付加されていること。
  - コメントリンクが`target="_blank"`・`rel="noopener noreferrer"`・
    適切な`aria-label`を持つこと。
  - mobile/desktopとも`document.documentElement.scrollWidth ===
    clientWidth`(横方向のoverflow無し)。
  - 「他のノートを見る」等、既存の区画のレイアウトに影響が無いこと。
- **実際のGoogleスライドURLでの表示・コメント権限の動作は未確認**
  (現時点でURLが未提供のため)。プロジェクトオーナーがURLを設定した
  後、実際に埋め込み表示・コメント遷移が正しく動作するか、改めての
  確認をお願いしたい。

## Google側で必要な設定(プロジェクトオーナーの作業)

「ウェブに公開」と「コメント可能な共有設定」は別の操作のため、それぞれ
案内する。

1. **埋め込み用URL(`slidesEmbedUrl`)の取得**
   - 対象のGoogleスライドを開く → 「ファイル」→「共有」→
     「ウェブに公開」。
   - 「埋め込み」タブを選ぶ(「リンク」タブではない)。
   - 自動再生に関するチェックボックス(「スライドを自動的に切り替える」
     等)はどちらでも構わない(このサイト側で`start=false`・
     `loop=false`を常に強制するため)。
   - 「公開」を押すと表示される`<iframe src="https://docs.google.com/
     presentation/d/e/.../embed?...">`の、`src="..."`の中身(URL)だけを
     使う。

2. **コメント用URL(`slidesCommentUrl`)の取得**
   - 同じスライドの「共有」(「ウェブに公開」とは別のボタン)を開く。
   - 「リンクを知っている全員」に変更し、権限を「コメント可」にする
     (「閲覧可」のままだとコメントできない)。
   - 発行された共有URL(`https://docs.google.com/presentation/d/.../
     edit?usp=sharing`のような形)をそのまま使う。

3. **設定場所**
   - `src/data/labNotebooks.ts`の該当ノート(`oto-no-michi`/
     `fieldnote`/`research-fragments`)のオブジェクトに、
     `slidesEmbedUrl: "..."`・`slidesCommentUrl: "..."`を追加する
     (どちらか一方のみの設定も可能)。
   - この作業は本PRのマージ後、別途対応をお願いする(架空のURLを
     このPRに含めていないため)。

4. **公開前の確認のお願い**
   - 「ウェブに公開」にすると、リンクを知らない第三者でも検索エンジン
     経由などでアクセスできる可能性がある状態になる。公開するスライド
     に、非公開情報(下書き段階の内容、個人情報、外部に見せる想定の
     無い内容等)が含まれていないか、公開前にご確認をお願いしたい。

## 採用理由

実際には存在しなかったMiro埋め込みを「置き換える」のではなく、指示書の
意図(訪問者が資料を見てコメントできる、静かな導線)を汲んで、指示された
Googleスライド方式を新規に実装した。3冊すべてに同じ仕組みを持たせつつ、
URLが無いノートには何も表示しない設計にすることで、「一部のノートだけ
スライドがある」という将来の状態にも、データを追加するだけで自然に
対応できる。

## 他の案

対象ページを「実験室の3冊のノート」ではなく「Research Review(研究
断面)」に限定する案もあったが、「この断面にコメントを置く」の文言が
指す対象について確信が持てなかったため実装前に確認し、実験室3冊全てに
適用する指示を受けたため、この形にした。

## 将来の変更可能性

- Research Review(研究断面)側にも同様の仕組みが必要になった場合、
  `ReviewSection`や`ResearchReviewArticle`に同種のprops
  (`slidesEmbedUrl`/`slidesCommentUrl`)を追加する形で、同じ
  `buildSlidesEmbedSrc()`のロジックを再利用できる。
- Googleスライドの既定の縦横比が変わった場合、または4:3のスライドを
  使うノートが出てきた場合は、`.slidesEmbed`の`aspect-ratio`をノート
  ごとに指定できるようフィールドを追加する必要がある(現状は全ノート
  一律16:9で固定)。

## Research Context

「Miro埋め込みを置き換えてほしい」という指示の前提(既存の埋め込みが
存在する)が、実際のコードベースの状態と一致していないことが分かった
時点で、その食い違いを黙って解釈で埋めるのではなく、指示に含まれる
別の手がかり(「断面」という言葉の用法)まで踏まえて、対象を確認して
から実装した。これは、CLAUDE.mdの「情報アーキテクチャに関わる判断は
先に確認する」という原則の実践であり、また「実在しないものを実在する
かのように扱わない」というこのプロジェクト全体の姿勢を、指示の解釈
そのものにも適用した例である。
