# 0199 — モバイルもデスクトップと同じ3人横並びのHeroモーションに統一、PC幅の文字強弱を調整

## Decision
main のHeroについて、プロジェクトオーナーから2点の修正指示を受けた。人物イラスト・色・3人の並び順・研究断面以下の内容は変更していない。

**1. モバイルもデスクトップと同じモーションに統一**

モバイル専用だった「中央の人物ひとりが観察する/学ぶ/試すを切り替える」構成(Decision Log 0195/0198)を撤去し、デスクトップと同じ「観察する(左)/学ぶ(中央)/試す(右)を横並びで常時静止表示し、`prefers-reduced-motion: no-preference`かつJavaScript有効時だけ左から順にフェードイン→3人が揃った状態を保持→同時にフェードアウト→短い空白→再開する」構成(Decision Log 0197)に統一した。

- `src/pages/index.astro`から`.heroSceneMobile`(人物ひとり+`heroCaptionGroup`+`heroCaptionStatic`)を削除し、`.heroSceneDesktop`を`.heroSceneRow`という名前に変えて全幅で常に使う1つの構成にした。
- `src/pages/index.module.css`から、モバイル専用だった`heroPoseObserveMobile`/`heroPoseLearnMobile`/`heroPoseTryMobile`・`heroCaptionMobile*`とその@keyframes、`heroWalkerAnimated`関連のルールを削除した。
- `.heroWalker`のサイズを`clamp()`にし、狭い画面では連続的に縮小するようにした(上限はデスクトップの元の固定値と同じ4.4rem/7.3remなので、デスクトップの見え方は変えていない)。`.heroSceneRow`の`gap`も760px以下でだけ詰めている。
- `prefers-reduced-motion: reduce`、およびJavaScriptを実行しない環境では、デスクトップ・モバイルとも3人を常時表示する。`scripting: none`はCSSアニメーション自体を止めないため、`.heroFigureCell`のフェードインアニメーションを適用する条件に`(scripting: enabled)`も加え、JavaScript無効時は明示的にアニメーションを適用しないようにした(この観点はDecision Log 0197時点では抜けていたため、今回あわせて直した)。

**2. PC幅(768px以上)の文字の強弱**

`@media (min-width: 768px)`で、見出し(`.heroHeading`)のフォントサイズを少し小さく、行為名(`.heroCaption`)のフォントサイズを少し大きくした。書体・太さ・色・下線などの装飾は変えておらず、フォントサイズだけを動かしている。モバイル幅(768px未満)の文字サイズは変更していない。

- 見出し: `var(--home-hero-words)`(768pxで約34.7px、1440pxで40px)から`clamp(1.6rem, 0.65rem + 2.5vw, 2.15rem)`(768pxで約29.6px、1440pxで約34.4px)に変更。どちらの幅でもおよそ14〜15%小さくなる。
- 行為名: `var(--home-label-size)`(12px固定)から`0.875rem`(14px)に変更。

## 採用理由 (Rationale)
- モバイル専用構成を残したまま「PCと同じモーションに」という指示に応えようとすると、結局デスクトップの構成をモバイル幅に複製することになり、コードの二重管理になる。指示が「モバイル専用の...構成は削除してください」と明記しているとおり、1つの構成に統一するのが最も単純で、今後の保守も1箇所で済む。
- `.heroWalker`のサイズを固定値の切り替え(メディアクエリでの別の固定値)ではなく`clamp()`にしたのは、320px〜768px超まで幅が変わるたびに人物が唐突に大きさを変えるのではなく、連続的に縮小・拡大させるため。上限をデスクトップの元の値と一致させることで、「デスクトップの配置は変更しない」という指示を数式のうえでも保証している。
- `scripting: enabled`を追加条件にしたのは、実装中に「JavaScript無効環境でも通常のCSSアニメーションはそのまま動く(3人が消えたまま止まって見えることがある)」ことをPlaywrightで確認したため。今回の指示が「JavaScript無効時は...3人を常時表示します」と明記しているため、確実に静止表示になるよう修正した。
- 見出しを小さく・行為名を大きくする際、指示が「行為名を大見出しやボタンのように強くしないでください」と明記しているため、フォントサイズ以外(書体・太さ・色・枠線)は一切変更していない。

## 他の案 (Alternatives)
- `.heroGroundLine`の絶対配置化(実装中に見つけたレイアウト不具合の修正)は、今回の指示の対象外だが、モバイル幅で3人が右へ寄って詰まって見える実害のある不具合だったため、最小限の修正として合わせて直した。別のPRやタスクに分けることも検討したが、そもそも今回の「モバイルもデスクトップと同じ横並びにする」変更をしなければ表面化しなかった不具合であり、切り離す意味が薄いと判断した。
- PC幅の文字サイズをより大きく変える案(見出しをさらに小さく、行為名をさらに大きく)も検討したが、指示の「少し」「前に出る程度」という言葉に沿って、14〜15%程度の控えめな変化にとどめた。

## 将来の変更可能性 (Future changes)
- `.heroWalker`のclamp()の下限・上限、`.heroSceneRow`のgapは、実機での見え方次第で微調整してよい。
- PC幅の見出し・行為名のフォントサイズも、`@media (min-width: 768px)`ブロック内の値を変えるだけで調整できる。

## Research Context
モバイルとデスクトップで見せ方(1人が入れ替わるか、3人が横並びか)が異なっていると、同じHeroでも画面幅によって受け取る印象が変わってしまう。指示どおり構成を1つに統一したことで、「暮らしのなかで、観察し、学び、試す」という探究のリズムを、どの画面幅で見ても同じ体験として伝えられるようになった。また、見出しを背景・文脈として少し後ろに引き、行為名を少し前に出したことは、「暮らし」という時間の中で「観察する/学ぶ/試す」という具体的な行為が主役であるという、この一連のHero改修全体の意図をPC幅でより明確にする調整である。

## 検証・未検証事項
- `npx astro check` / `npm run build`: エラーなし。
- Playwright(Chromium)で320/375/390/430/500/600/700/760/761/900/1200/1440px幅を検証し、横方向のoverflowが無いことを確認。
- 320/390/760px幅で、Heroコンテンツ下端と`.introAside`(この場所について)の間に一定の余白(24px)があること、3つの`.heroFigureCell`の横位置・幅を確認(実装中、`.heroGroundLine`がflexアイテムとして3人と横幅を奪い合い、狭い画面で3人が右へ寄って詰まって見える不具合を発見・修正した)。
- 390px幅・1440px幅の両方で、Web Animations APIを使わずに実時間で1周期(観察する→学ぶ→試すの順にフェードイン→3人保持→同時フェードアウト→短い空白→再開)を確認。
- `prefers-reduced-motion: reduce`で、デスクトップ・モバイルとも3つの`.heroFigureCell`にアニメーションが適用されず(`getAnimations().length === 0`)、不透明度が常に1であることを確認。
- JavaScript無効(`scripting: none`)でも、デスクトップ・モバイルとも3人が常時表示されることをスクリーンショットで確認(前述のとおり、この確認で`scripting: enabled`条件の不足を発見・修正した)。
- 767px/768px/1440px/390px幅で見出し・行為名の`font-size`の計算値を確認し、768px境界の前後で見出しが縮小・行為名が拡大し、390px(モバイル)は変更前と同じ値のままであることを確認。
- h1のtextContentが「暮らしのなかで、観察し、学び、試す。」のまま変わっていないことを確認。
- 本entryはmain へ直接反映した変更のため、Cloudflare Production(`futoing.com`)への反映確認はデプロイ後にユーザー報告で行う。
