# 0118. 「読みたい・未所蔵」の本を3冊追加し、「この本を贈る」を実データで有効化する

- 日付: 2026-09-11
- 状態: 一部上書き済み(→ 0119。「新品で贈る」「古本で贈る」を
  URL未設定時のみ非表示にする条件分岐は、Decision Log 0119で
  「常に非表示(コードごと撤去)」に変更された。本データ3冊の追加・
  featuredをfalseのまま維持した判断はそのまま有効)

## Decision

プロジェクトオーナーから、`/bookshelf`のcanonical data
(`src/data/bookshelf.ts`)に「読みたい・未所蔵」の本を3冊追加する
指示を受けた。目的は、(1)実際に「この本を贈る」導線が表示される
本を用意すること、(2)今の研究の方向性が本棚から見えるようにする
こと。既存の読書中3冊(経験と教育/調査的感性術/想像の共同体)・
conversation MVP(Decision Log 0115)は変更しない。

追加する3冊(マツタケ/生きていること/現代日本語における意図性副詞の
意味研究)はいずれも`status: "wishlist"` / `owned: false` /
`giftEnabled: true` / `conversationEnabled: true`。購入先URL
(`newBookUrl`/`usedBookUrl`)は未確定のため設定せず、UI側で
「無効リンクを表示しない・"#"を使わない・クリック不能なUIを作らない」
という制約に従う実装にした。`featured`は既存の設定(false)を維持し、
Home・`/participate`のteaserには混ざらないようにした。

## 対応

### 1. 本データの追加(src/data/bookshelf.ts)

3冊とも、プロジェクトオーナー提示の値をそのまま使用した。

| タイトル | 著者 | status | owned | giftEnabled | conversationEnabled |
|---|---|---|---|---|---|
| マツタケ――不確定な時代を生きる術 | アナ・チン | wishlist | false | true | true |
| 生きていること――動く、知る、記述する | ティム・インゴルド | wishlist | false | true | true |
| 現代日本語における意図性副詞の意味研究 | 李澤熊 | wishlist | false | true | true |

`reason`もプロジェクトオーナー指定の一言をそのまま使用した。
`newBookUrl`/`usedBookUrl`は設定していない(未確定のため)。`image`も
未設定(実在書影を外部取得・転載していない)。`tone`は仮カバー用に
warm/moss/skyを本ごとに割り当てた(既存3冊と同じ運用)。`featured`は
すべて`false`(指示により、Home・`/participate`のfeatured設定は
今回変更していない)。

既存3冊(経験と教育/調査的感性術/想像の共同体)の`status`/`owned`/
`giftEnabled`/`conversationEnabled`等は一切変更していない。

### 2. URL未設定時の贈り方表示(BookshelfFullList.astro)

これまで「新品で贈る」「古本で贈る」は`book.newBookUrl ?? "#"`/
`book.usedBookUrl ?? "#"`という形で、URL未設定時もダミーの"#"リンク
として常に表示していた(Decision Log 0116時点では全冊giftEnabled=
falseだったため、この分岐が実際に踏まれることはなかった)。今回
giftEnabled=trueの本が実際に登場したことで、この設計のまま出すと
「押しても何も起きないリンク」が公開されてしまう状態だった。

`book.newBookUrl && (...)` / `book.usedBookUrl && (...)`という条件
付きレンダリングに変更し、**URLが設定されていない贈り方の選択肢
自体を出さない**実装にした。「手元にある本を贈る」は本のURLに
依存しない固定の導線のため、これまで通り常に表示する。結果として、
今回追加した3冊では「この本を贈る」パネルに「手元にある本を贈る」
のみが表示される(新品/古本のURLが決まり次第、対応する選択肢が
自動的に増える)。

## 採用理由

- 「Claude側で勝手にAmazon等のURLを追加しない」という明示的な指示が
  あったため、実在するか確認できない購入先URLを推測で埋めることは
  しなかった。
- 「無効リンクを表示しない/#を使わない/クリック不能なUIを作らない」
  という3つの制約は、いずれも「選択肢自体を出さない」という1つの
  実装で同時に満たせるため、それを採用した。新たな「準備中」表示や
  グレーアウトしたボタン等は追加していない(既存のUIトーンを壊さない
  最小実装)。
- `featured`を変更しなかったのは、「今回追加する3冊をfeaturedにする
  かどうかは、勝手に変更しないでください」という明示的な指示に
  従ったもの。Home・`/participate`のプレビューが本棚全体の増加に
  つれて肥大化しない设计を維持した。

## 他の案

- URL未設定時に「準備中です」等の非リンクテキストを表示する案も
  検討したが、指示にない文言を追加することになるため見送った
  (Decision Log 0114以降、この本棚まわりでは指示にない文言を
  作らない方針を一貫させている)。
- 3冊とも`featured: true`にして「読みたい本」もHome・`/participate`
  で見せる案も考えられたが、明示的に「勝手に変更しない」との指示が
  あったため、既存の設定(false)のまま維持した。

## 将来の変更可能性

- 購入先URL(Amazonほしいものリスト、出版社サイト等)が確定次第、
  該当する本の`newBookUrl`/`usedBookUrl`を追加する。追加した時点で、
  対応する贈り方の選択肢がBookshelfFullList.astro側の変更なしに
  自動的に表示される。
- 実際の書影画像が用意され次第、該当する本の`image`を設定する
  (未設定の間は仮カバーのまま)。
- 「読みたい本」をHome・`/participate`のプレビューにも見せるかどうかは、
  プロジェクトオーナーが`featured`の値を判断して決める。

## Research Context

この追加により、「研究の本棚」は初めて「所有していない本」「まだ
読んでいない本」を含むようになった。これは、公開研究室が「すでに
読んだ本の記録」だけでなく「これから向かう関心」も見せる場である
ことを、データの上でも体現する変化である。同時に、「贈る」機能が
初めて実データで動く状態になったことで、URLが確定していない状態を
どう扱うかという実務的な課題(無効リンクを出さない)にも向き合う
ことになった。存在しない情報を偽装しない、という一貫した姿勢を
UIの細部にまで適用した一例として記録する。
