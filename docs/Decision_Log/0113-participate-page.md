# 0113. 「関わる」ページ(/participate)を新設する

- 日付: 2026-09-11
- 状態: 採用

## Decision

プロジェクトオーナーから、「ふ、と」に関わるための入口をまとめた新規
ページ(添付イメージ・各セクションの構成案付き)の実装指示を受けた。
実装前に、変更対象ファイル・新規作成ファイル・ページ構成案・各
セクションの実装方針・既存流用コンポーネント・フォーム送信の扱いを
一覧で提示し、プロジェクトオーナーに確認した。

このページ(構成: Hero → 気になるものを寄せる → 本を贈る/この本を
贈る → 一緒に試す・話す → 場所・知識・技術を貸す → まとめ)は、
CLAUDE.mdのParking Lot一覧(Concept Graph・Version UI等)そのものには
含まれていなかったが、「β公開までは新機能を増やさない」という現在の
方針の範囲を超える新規ページである。Decision Log 0111(研究の本棚・
研究便り・研究を支えるの新設)と同様、プロジェクトオーナーからの
明示的な指示に基づく方針転換として扱う。

【重要な制約】このセッションは実装確認の直後にコンテキストの要約
(compaction)を挟んでおり、添付イメージ・各セクションの厳密なコピー
文言そのものは要約後に失われている。構成(セクション名・役割・実装
方針の一覧)は要約に残っていたためそれに従ったが、本文の文言(Hero
の本文、フォームの説明文、各カードの説明文等)は、要約に残っていた
構成情報とサイト内の既存トーン(Contact/Support/About等)を手がかりに
このセッションで作成したものであり、添付イメージの原文そのままでは
ない可能性がある。プロジェクトオーナーには、公開後に原文と突き合わせ、
必要であれば文言のみの修正を依頼したい。

## 対応

### 1. 型・データ

- `src/types/participate.ts`を新規作成。`GiftBookEntry`(本を贈る候補、
  タイトル・理由・仮カバーのtone)、`GiftMethod`(贈り方の選択肢)、
  `LendCategory`(場所・知識・技術を貸すの3項目)の3型を定義した。
- `GiftBookEntry`に著者名フィールドは持たせていない。実在の著者情報が
  確定していない仮データのため、誤った実在情報を掲載しないよう、
  「研究の本棚」の`BookEntry`(Decision Log 0111)と同じく著者名を
  扱わない方針にした。

### 2. GiftBookList.astro / .module.css(新規)

- 「本を贈る」(3冊のカード、クリックで選択)と「この本を贈る」
  (選択中の本の詳細+贈り方3択)を1つのコンポーネントにまとめた。
  選択の切り替えはフレームワークを使わずvanilla JSで実装している
  (Header.astroのメニュー開閉と同じ方針)。カードは`<button>`とし、
  `aria-pressed`で選択状態を伝える。JS未実行環境でも1冊目の内容が
  「この本を贈る」欄に最初から表示されているため、情報は欠落しない。
- 仮カバー(`.cover[data-tone]`)は、「研究の本棚」
  (BookshelfList.module.css、Decision Log 0111)と全く同じ
  color-mixの配色・実装をそのまま複製した。新しいHEX値は追加して
  いない。
- 贈り方3択のうち、受け皿(Amazonほしいものリスト等)が未確定の2件は
  href="#"または`/contact`にとどめ、実際に機能する「お問い合わせから
  相談する」を必ず1件含めた。「研究を支える」(support.astro、
  Decision Log 0111)と同じ、「受け皿が決まるまではお問い合わせに
  委ねる」考え方を踏襲している。

### 3. participate.astro / .module.css(新規)

- Hero: 左に見出し・本文、右に実在の写真素材の代わりとなる
  color-mixの色面+縦書き(`writing-mode: vertical-rl`)の一文
  (装飾、`aria-hidden`)を配置した。このサイトで縦書きを使うのは
  初めてだが、外部ライブラリは使わず標準CSSプロパティのみで実装した。
- 「気になるものを寄せる」: Contactページと同じFormspreeエンドポイント
  (`contactFormEndpoint`、Decision Log 0076)へ実際に送信するフォーム。
  隠しフィールド`_subject`で「ふ、と 気になるものを寄せる」として
  件名を分け、Contact/研究便り(Decision Log 0111)と同じ受信箱に届く
  形にした。返信を必須にしない投稿という性質上、メールアドレスは
  任意項目にした(Contactページの必須項目とは異なる判断)。
- 「一緒に試す、話す」: 2カラムで「一緒に試す」「一緒に話す」を並べ、
  両方とも`/contact`への導線にした(具体的な受け皿が別に用意される
  までの暫定対応)。
- 「場所・知識・技術を貸す」: 3カード、外部アイコンライブラリを使わず
  About.astroの循環図(Decision Log 0094)と同じ方針でインラインSVGの
  線画アイコンを直接埋め込んだ。リンク先はすべて`/contact`。
- 「ともに、続けていくために」(まとめ): 色面+文章+
  `ArrowLink`(既存コンポーネント)で`/contact`へ誘導する、
  クロージングのセクション。

### 4. Header.astro

- ナビゲーションに「関わる」(`/participate`)を追加した。「本棚」と
  「公開研究室ふ、と」の間に配置し、研究断面/本棚/関わる/公開研究室
  ふ、との4項目になった。

## 採用理由

- Parking Lot本体には含まれない新規ページだが、プロジェクトオーナー
  からの明示的な指示(添付イメージ・構成案付き)であり、Decision Log
  0111と同じ「プロジェクトオーナーが直接指示した新機能は、確認の
  うえ実装する」という運用を踏襲した。
- 受け皿(本の贈り方・場所や技術の申し出の受付方法)が未確定の項目は、
  「フォームだけあって機能しない」状態を避けるため、既存のContact
  フォーム(Formspree)への導線に暫定的に委ねた。研究を支える
  (Decision Log 0111)と同じ考え方。
- 著者名等、確定していない実在情報は掲載しないことで、仮データが
  誤った事実として読まれるリスクを避けた。

## 他の案

- 「本を贈る」の贈り方3択すべてを`/contact`に統一する案も検討したが、
  「準備中」であることが分かる説明文を添えたうえでカードとして残す
  ことで、将来Amazonほしいものリスト等のURLが決まった際にhrefを
  差し替えるだけで対応できる構造にした。
- Hero右側の縦書きコピーを省略し、単純な色面のみにする案も検討したが、
  添付イメージの構成案(右に画像+縦書きコピー)を尊重し、実在の写真の
  代わりに装飾的な一文を添える形で実装した。

## 将来の変更可能性

- Hero右側の色面は、実際の写真素材が用意され次第、画像に差し替える
  想定(研究の本棚の仮カバーと同じ考え方)。
- 「本を贈る」の3冊・贈り方の受け皿は、いずれも仮データ・仮導線。
  実際の書影・実際に欲しい本のリスト・贈り方の受け皿が決まり次第、
  `participate.astro`のデータを更新する。
- 本文の文言は、上記【重要な制約】の通り、添付イメージの原文を
  厳密に引き継げていない可能性があるため、プロジェクトオーナーの
  確認を経て、必要な箇所を差し替える。

## Research Context

「関わる」ページは、これまで個別のページ(Contact・Support)に
分散していた「読者が取れる行動」を、1つの入口としてまとめる試みで
ある。CLAUDE.mdの「完成度よりも育てられることを優先する」姿勢に
従い、受け皿や実データが未確定の項目(本の贈り方、場所・知識・技術の
申し出)も、機能する部分(お問い合わせへの導線)から先に公開し、
後から実際の仕組みに差し替えていく前提で実装した。あわせて、AIが
長い対話の途中でコンテキストを失った場合でも、それまでに確認した
構成の合意を手がかりに実装を止めずに進め、内容面の確認が必要な箇所は
正直にDecision Logに書き残す、という進め方自体も記録しておく。
