# 0197 — デスクトップHeroに最小限のモーション(観察する→学ぶ→試すの順にフェードイン)を追加

## Decision
main にマージ済みのHero(Decision Log 0196、観察する/学ぶ/試すの3人を常時静止表示するデスクトップ構成)に、プロジェクトオーナーから最小限のモーションを追加する指示を受けた。人物イラスト・見出し・配置・色・余白は変更せず、デスクトップのみに以下のモーションを追加した(モバイルの「人物ひとりが中央で3姿勢をクロスフェードする」構成は変更していない)。

1. 左の「観察する」が静かにフェードイン(ごく小さく上へ動く程度、大きな移動はしない)
2. 少し間を置いて中央の「学ぶ」がフェードイン
3. 少し間を置いて右の「試す」がフェードイン
4. 3人が揃った状態を最も長く保つ
5. 3人と行為名が同時にフェードアウトし、余白だけになる
6. 短い間を置いて、左の「観察する」から繰り返す(周期11秒)

実装は`src/pages/index.module.css`のみ。`.heroSceneDesktop .heroFigureCell`(観察する/学ぶ/試すの各セル、人物イラスト+ラベルをまとめて含む既存の要素)に対し、`:nth-of-type(1/2/3)`でそれぞれ異なる`@keyframes`(`heroFigureCellObserve`/`Learn`/`Try`)を適用した。3つとも`animation-delay`は使わず、11秒という同じ長さの中に「いつフェードインするか」を%で作り分け、フェードアウト・余白の区間(77.3%〜100%)だけ3つとも完全に同じ値にすることで、揃ってフェードアウト・揃って再開することを保証している。歩く・移動するアニメーション、矢印・進行バー・点滅・数字・工程UIは追加していない。

`.heroFigureCell`自体はこれまでopacity/transformの指定を持っていなかった(常時不透明度1)。新しいアニメーションは`@media (prefers-reduced-motion: no-preference)`の中でだけ適用しているため、`prefers-reduced-motion: reduce`環境・JavaScript無効環境では、この`@media`ブロックの外にある「アニメーションなしの既定値(常時不透明度1)」がそのまま残り、3人が常時表示されるフォールバックになる。追加の分岐実装は不要だった。h1の読み上げ用テキスト「暮らしのなかで、観察し、学び、試す。」は変更していない。

## 採用理由 (Rationale)
- 指示が「人物イラスト、見出し、配置、色、余白は変更しない」と明記しているため、変更は`.heroFigureCell`への`animation`プロパティの追加のみに絞った。マークアップの変更も不要だった(`.heroSceneDesktop`内の3つの`.heroFigureCell`という既存の構造に`:nth-of-type`で対応できたため)。
- `animation-delay`でずらす方式ではなく、1本の11秒の@keyframes内で3つの姿勢それぞれの登場%を作り分ける方式にしたのは、フェードアウト・余白の区間を3体で完全に同じ値に固定することで「バラバラに消える」ことを構造的に防ぐため(delayを使う方式だと、周期の終端をずらさずに揃えるための計算がかえって複雑になる)。
- reduced-motion/JavaScript無効時のフォールバックを既存の(何も指定しない)既定値に委ねたのは、これまでの実装(Decision Log 0196)がもともと「アニメーションを何も適用しない状態=3人常時表示」だったため、新しいフォールバック用の分岐を追加する必要がなく、変更範囲を最小限に保てるため。

## 他の案 (Alternatives)
- 3体それぞれに`animation-delay`を設定する案も検討したが、同じ11秒の周期内でフェードアウト・余白を完全に一致させるには、結局各delayに応じて@keyframesの%も調整する必要があり、複雑さが変わらないため、delayなしの案を採用した。
- 人物ごとに個別のfade-inアニメーションだけを付け、フェードアウトは付けない(表示されたままにする)案も検討したが、指示が「3人と行為名が同時に静かにフェードアウトし、余白だけになる」という往復のリズムを明記しているため、フェードアウト・余白の区間も実装した。

## 将来の変更可能性 (Future changes)
- 周期(11秒)やフェードイン同士の間隔は、`heroFigureCellObserve`/`Learn`/`Try`の%値を調整するだけで変更できる。3つとも77.3%(揃ってフェードアウト開始)より前の%だけを変えればよい。
- 4人目以降を追加する場合は、`:nth-of-type(4)`用の@keyframesを追加し、既存の3つの77.3%〜100%の値と揃える。

## Research Context
「ふ、と」は工程を説明する場ではなく、暮らしの中で探究が息づく様子を見せる場である。3人が同時に現れて機械的に並ぶのではなく、観察する→学ぶ→試すの順に静かに現れ、しばらく佇んでから消え、また現れるという呼吸のようなリズムにしたことは、暮らしの中の探究が繰り返される様子を、工程図ではなく体感として伝えるという指示の意図を反映している。

## 検証・未検証事項
- `npx astro check` / `npm run build`: エラーなし。
- Playwright(Chromium、1440px幅)でWeb Animations APIのcurrentTimeを操作し、0〜11秒のタイムラインを0.5秒刻みでサンプリングして確認: 観察する(約1秒でフェードイン完了)→学ぶ(約2.5秒)→試す(約4秒)→3人とも不透明度1を約4.5秒保持→約8.5〜9.5秒で3人同時にフェードアウト→約1.5秒の余白→11秒でループ、という設計どおりの推移を確認。
- `prefers-reduced-motion: reduce`で、3つの`.heroFigureCell`に一切アニメーションが適用されず(`getAnimations().length === 0`)、不透明度が常に1であることを確認。
- JavaScript無効でも同様に3人が常時表示されることをスクリーンショットで確認。
- モバイル(390px)で`.heroSceneDesktop`が`display: none`のまま(今回変更していない)であること、および人物ひとりのクロスフェード構成が変更前と同じ見た目であることをスクリーンショットで確認。
- 横方向のoverflowが無いことを確認。h1のtextContentが「暮らしのなかで、観察し、学び、試す。」のまま変わっていないことを確認。
- 本entryはmain へ直接反映した変更のため、Cloudflare Production(`futoing.com`)への反映確認はデプロイ後にPRコメントではなくユーザー報告で行う。
