# 0196 — Hero人物を描き込みのあるイラストに刷新し、デスクトップは3姿勢常時表示に変更

## Decision
Decision Log 0194/0195で実装したHeroの人物について、プロジェクトオーナーからChatGPT生成の参考イラストとともに指摘を受けた。実装が「小さな単色の人型アイコン(頭+手足の線だけ)」になっており、髪・服(Tシャツ・ジーンズ・スニーカー)が読み取れず、参考イラストの方向性と異なっていた。また、デスクトップは元の実装(Decision Log 0194)のまま、Hero高さを一切変えない制約の中で人物を極small(高さ1rem)に収めていたため、人物がほぼ見えない状態になっていた。

これを受け、以下を変更した。

1. **人物イラストの刷新**: `src/components/HeroWalkerFigure.astro`という新しいコンポーネントを作り、髪(塗りつぶし)・顔(頭部の輪郭+小さな鼻)・首・Tシャツ(袖のあるシルエット)・腕・ジーンズ(2本の脚)・スニーカー(足先の輪郭)を持つ、線画としてある程度描き込んだSVGイラストに置き換えた。以前の「頭(円)+手足(線)+小さな四角(小道具)」という記号的なSVGは撤去した。線の色は`--color-ink`ではなく`--color-accent-blue`(既存の落ち着いた青灰色トークン)にし、参考イラストの色味に近づけた。
2. **デスクトップを3姿勢の常時静止表示に変更**: 従来(Decision Log 0194)は人物1体が3つの位置をアニメーションで移動し、位置・不透明度のアニメーションのタイミングによっては人物が一瞬も見えない瞬間が発生し得る構成だった。これを、観察する/学ぶ/試すの3つの固定インスタンス(`.heroWalkerObserve`/`.heroWalkerLearn`/`.heroWalkerTry`、いずれも`HeroWalkerFigure`を内包)を横に並べて常時表示する構成に変更した。姿勢の切り替えアニメーション自体を撤去したため、「モーションが停止している瞬間にも人物が見えない」という不具合が構造的に起こり得ない。
3. **Hero高さの制約を撤廃**: `.heroScene`の絶対配置(position: absolute)による重ね描き、および`.intro`のpadding-block↔`.introAside`のmargin-topの付け替えによる「Hero高さを一切変えない」仕組みを、デスクトップ・モバイルの両方で撤去した。`.heroScene`は通常のドキュメントフローに置かれ、人物イラストの実際の高さぶんHero全体の高さが増える。指示により「研究断面を最初の画面内に収める」よりも「人物が人として読める大きさであること」を優先している。
4. **モバイルは既存の仕組みを維持**: Decision Log 0195で実装した「人物ひとりが中央でその場のまま3姿勢をクロスフェードする」仕組み自体は変更していない(指示どおり)。イラストを`HeroWalkerFigure`に差し替え、人物のサイズを大きくした(高さ約7.6rem)のみ。
5. **`.intro`の`align-items`を`end`から`start`に変更**: 人物イラストの高さぶん`.heroStage`が縦に伸びたため、「この場所について」を人物の足元(下端)ではなく見出しの高さ(上端)に揃える方が自然だと判断した。

## 採用理由 (Rationale)
- 参考イラストのような描き込みのある人物にするには、SVGを「小さく描いてCSSで拡大する」のではなく、拡大した状態でも読めるだけのパス(髪・襟・袖・裾・靴の輪郭線)を最初から持たせる必要がある。今回のイラストはハンドコーディングのベクターパスであり、参考イラストそのものの精密さには及ばないが、頭・胴体(シャツ)・腕・脚(ジーンズ)・靴が線画として判別できる密度を持たせた。
- デスクトップで人物が見えなくなっていた根本原因は、「Hero高さを一切変えない」という制約の中に、詳細なイラストを収めようとしたことにあった。3姿勢を移動する構成をやめ、3姿勢を横に並べて常時表示する構成に変えることで、「人物が消える」という不具合の可能性自体を設計上なくした。指示の「モーションが停止している瞬間にも、最低1人の人物が必ず見えていること」は、これにより常に3人とも見えているという形で余裕を持って満たしている。
- Hero高さの制約は、そもそも人物を小さくせざるを得なかった主因である。指示が「研究断面を最初の画面内に収めることより、人物が人として読める大きさであることを優先する」と明記しているため、デスクトップ・モバイルとも高さの制約を外した。

## 他の案 (Alternatives)
- デスクトップでも人物ひとりが3位置を移動するアニメーションを維持しつつ、単にイラストだけを差し替える案も検討したが、「現在のように人物が見えない状態は不可」という指示に対し、アニメーションのタイミング調整だけで「常に見える」ことを保証するのは脆く(実際に前回、フェードアウト中に人物が消える不具合を出している)、静止した3姿勢常時表示の方が構造的に確実だと判断した。
- 実際の画像ファイル(参考イラストのような生成画像やイラストレーター制作のSVG)を新規アセットとして追加する案は、指示の「新しい画像アセットや外部ライブラリは追加せず、可能ならインラインSVGとCSSで実装する」という制約に反するため見送った。

## 将来の変更可能性 (Future changes)
- `HeroWalkerFigure.astro`は3つの`<g>`(poseObserve/poseLearn/poseTry)を持つ1つのSVGとして完結しているため、絵柄の微調整(髪型・服の輪郭など)はこのファイルだけで行える。
- デスクトップ・モバイルとも同じ`HeroWalkerFigure`を再利用しているため、将来イラストを差し替える場合は1箇所の変更で両方に反映される。
- Hero高さが伸びたことで、`.intro`の余白(`--home-intro-space`)や`.heroScene`の`margin-top`は、実際の見え方次第で今後調整してよい。

## Research Context
「ふ、と」は暮らしの中の探究を見せる場であり、人物が象徴的な記号(ピクトグラムや棒人間)に見えてしまうと、暮らしの手触りが失われる。髪・服・靴が判別できる人物イラストに刷新し、デスクトップで常に3人が見える構成にしたことは、「暮らしのなかで、観察し、学び、試す」という具体的な生活者の営みを、記号ではなく人として見せるという指示の意図を反映した変更である。
