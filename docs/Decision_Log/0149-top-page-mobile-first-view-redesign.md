# 0149. トップページを、スマホのファーストビューでサイト全体像が分かる構成に再設計

- 日付: 2026-09-14
- 状態: 採用
- 関連: Decision Log 0111(編集的な再設計の初出)・0112(見出し句点等の
  差し戻し)・0125(4層構成への整理。本Decisionはその構成をさらに
  整理する)・0127(研究断面セクションの最新2件表示)・0140(実験室の
  3冊のノート)。0125で「トップページに置かない」とした「研究の本棚」
  プレビューを、今回改めて復活させる(詳細は下記)。

## Decision

プロジェクトオーナーから、トップページ(`/`)のスマホのファーストビュー
(スクロールせずに見える範囲)だけで、初見の訪問者が

1. 何の場所か
2. 何があるか
3. どこから入れるか

の3つが分かる構成にする指示を受けた。見出し文言・説明文・3つの主要
入口(研究断面/本棚/実験室)の文言・「いま動いていること」の3項目
(音の道/Fieldnote/研究断面をひらく)・デザインルール(スマホ優先、
文字サイズを大きくしすぎない、大型カードや巨大Heroにしない、
短い言葉と細い罫線で整理する、絵文字不要)・スクロール後の並び順
(Research Statement全文→研究断面2件→実験室のノート→研究の本棚3冊→
研究便り)まで、具体的な指定を受けた。「既存コンテンツやリンク先は
削除せず、情報量と順序を整理する」という制約も明示されていた。

### ファーストビュー(スクロール不要な範囲)を3区画に新設

1. **Hero**: 見出し「気づいたら、そこに問いがある。」+説明1文
   (「公開研究室「ふ、と」は、日常のなかで問いが生まれ、育っていく
   過程をひらいています。」)のみ。長いResearch Statement全文は置かない。
2. **3つの主要入口**: 研究断面「考えていることを読む」・本棚「研究を
   支えている本を見る」・実験室「書き残す・一緒に試す」。カード風の
   影・太い枠線・大きな角丸は使わず、ラベル+短い説明+矢印だけの
   1行リストとして「編集された目次」のように見せた。Header.astroの
   ナビゲーション(研究断面/本棚/実験室)と同じ順序にした。
3. **いま動いていること**: 実験室(`/participate`)の3冊のノート
   (音の道・Fieldnote・研究断面をひらく)を、ノートごとに既存の
   説明文(`src/data/labNotebooks.ts`)を1行(`-webkit-line-clamp: 1`)
   だけ添えてコンパクトに表示した。

3区画とも、他セクションが使う`<ResearchSection>`(`padding-block:
var(--space-6)` = 6rem)を経由せず、この3区画専用のCSS
(`.hero`/`.entryNav`/`.nowSection`)で余白を独自に詰めている。
既存の余白スケールのまま使うと1画面に収まらないため。

ローカルのPlaywright検証(390×844、iPhone想定)で、Hero〜「いま動いて
いること」までが798px(利用可能な844px以内)に収まることを確認した。
デスクトップ幅(1280px)でも、1行リストのまま違和感なく表示されることを
確認した(3列グリッド化はしていない。3項目とも1行に収まる短い文言の
ため、列に分割するメリットが薄く、罫線区切りの1行リストの方が
「編集された目次」の見た目に近いと判断した)。

### 見出しの句点「。」について

Decision Log 0112で「気づいたら、そこに問いがある」(句点なし)に
差し戻した経緯があるが、今回の指示で明示的に「気づいたら、そこに
問いがある。」(句点あり)という新しいHero見出しが指定された。これは
既存のResearch Statement見出し(句点なし、0112の状態のまま
`research-statement.astro`・`ResearchStatement.astro`に残る)とは別の、
新設Hero専用の見出しとして扱った。0112の決定を上書きするのではなく、
「Hero(新設、句点あり)」と「Research Statement本文の見出し
(既存、句点なし)」という、役割の異なる2つの見出しが同じサイト内に
併存する形になる。

`--font-hero-heading`(Klee One)は「気づいたら、そこに問いがある」の
文字のみをサブセット化した自己ホストフォントで、句点「。」の字形は
含まれていない。しかしtokens.cssのフォントスタックは
`"Klee One", var(--font-body)`となっており、収録されていない文字は
自動的に`--font-body`へフォールバックする(tokens.cssに明記された、
意図された挙動)。そのため句点だけ`--font-body`(明朝)で描画される。
新しいフォントサブセットを作り直す(fontToolsでの再生成が必要)ことは
せず、既存の設計通りのフォールバックに委ねた。

### スクロール後の並び順を整理

1. **Research Statement全文**: これまでHomeには冒頭2文の要約のみを
   置き、全文は独立ページ`/research-statement`のみに掲載していた
   (Decision Log 0111)。今回の指示でHomeにも全文を戻すことになった
   ため、`research-statement.astro`と同じ6段落をそのまま
   `<ResearchStatement>`に渡した。文章の内容・段落構成は変更していない。
   `heading`propは渡していない(Heroが既に同じ趣旨の見出しを担って
   おり、直下でほぼ同じ文言の見出しを繰り返すと冗長なため)。
   `title`ラベル(「RESEARCH STATEMENT」という控えめな見出し)のみ
   引き続き表示する。
2. **研究断面**: 既存のまま(Decision Log 0127、最新2件)。変更なし。
3. **実験室のノート**: 既存の「実験室」パネル(見出し・本文・
   「実験室を見る→」)をそのまま、独立したセクションにした。
4. **研究の本棚3冊**: 新設(下記参照)。
5. **研究便り**: 既存のメルマガ登録フォームをそのまま、独立した
   セクションにした。

3・5は、これまで1つの背景面(`.panel`)を共有していたが、間に4
(研究の本棚3冊)を挟む順序に変更したため、それぞれ独立した`.panel`
に分割した。内容・リンク先・フォームの実装(Formspree送信・
バリデーション・ステータス表示)は変更していない。

### 「研究の本棚3冊」の復活について

Decision Log 0125で、Homeの「研究の本棚」プレビュー(3冊)は
「トップページを機能一覧にしない」という方針のもと削除していた。
今回の指示はこれを明示的に復活させるものだった。CLAUDE.mdの
Parking Lotでは「研究の本棚(Bookshelf)」は既に「Released from
Parking Lot」(2026-09-10、Decision Log 0111)として扱われており、
新機能追加の制限には抵触しない(今回追加するのは、既存の`/bookshelf`
ページへの新しい入口の1つに過ぎない)。

`src/types/bookshelf.ts`の`featured`フィールドには、もともと
「以前はHome・`/participate`の圧縮表示に出す本の選定に使っていたが
…将来のプレビュー用途に備えて残しているだけの値である」という
コメントが残っており、まさに今回のような復活を想定して温存されて
いたフィールドだった。そのため`books.filter((book) => book.featured)`
の先頭3冊(現在「読書中」の3冊)をそのまま使い、`bookshelf.ts`側の
データ・並び順は変更していない。書影は`/bookshelf`本体
(`BookshelfFullList.module.css`)と同じ、小さな書影+仮カバー(tone、
color-mixによる3色のグラデーション)の考え方をこのページ用に複製した
(プロジェクト全体で「ページごとにスタイルを独立させる」既存の方針を
踏襲。共通コンポーネント化はしていない)。

## 対応

- `src/pages/index.astro`: Hero・3つの主要入口・いま動いていること
  (新設)/Research Statement全文/研究断面(既存)/実験室(既存を
  分離)/研究の本棚3冊(新設)/研究便り(既存を分離)の順に全面的に
  構成し直した。`labNotebooks`・`books`を新たにimportした
  (どちらも既存データを共有するのみで、新規データファイルの追加は
  していない)。
- `src/pages/index.module.css`: `.hero`/`.entryNav`/`.entryItem`等
  (Hero・主要入口)、`.nowSection`/`.nowList`/`.nowItem`等(いま動いて
  いること)、`.bookshelfHeading`/`.bookshelfList`/`.bookshelfCover`等
  (研究の本棚3冊)を新設した。既存の`.panel`/`.panelSection`/
  `.newsletterForm`系・`.researchReviewsHeading`系のスタイルは変更して
  いない。

## 採用理由

指示を字面通りに実装した。特に「既存コンテンツやリンク先は削除しない」
という制約に従い、`/research`・`/bookshelf`・`/participate`・
`/research-statement`・Formspreeエンドポイント等、すべての既存リンク先・
データソースをそのまま使い、新しいページ・新しいバックエンドは追加
していない(「情報量と順序を整理する変更」という指示の範囲に収めた)。

ファーストビュー専用の3区画だけ`<ResearchSection>`の共通余白
(`space-6`)を使わなかったのは、「余白は残すが、1画面に収める」という
相反する2つの要求を両立させるための必要最小限の例外であり、
スクロール後のセクションは引き続き既存の余白ルールに統一している。

## 他の案

- **3つの主要入口をDesktop幅で3列グリッドにする**: 指示文の
  「横並びまたはスマホで3列/コンパクトなグリッド」という表現を
  文字通り解釈し、3列グリッド化も検討した。しかし3項目とも短い
  1行の文言であり、列に分割すると逆に余白が増え「編集された目次」
  というよりカード一覧に近い見た目になってしまうため、Mobile/
  Desktopとも同じ罫線区切りの1行リストに統一した。将来、入口の
  文言が長くなった場合は再検討する。
- **Research Statement全文をアコーディオン等で折りたたみ表示する**:
  ファーストビューの外側であればスクロール量に上限を設ける必要は
  ないと判断し、既存の`/research-statement`ページと同じ、折りたたみ
  なしの全文表示にした(「スクロール後」の指示にアコーディオン化の
  指定はなかったため)。
- **「研究の本棚3冊」を新しい選定基準(専用フラグ)で選ぶ**: 新しい
  `homePreview`のようなフラグを`BookEntry`に追加する案も検討したが、
  既存の`featured`フィールドが「将来のHomeプレビュー用途」として
  既に用意されていたため、新しいフィールドを増やさずそのまま使った。

## 将来の変更可能性

- 研究断面の記事・実験室のノート・本棚の本が増えた場合も、
  ファーストビューの3区画(Hero・主要入口・いま動いていること)は
  件数を増やさず現状の構成を維持する方針とする(1画面に収める
  という制約と両立しないため)。
- Hero見出しの句点「。」の扱いは、プロジェクトオーナーの今後の指示
  次第でさらに変わる可能性がある(Decision Log 0108→0112→今回、と
  複数回変遷している)。
- `books.filter((book) => book.featured).slice(0, 3)`という選定方法は、
  `featured: true`の本が増えた場合、常に配列の先頭3冊(現在は
  「読書中」の3冊)になる。「読みたい」本を優先的に見せたい等の
  要望が今後出た場合は、選定ロジックの見直しを検討する。

## Research Context

「初めて来た人が、上から読むだけで場所の全体像をつかめるようにする」
という今回の指示は、CLAUDE.mdの「公開研究室」という位置づけ
(完成した成果物の展示ではなく、育っていく研究そのものを見せる場)を、
スマホという実際の閲覧環境によりよく適応させる試みである。
Decision Log 0125で確立した「トップページを機能一覧にしない」という
原則は維持しつつ、「全体像がスクロールなしで分かる」という新しい
要求を、情報量を増やすのではなく、既存の要素を(1)ファーストビュー用の
コンパクトな要約と(2)スクロール後のフルサイズの内容、の2段階に
再配置することで両立させた。これは「余白を思考時間として扱う」
(Design Spec 10)という方針と、「読者が迷わず場を把握できる」という
実用性の要求を、削除ではなく再配置によって両立させる、という
このプロジェクトらしい解決のかたちだと考える。
