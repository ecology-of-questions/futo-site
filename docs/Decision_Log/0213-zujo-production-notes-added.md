# 0213. 「頭上の記録」を実験室に追加し、Homeの注目ノートを差し替える

- 日付: 2026-11-11
- 状態: 採用

## Decision

プロジェクトオーナーから、新しい制作("頭上の記録" — 自宅上空を飛ぶ飛行機・ヘリの音を暮らしの観察として記録する道具)の制作過程を綴る「制作ノート」を追加する依頼を受けた。事前にリポジトリの構成(フレームワーク・データモデル・既存の記事パターン)を調査して計画を報告し、「実験室に追加したい。今はTOPページの実験室が散歩譜だがそれを変更するイメージ」という指示を受けて、以下を実装した。

### 追加・変更したファイル

- `src/types/labNotebook.ts`: `LabNotebook`に`detailHref?: string`を追加。`/participate/[slug]`はGoogleスライド埋め込みを前提にしたテンプレートのため、スライドを使わないノートが別の場所(今回は`/zujo/`)に本体を持てるようにする上書きフィールド。
- `src/data/labNotebooks.ts`: 4冊目のノート「頭上の記録」(slug: `zujo-no-kiroku`、category: "アプリ"、`detailHref: "/zujo/"`)を配列の先頭に追加。既存の3冊(散歩譜・Fieldnote・研究断面をひらく)は変更していない。
- `src/components/LabNotebookList.astro`: リンク可否・遷移先の判定を`hasDetailPage(notebook) || Boolean(notebook.detailHref)`に拡張し、`detailHref`があればそちらを使うようにした。「頭上の記録」用の装飾トレース(SVG、上空を横切る軌跡+気づきの点+下向きの弧2本)を追加。
- `src/pages/participate.astro`: ランディング専用の説明文(`landingDescriptions`)に「頭上の記録」の1件を追加。
- `src/pages/index.astro`: Homeの「実験室」注目セクションが参照するノートを、`oto-no-michi`(散歩譜)から`zujo-no-kiroku`(頭上の記録)に差し替えた。タグラインを「散歩中の気づきを動きから辿る。」から「頭上を通る音から、暮らしの記録をたどる。」に、`HomeMotion`の種類を`sound`から`question`(「小さな気づきがつながり、問いになる」)に変更した。CTAの遷移先も`featured.detailHref`を優先するよう修正した。
- `src/types/productionNote.ts` / `src/data/productionNotes.ts`: 「制作ノート」本体(各回)のための型とデータ(研究断面の`ReviewSection`ブロック型を再利用。現時点では空配列)。
- `src/components/ProductionNoteList.astro` / `.module.css`: 一覧表示コンポーネント(研究断面の一覧と同じ見た目・トークンを再利用)。entriesが空の間は「まだ公開している回はありません。」と表示する。
- `src/pages/zujo/index.astro` / `index.module.css`: 制作ノート一覧ページ。「← 実験室」で`/participate`に戻れる。各回の詳細ページ(`/zujo/01`等)は、第1回の本文が確定してから追加する(今回は作っていない)。

散歩譜(oto-no-michi)は配列・`/participate`一覧・`/participate/oto-no-michi`の詳細ページともそのまま残しており、削除していない。Homeで取り上げる1冊を変えただけである。

## 採用理由

- `/participate/[slug]`は、現状完全にGoogleスライド埋め込みを前提にしたテンプレートになっている(Decision Log 0192で非スライド用レイアウトを削除済み)ため、「頭上の記録」をこのテンプレートに無理に載せると中身が空のページになってしまう。`detailHref`という小さな上書きフィールドを追加し、実験室の一覧コンポーネント1箇所の分岐を広げるだけで、既存3冊の挙動を一切変えずに新しい遷移先を持たせられる。
- 制作ノート本体を研究断面と同じ「型(ブロック)+データ配列+一覧コンポーネント+個別手書きページ」の構造にしたのは、このリポジトリに既にある最も近い前例(研究断面)をそのまま再利用し、新しいパターンを増やさないため。`ReviewSection`型を複製せずimportして使っている。
- 個別の回(`/zujo/01`等)はまだ作っていない。第1回の本文(骨子からの下書き作成の可否、文体・フォントの扱い)がまだ確定していないため、確定していない内容を先に実装すると後で作り直すことになる。一覧ページと空状態だけを用意し、本体は後続の作業とした。
- HomeのHomeMotionを`sound`から`question`に変えたのは、新しい`sound`/`question`以外の種類を増やす(新しいモーション資産を作る)よりも、「小さな気づきがつながり、問いになる」という既存の`question`モーションが、頭上の音に気づいて記録する、という行為の抽象化としてそのまま使えると判断したため。

## 他の案

- 「頭上の記録」を`/participate/zujo-no-kiroku`という通常の詳細ページにし、そこから`/zujo/`へのリンクを置く2段階の構成も検討したが、クリックが1回増えるだけで利点が無く、`detailHref`で直接`/zujo/`に飛ばす方が単純だった。
- 制作ノートの本体を`/participate/zujo-no-kiroku/01`のように実験室の配下にネストする案も検討したが、研究断面(`/research/reviews/01`)と同じ「トップレベルの一覧+番号」という形の方が、URLの対称性があり分かりやすいと判断し、`/zujo/`という独立した一覧にした(実験室の一覧カードからは`detailHref`で直接たどり着ける)。

## 将来の変更可能性

- 第1回以降の本文が確定したら、`src/data/productionNotes.ts`に`ProductionNoteEntry`を追加し、`src/pages/zujo/01.astro`等を研究断面の`01.astro`と同じ要領で追加する(`ProductionNoteArticle.astro`のような表示コンポーネントは、最初の1本を書く段階で合わせて用意する)。
- Homeで取り上げるノートを再び変えたくなった場合は、`index.astro`の`featured`の検索条件(slug)・タグライン・`HomeMotion`の種類を変更するだけでよい。
- 散歩譜を実験室の一覧から完全に下げたい場合は、`labNotebooks.ts`の配列から該当エントリを削除するか、配列の末尾に動かす(表示順をそのまま使っているため)。

## Research Context
「頭上の記録」は、公開アプリとして育てる前段階として、まず「ふ、と」というこの研究室の中で、作っていく過程そのものを公開する——完成品を見せるのではなく、迷ったことやつまずいたことも含めて記録する、という「公開研究室」の姿勢そのものの実践である。実験室の注目ノートを差し替えたことは、この研究室がいま最も活発に動かしている観察・記録の対象が何かを、トップページの時点で正直に示す調整である。

## 検証・未検証事項

- `npx astro check` / `npm run build`: エラーなし(既存の`SectionTitle.astro`のProps未使用警告のみ、本変更とは無関係)。
- Playwright(Chromium)でHome(390px/1440px)・実験室(1440px)・`/zujo/`(390px/1440px)のスクリーンショットを確認し、コンソールエラーが無いこと、Homeの注目セクションが「頭上の記録」に差し替わっていること、実験室の一覧に「頭上の記録」が先頭で表示され「ノートを見る→」が`/zujo/`に遷移すること、散歩譜以下の3冊の表示・リンクが変更前と同じであることを確認した。
- `/zujo/`は本文が空のため、第1回公開後に改めて実機確認が必要。
