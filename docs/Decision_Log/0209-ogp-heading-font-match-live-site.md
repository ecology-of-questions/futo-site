# 0209. OGP画像の見出しフォントを、実機のHero見出しと一致させる

- 日付: 2026-09-27
- 状態: 採用
- 関連: 0208(現在のHero構成への作り直し)

## Decision

Decision Log 0208でOGP画像を作り直した際、レンダリング環境に日本語の明朝体フォントが無く、見出し(`h1`)がタグラインと書体が揃わずちぐはぐに見えたため、見出し・タグラインの両方をゴシック体(`--font-sans`相当)に統一していた。プロジェクトオーナーから、実機のHero見出し(`.heroHeading`、`--font-body`相当のHiragino Mincho ProN/Yu Mincho)と、OGP画像の見出しのフォントをそれぞれ確認したいという質問を受け、両者が一致していないことを説明した。そのうえで「実機の見出しに合わせる」という指示を受けた。

`h1`のfont-familyを、0208で設定したゴシック体から、実機の`--font-body`と同じ`"Hiragino Mincho ProN", "Yu Mincho", "IPAMincho", serif`に戻した。タグラインは実機のHero見出しとも元々別の書体(見出しは`--font-body`、タグラインに相当する本文・ラベル類は`--font-sans`)であるため、ゴシック体のまま変更していない。見出しの文字サイズ(46px)は変更していない。

`DefaultLayout.astro`の`og:image`参照を`?v=3`から`?v=4`に更新した。

## 採用理由

- 画像内の書体の統一よりも、実機との一致を優先するという明確な指示のため。OGP画像は実機のHeroを反映するために作られたものであり(Decision Log 0208)、その見出し自体が実機と異なる書体では本末転倒になる。
- レンダリング環境にHiragino Mincho/Yu Minchoが無いため、この画像生成時点では実際にはフォールバック(既定のserifフォント)で描画されている。これは実機がMac/Windows以外の環境(またはこれらのフォントを持たない環境)で閲覧された場合と同じフォールバック挙動であり、新たな不整合を生んでいるわけではない。CSSの宣言自体を実機と一致させることを優先した。

## 他の案

- 見出し・タグラインの書体を画像内で統一したまま維持する案(Decision Log 0208の状態を保つ)もあったが、プロジェクトオーナーの明確な指示(「1」=実機の見出しフォントに合わせる)に従った。

## 将来の変更可能性

- 実機のHero見出しの書体(`--font-body`)が将来変更された場合は、この画像の見出しも合わせて変更する必要がある。

## Research Context
OGP画像は実機の「顔」を伝えるものであり、実機と食い違う書体を使うと、シェアされた瞬間の印象と実際にページを開いたときの印象がずれてしまう。画像内の見た目の統一感よりも実機との一致を優先したことは、Decision Log 0208の「コンテナの変更をコンテンツにも一貫して反映する」という方針をより厳密に適用したものである。
