# 0152. 研究断面の一覧・詳細ページをv0.1公開仕様に更新

- 日付: 2026-09-16
- 状態: 採用
- 関連: Decision Log 0150(v0.1公開仕様の受領)・0151(この場所についての
  全面差し替え)。Decision Log 0033・0054・0055・0056・0093
  (/researchの一覧UIの変遷、今回はほぼ変更していない)。Decision Log
  0030・0036・0041(研究断面詳細ページのコンポーネント設計)。

## Decision

プロジェクトオーナーから、v0.1公開仕様に基づき「研究断面」の一覧・
詳細ページを更新する指示を受けた。PR #83(Top・About)は既にmerge
済みだったため、指示どおり最新mainから新しいブランチ
(`claude/research-reviews-v0.1`)を作り、新規PRとして進めた。

目的は、研究断面を「ブログ記事一覧」ではなく「その時点で考えていた
ことが、時間とともに蓄積されていく場所」として見せること。既存URL
(`/research`、`/research/reviews/01`、`/research/reviews/1-5`)・既存の
記事本文(`sections`)は変更していない。

### `/research`一覧ページ: 変更なし

実装前にコードとスクリーンショットで確認したところ、既存の
`ResearchReviewList.astro`(Decision Log 0093時点の実装)は、既に
「番号+更新日 → タイトル(h2) → サブタイトル → 要約 → 読む→」という、
写真・サムネイルなし、カードなし、細い罫線区切りの縦1カラムリストに
なっていた。v0.1仕様が求める「番号/日付/タイトル/短い本文抜粋/矢印」
という構成と実質的に一致しており、「構想中」の扱いも既にバッジ的な
演出のない1行表示だったため、**このページ自体には変更を加えなかった**
(不要な書き直しを避け、既存の動く実装をそのまま活かす判断)。

### 研究断面詳細ページ: 目次・関連コンテンツ・前後ナビゲーションを追加

`ResearchReviewArticle.astro`(01・1.5が共有するコンポーネント)に、
以下の3つを追加した。既存の本文描画ロジック(`ReviewContentBlock`への
委譲)・各記事の`sections`(本文そのもの)は一切変更していない。

1. **目次**: `sections`の`heading`から自動生成する(記事ごとに手で
   書かない。将来02・03を追加しても自動的に追従する)。Desktop幅
   (900px〜)は本文の右に小さくsticky表示し(指示どおり「主張を
   弱くする」ため`--fs-sm`・淡い色)、Mobile幅は標準HTMLの
   `<details>`(追加JSなし)で折りたたみ、既定で閉じている。左側の
   記事一覧サイドバーは作っていない(目次のみ)。
2. **この断面のそばにあるもの**: 本文中で実際に確認できる関連のみを
   表示する(下記「実データとして表示している内容」参照)。関連が
   1件も無い場合はセクションごと非表示にする(架空の関連付けは
   作らない、という指示への対応)。カードUIにはせず、Topの
   `.entryItem`等と同じ「細い罫線区切りの行」で見せ、CTAらしい強い
   装飾(背景色・ボタン)は付けていない。
3. **前後の断面ナビゲーション**: 「← 前の断面」「次の断面 →」の
   静かなテキストリンクのみ。最初/最後の記事では該当する側を表示
   しない(01は「次の断面」のみ、1.5は「前の断面」のみになることを
   スクリーンショットで確認済み)。

データの解決は`src/data/researchReviews.ts`に追加した
`getReviewNavigation(number)`(前後記事)・`getRelatedContent(entry)`
(関連本・関連ノートの解決)が行い、`ResearchReviewArticle`は渡された
propsをそのまま描画するだけにした(Decision Log 0003の「コンポーネント
はpropsで受け取り、ハードコードしない」方針を踏襲)。

### 実データとして表示している関連コンテンツ

`relatedBookIds`/`relatedNotebookSlugs`(`PublishedReviewEntry`に追加、
`src/data/bookshelf.ts`/`src/data/labNotebooks.ts`のid/slugをそのまま
参照)は、以下の根拠のみで設定した。

- **研究断面01 → 本棚『現代日本語における意図性副詞の意味研究』
  (李澤熊)**: 01本文末尾の「参考文献・参照資料」に実際に引用されて
  いる本で、`bookshelf.ts`の`id: "ito-sei-fukushi"`と一致することを
  確認した。
- **研究断面01・1.5 → 実験室『研究断面をひらく』ノート**: このノートの
  説明文(`labNotebooks.ts`)は「書いてきた『研究断面』を、実際の場所で
  ひらき、展示したり、話したりする企画を考えています。」であり、
  「研究断面」という内容そのものを対象にした企画のため、公開済みの
  研究断面すべてに共通して関連すると判断した。
- **研究断面1.5 → 本棚**: 1.5の本文・参考文献リストを`bookshelf.ts`の
  全タイトル・著者名と突き合わせたが、一致するものは見つからなかった
  ため、`relatedBookIds`は設定していない(結果、1.5の詳細ページでは
  「この断面のそばにあるもの」に本棚の項目は表示されない)。

## 対応

- `src/types/researchReviewListing.ts`: `PublishedReviewEntry`に
  `relatedBookIds`/`relatedNotebookSlugs`(任意)を追加。
- `src/data/researchReviews.ts`: 01・1.5に上記の関連付けデータを設定。
  `getReviewNavigation()`・`getRelatedContent()`を追加。
- `src/components/ResearchReviewArticle.astro`: 目次(Desktop sticky /
  Mobile `<details>`折りたたみ)・「この断面のそばにあるもの」・前後
  ナビゲーションを追加。Props(`relatedBooks`・`relatedNotebooks`・
  `prev`・`next`、いずれも任意)を追加。
- `src/components/ResearchReviewArticle.module.css`: 上記に対応する
  スタイル(`.layout`・`.tocMobile`・`.tocDesktop`・`.tocList`・
  `.related*`・`.reviewNav*`)を追加。既存のスタイルは変更していない。
- `src/pages/research/reviews/01.astro` / `1-5.astro`:
  `getReviewNavigation`/`getRelatedContent`を呼び出し、
  `ResearchReviewArticle`に新しいpropsを渡すよう配線。本文
  (`sections`)・タイトル・サブタイトルは変更していない。
- `src/components/Footer.astro`: サイト名表記を「公開研究室「ふ、と」」
  → 「公開研究室ふ、と」に統一(Top・About等、v0.1刷新済みの他ページと
  揃えた)。

## 採用理由

「架空の関連付けを作らない」という指示を、実装可能な形に落とし込む
ため、関連付けデータを本文・参考文献との実際の一致(本のタイトル・
著者名、または明示的に「研究断面」を対象にしているノートの説明文)
でのみ設定し、それ以外の「テーマ的に近そうだ」という主観的な判断
(例: 「音の道」の説明文が01・1.5の主題と雰囲気的に響き合う、といった
連想)は採用しなかった。これにより、01では本棚+実験室の2件、1.5では
実験室の1件のみが表示され、関連が薄い記事では無理に本棚の関連を
出さない、という「関連付けデータが存在しない場合は空にしてよい」という
指示どおりの挙動を実装できた。

目次をpropsではなく`sections`から自動生成したのは、「02以降も同じ
構造で追加する」というこのコンポーネントの既存の設計方針
(Decision Log 0030)に沿うため。記事ごとに目次を手書きする方式だと、
本文の見出しを変更した際に目次だけ更新し忘れる不整合が起きうる。

## 他の案

- **目次を`<details>`1つに統一し、Desktop幅でCSSのみで常時展開状態に
  見せる**: `<details>`の開閉状態はJSなしにはCSSだけで強制できない
  (`open`属性はHTML側の状態)。Mobile(既定で閉じる)とDesktop(常に
  開いている)で要求される既定状態が逆であるため、1つの要素を
  メディアクエリだけで両立させることは技術的に無理があると判断し、
  Desktop用のsticky nav(常時展開)とMobile用の`<details>`(既定で
  閉じる)を別々に用意し、`display: none`で出し分ける方式にした。
  同じ目次が2箇所DOMに存在する形になるが、内容は完全に同一の
  ナビゲーションであり、実害は小さいと判断した。
- **関連コンテンツの選定を、本文の主題との類似度(キーワード一致等)で
  自動判定する**: 「架空の関連付けを作らない」という指示に対し、
  もっとも保守的な実装は「実際に引用・言及されているものだけを、
  人が確認して明記する」方式だと判断した。キーワード一致による自動
  判定は、意図しない偽陽性(例: 「身体」という語だけで無関係な本が
  紐付く)を生みかねないため採用しなかった。
- **「研究断面をひらく」ノートとの関連を、01・1.5個別にではなく一覧
  ページ側で一括表示する**: このノートは特定の1記事ではなく「研究
  断面」というジャンル全体を対象にしているため、一覧ページ側に
  1箇所だけ置く案も検討したが、指示が「各記事の末尾に『この断面の
  そばにあるもの』を設ける」ことを明示していたため、各詳細ページに
  表示する現在の実装にした。

## 将来の変更可能性

- 研究断面02・03が実際に公開される際は、同じ構造
  (`getReviewNavigation`/`getRelatedContent`の呼び出し+
  `relatedBookIds`/`relatedNotebookSlugs`の設定)を踏襲すれば、目次・
  前後ナビゲーション・関連コンテンツは自動的に機能する。
- 「この断面のそばにあるもの」の関連付けは、今回は本棚・実験室の
  2種類のみ実装した。将来、研究便り(バックナンバー)等、他の
  コンテンツ種別との関連付けが必要になった場合は、
  `getRelatedContent()`の戻り値を拡張する。
- Desktop目次とMobile目次が同一内容のまま2箇所DOMに存在する実装は、
  将来アクセシビリティ上の指摘があれば、JSで表示中の一方だけを
  DOMに残す方式への切り替えを検討する。

## Research Context

「その時点で考えていたことが、時間とともに蓄積されていく場所」という
今回の位置づけは、CLAUDE.mdの「研究は公開した瞬間に完成しない」という
考え方と、「この断面のそばにあるもの」を実データのみに厳密に限定した
今回の実装によって、より具体的な形で体現された。関連コンテンツを
「それらしく埋める」のではなく、本文・参考文献という一次資料に基づいて
だけ表示することで、研究断面・本棚・実験室という3つの領域が、演出では
なく実際の研究のつながりとして結びついている状態を保っている。
