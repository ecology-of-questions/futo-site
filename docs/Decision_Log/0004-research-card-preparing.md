# 0004. ResearchCard を Preparing 状態に対応させる

- 日付: 2026-08-04
- 状態: 一部上書き済み(→ 0005。statusの意味づけを「出版状態」から「研究状態」へ変更)。
  ResearchCardコンポーネント自体は→ 0033で/researchページから廃止
  (ResearchReviewListに置き換え)。

## Decision

`ResearchCard.astro` を実装した。`status` prop(`preparing` / `published`)
を持ち、タイトル・ステータス・Current Focus・Last Updated のみを表示する
最小構成にする。装飾やレイアウトの作り込みは行わない。

これは、モックアップを待たずにClaude側から提案した最初の実装。
「Design Specの思想と既存デザインシステムに整合する範囲であれば、
モックアップがなくても実装を提案してよい」というワークフロー変更
(2026-08-04)に基づく。

## 採用理由

- β公開の方針転換により、Researchページは "Status: Preparing" 程度の
  プレースホルダーで十分という要件が既に明確に示されていた
  (フィールド構成も含めて指定済み)。
- フィールド構成(Status / Current Focus / Last Updated)は
  プロジェクトオーナーから直接提示された情報であり、
  新たな情報設計の判断を必要としなかった。そのため
  「実装として自然に決められる部分」と判断し、着手した。
- `status` を prop 化することで、Researchページが将来 "Preparing" から
  "Published"(詳細UIあり)へ進化しても、同じコンポーネントの
  延長で扱える。

## 他の案

- **Researchページ全体(ルーティング・タイトル・件数など)まで
  一括で実装する案**: 情報設計(どのページに何件表示するか、
  URLの構造など)はChatGPT/プロジェクトオーナーの判断領域であるため、
  カード単体の実装に留め、ページへの組み込みは提案として別途確認する
  方針にした。
- **statusをboolean(`isPreparing`)にする案**: 将来「非公開」
  「アーカイブ」等の状態が増えた場合に対応しづらいため、
  文字列のUnion型にした。

## 将来の変更可能性

- `published` 状態になったときの表示内容(サムネイル、要約文など)は
  未定義。実際のResearch Reviewコンテンツの仕様が来た時点で
  Propsを拡張する。
- カードを並べる一覧ページ(`pages/research/`)の構成は、
  IA(情報設計)がChatGPT側で固まり次第、正式に反映する。

## Research Context

「空の棚を恐れない」という方針転換の思想を、そのままコンポーネントの
状態(`status: "preparing"`)として実装した。未完成であることを隠す
のではなく、「準備中である」という状態そのものを構造として表現する
ことが、「公開してからが開発のスタート」という考え方をコードに
落とし込む一番自然な形だと判断した。
